# Initialize Rust Foundation Workspace

## Objective

Create the initial Rust workspace and the reusable foundation crates prescribed by `design/level-2/001. workspace and package layout.md`.

This task is scaffolding only. Do not design or implement the semantic object model, database schema, snapshot algorithm, query language, migrations, or projection behavior.

Read before editing:

1. `design/level-1/001. vision and principles.md`
2. `design/level-2/001. workspace and package layout.md`

The important architectural rule for this task is:

> Foundation crates must remain useful without an agent runtime or product surface.

## Root `Cargo.toml`

Create a Cargo workspace using resolver version 3.

The workspace members for this task are exactly:

```text
crates/scriberig-core
crates/scriberig-store
crates/scriberig-schema
crates/scriberig-graph
crates/scriberig-query
crates/scriberig-migration
crates/scriberig-projection
crates/scriberig-session
```

Define shared package metadata:

- version `0.1.0`;
- Rust edition `2024`.

Do not add application, server, CLI, TUI, or agent crates yet. A later Level 3 task extends the member list.

Do not add dependencies that are not needed for an empty compileable scaffold.

---

## `rust-toolchain.toml`

Use the stable Rust toolchain.

Include the normal formatting and linting components:

```text
rustfmt
clippy
```

Do not pin a numeric Rust release in this task.

## `src/lib.rs` Content

Each `lib.rs` must contain only crate-level documentation describing the crate's architectural responsibility and, if useful, a small comment explaining that the API is intentionally deferred to later design documents.

Do not create speculative structs, traits, enums, placeholder identifiers, or fake APIs simply to make the crate appear populated.

The empty documented libraries must compile.

The crate descriptions should communicate:

- `scriberig-core`: universal low-level types and identifiers;
- `scriberig-store`: persistence abstractions for immutable knowledge state;
- `scriberig-schema`: domain-independent schema vocabulary;
- `scriberig-graph`: universal entity/relation graph layer;
- `scriberig-query`: domain-independent traversal/query layer;
- `scriberig-migration`: common semantic change boundary;
- `scriberig-projection`: shared render/import/reconcile abstractions;
- `scriberig-session`: structured sessions as knowledge, independent of agent execution.

Do not claim that any unimplemented feature already exists.

## Required Checks

Run:

```text
cargo fmt --all -- --check
cargo check --workspace
cargo clippy --workspace --all-targets -- -D warnings
```

All three must succeed.

If Clippy reports a warning caused solely by intentionally empty scaffolding, fix the source rather than weakening the lint invocation.

---

## Do Not Do

- Do not edit the Level 1 or Level 2 design documents.
- Do not add SQLite or another database backend.
- Do not define `EntityId`, `RevisionId`, or `SnapshotId` yet; their exact representation belongs to a more specific design.
- Do not implement content addressing.
- Do not create a query parser.
- Do not create migration operations.
- Do not create projection traits unless a later design has defined them.
- Do not add any agent crate.
- Do not add any product executable.
- Do not add domain-specific code.
