# Implement Neutral Reusable Components

## Objective

Implement `@scriberig/components` as a reusable React component library over `@scriberig/react` and `@scriberig/editor-core` with minimal visual assumptions and no MUI dependency.

The components provide ready-made semantic views while preserving replaceability and styling freedom for third-party applications.

Read before editing:

1. `design/level-1/012. web platform and integrated editor.md`
2. `design/level-2/001. web workspace packages and integrated editor.md`
3. `design/level-3/005. implement headless editor core primitives.md`
4. `design/level-3/006. implement react bindings.md`

Prerequisite: React bindings and headless controllers compile.

## Styling Rules

The package must not depend on MUI or another application design system.

Allowed styling mechanisms:

- semantic class names;
- data attributes;
- minimal package CSS if needed for structural layout/accessibility;
- render props/slots for caller-owned rendering;
- standard HTML attributes and ARIA roles.

Do not hard-code Scriberig product colors, typography, spacing system, or panel layout.

Components should accept `className` and relevant standard DOM props where practical.

---

## ObjectTree

Render the headless knowledge tree state.

Requirements:

- lazy expanded children only;
- expandable/collapsible rows;
- loading and error state per node;
- semantic labels/descriptions where present;
- selection integration;
- load-more behavior;
- keyboard navigation provided through shared interaction behavior;
- accessible tree/treeitem semantics where appropriate.

Do not fetch descendants independently from editor-core/model logic.

---

## ObjectInspector

Render semantic object information in a domain-neutral form.

Support at least:

- semantic identity/reference;
- type/schema label;
- description/provenance where supplied;
- current/exact revision information;
- properties/summary values;
- available relations;
- stale/historical indicators.

Allow domain extensions or caller slots to replace sections.

---

## RelationBrowser

Render one selected relation/collection with pagination and semantic child selection.

Do not treat relation contents as a flat static array if the model exposes paging/count metadata.

---

## HistoryView and SemanticDiffView

`HistoryView` renders semantic history/lineage summaries and allows selection of revisions/snapshots for comparison.

`SemanticDiffView` renders structured semantic diff data rather than computing diffs itself.

Support caller/domain rendering overrides for specialized diff entries.

Do not implement source-text diffing algorithms in this package.

---

## MigrationPreview

Render a migration proposal/detail including:

- base snapshot;
- affected objects;
- selected semantic changes;
- validation status;
- stale/conflict state;
- apply/accept action when capability permits;
- reject/close local review action.

Use the migration review controller/hook.

Do not directly mutate server/database state.

---

## SessionTree and BranchView

Represent sessions as structured semantic objects.

`SessionTree` must expose branches and nested branch structure progressively.

`BranchView` should show, where available:

- title/description;
- purpose;
- status;
- outcome;
- touched objects;
- decisions/tasks;
- resulting migrations/snapshots;
- links to detailed turn/chat projection when requested.

Do not reduce the session model to one chronological chat list.

---

## ValidationResults and OperationView

`ValidationResults` renders structured validation results and preserves distinctions among checks, diagnostics, pass/fail states, and references.

`OperationView` renders one durable operation lifecycle and progress/result references.

Closing/unmounting the component must not cancel the operation automatically.

---

## ProjectionHost

`ProjectionHost` is a domain-neutral host for registered projection view/editor implementations.

Responsibilities:

- receive projection identity and semantic selection context;
- locate the applicable registered projection handler;
- display unsupported/readonly states explicitly;
- pass semantic location selection callbacks between projection handler and shared selection model;
- surface stale/candidate/conflict state.

Do not hard-code Monaco, CodeMirror, PDF.js, or Markdown editors in this task.

---

## AgentOperationView

Render agent operation state and semantic result links.

It may show streamed text/output when protocol exposes it, but semantic links to branch, migration, validation, and affected objects are first-class.

Do not make plain chat output the only result representation.

---

## Slots and Domain Extension

Where domain-specific rendering is expected, accept typed render callbacks/registered view descriptors rather than importing every domain package directly.

The neutral package should be able to render a useful fallback when no specialized extension exists.

---

## Accessibility

Required shared behavior:

- keyboard-operable tree and command controls;
- semantic button labels;
- focusable interactive rows where appropriate;
- ARIA roles for trees, lists, status, progress, dialogs/panels when applicable;
- no interaction that is pointer-only.

Do not duplicate complex focus logic if editor-core already provides it.

---

## Tests

Required tests:

1. ObjectTree renders only loaded/expanded children;
2. selection changes through a tree row update shared selection;
3. keyboard navigation works for the primary tree interaction;
4. historical/stale state is visible in ObjectInspector;
5. MigrationPreview shows conflict/stale state distinctly from validation failure;
6. SessionTree renders branch summaries without loading every branch transcript;
7. unmounting OperationView does not cancel the underlying operation;
8. package tests run without MUI context/theme.

## Do Not Do

- Do not add MUI.
- Do not add a product theme.
- Do not implement app routing or panel layout.
- Do not duplicate transport/model/editor-core state machines.
- Do not implement source-specific projection editors.
- Do not query the server directly from visual components when a hook/controller exists.
- Do not create frontend-only mutation semantics.
