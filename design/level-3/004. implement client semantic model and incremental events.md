# Implement Client Semantic Model and Incremental Events

## Objective

Implement `@scriberig/model` as the framework-independent browser/client semantic state layer.

This package coordinates loaded protocol data, immutable revision caches, current snapshot resolution, operation state, and event application. It must not become a second canonical database and must not depend on React or MUI.

## Model Boundary

The model owns client-side knowledge of already loaded server state.

It may cache and coordinate:

- immutable revisions;
- entity resolution for one or more known snapshots;
- loaded relation pages;
- operation records;
- connection/event status;
- stale-view markers;
- pending migration previews represented by public protocol objects.

It must not claim that locally cached state is authoritative beyond the snapshot/revision references received from the server.

---

## Revision Cache

Implement a cache keyed by immutable `RevisionId`.

Required behavior:

- inserting the same revision twice is idempotent;
- immutable revision content is never mutated in place;
- a later global snapshot does not evict unchanged revisions automatically;
- consumers may query whether a revision is loaded;
- cache values preserve the protocol type/summary required to render or inspect them.

Do not key immutable content solely by mutable/current entity identity.

---

## Snapshot State

Represent at least:

```text
current server snapshot
viewed/selected snapshot
historical snapshot state
branch/candidate snapshot state when supplied by protocol
```

The model must make it possible to distinguish:

- viewing the current snapshot;
- viewing an older exact snapshot;
- a view that became stale because current state advanced;
- candidate state that has not become canonical.

Do not silently advance historical views when the current snapshot changes.

---

## Entity Resolution

Maintain loaded entity-to-revision resolutions scoped by snapshot when required by the protocol.

A snapshot-advanced event may mark current resolutions stale or replace them when the event contains enough information.

Do not rewrite immutable cached revision data when an entity resolves to a new revision.

---

## Relation Cache

Cache loaded relation/collection pages by enough identity to prevent mixing incompatible states.

At minimum include semantic scope such as:

```text
snapshot or exact revision context
entity
relation
page/cursor parameters
```

If the server returns immutable relation-result identities, prefer those.

Do not merge pages from different snapshots without explicit compatibility evidence.

---

## Operation Store

Track long-running operations independently from the component/panel that started them.

Support lifecycle states from the protocol:

```text
queued
running
completed
failed
cancelled
```

Store progress and result references without copying canonical objects into ad-hoc UI-only forms.

Operation updates from events must be idempotent where possible.

---

## Event Reducer

Implement a pure or testable event-application layer.

It must handle the event categories provided by `@scriberig/protocol`, including where available:

- snapshot advanced;
- entity revision changed;
- projection changed;
- branch/session changed;
- migration/validation completed;
- operation progress/completion/failure/cancellation;
- agent output references or chunks;
- connection/resume state.

Important rule:

> A global snapshot change invalidates only current-resolution assumptions, not every immutable cached revision.

---

## Subscription API

Expose a small framework-independent subscription mechanism so React and other consumers can observe changes.

Requirements:

- subscribe/unsubscribe;
- notify only after consistent model transitions;
- no React dependency;
- no direct component references;
- allow selectors or narrowly scoped subscriptions if simple to implement without a state framework.

Do not add Redux, Zustand, MobX, RxJS, or another state library in this task.

---

## Stale-State Helpers

Provide reusable helpers for determining conditions such as:

```text
view snapshot != current snapshot
entity changed since edit base
candidate migration base is stale
connection lost while viewing live state
```

Helpers should return structured state, not user-facing prose.

---

## Workspace Model

`workspace-model.ts` composes the client, caches, event reducer, and subscriptions.

It should provide high-level methods needed by later packages for:

- inspecting/loading semantic objects through the client;
- resolving loaded entities;
- loading relation pages;
- observing current snapshot;
- inspecting operations;
- applying incoming events;
- starting/stopping event subscriptions.

Do not add visual selection or command palette logic here; those belong to `@scriberig/editor-core`.

---

## Tests

Required tests include:

1. a snapshot advances while an unchanged revision remains cached and reusable;
2. an entity resolves to a new revision without mutating the old revision object;
3. historical viewed snapshot remains historical after live snapshot advances;
4. relation pages from different snapshots do not mix;
5. operation progress events update one durable operation record;
6. duplicate/replayed events do not corrupt state;
7. disconnect state becomes observable.

Use fake client/transport objects. Do not require a running server.

## Do Not Do

- Do not add React.
- Do not add MUI.
- Do not store panel layout.
- Do not implement universal selection yet.
- Do not implement command discovery yet.
- Do not hide snapshot identity from consumers.
- Do not mutate immutable cached revisions.
- Do not refetch all known data after every snapshot event.
- Do not persist browser-local state into canonical knowledge.
