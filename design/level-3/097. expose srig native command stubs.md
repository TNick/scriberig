# Expose `srig` Native Command Stubs

**Status: [x] Complete**

## Objective

Expose the stable native command grammar described by `design/level-2/020. repository scaffold conventions and native command surface.md` without pretending that the TUI, API server, one-shot runtime, integrated agent runtime, or maintenance behavior is implemented.

The Cargo package under `apps/scriberig` remains named `scriberig`, but the executable produced by that package must be named `srig`.

---

## Required Command Surface

The executable must expose:

```text
srig tui
srig serve
srig run <PROMPT>
srig agent <PROMPT>
srig maintenance
```

It must also expose conventional parser-generated:

```text
srig --help
srig --version
```

`serve` must accept:

```text
--host <HOST>
--port <PORT>
```

Reasonable local-development defaults are allowed while server startup is still a stub.

---

## Ownership

Implement command parsing in:

```text
crates/scriberig-cli/
```

Keep the process entry point in:

```text
apps/scriberig/src/main.rs
```

The process entry point must delegate to the CLI crate and contain no mode-specific business logic.

Do not implement server, TUI, agent, storage, or semantic behavior in `scriberig-cli` merely to make the commands appear functional.

---

## Stub Behavior

Each mode stub must:

- parse successfully;
- appear in help output;
- accept its documented arguments;
- state clearly that the selected runtime mode is not implemented yet;
- return without claiming that work was performed.

Prompt-driven stubs may acknowledge that a prompt was accepted, but should avoid unnecessarily echoing prompt contents.

---

## Documentation Rules

All added Rust source must comply with repository conventions:

- module/file documentation;
- documented public and private functions;
- documented command/argument types and fields;
- plain intent comments after declaration documentation, with no blank line between Rust docs and the comment;
- 4-space Rust formatting;
- source files below the 400-line limit excluding preamble.
