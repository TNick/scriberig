# Persist Projection Conflicts and Captured Evidence

## Objective

Preserve ambiguous or failed projection reconciliation as structured knowledge so an external edit is never reduced to a transient watcher event or silently guessed into canonical history.

## Read First

1. `design/level-1/013. trust validation capabilities and provenance.md`, especially sections 20–23, 44–45, 51 and 60.
2. `design/level-1/006. projections and bidirectional editing.md`.
3. Existing projection/reconciliation Level 2 and Level 3 designs.
4. Existing provenance/core task.

If projection state, captured projection bytes/text, or candidate reconciliation does not exist yet, stop and report the prerequisite.

## Expected Area

Work primarily in the projection layer and its schema/graph integration. Typical modules:

```text
crates/scriberig-projection/src/conflict.rs
crates/scriberig-projection/src/reconcile.rs
crates/scriberig-projection/src/lib.rs
```

Use existing graph/schema facilities for persistence. Do not create an unrelated logging database.

## Captured Observation

When a managed projection changes externally, capture an immutable observation before attempting destructive normalization. It must retain enough data to identify:

```text
projection identity
previous rendered projection/revision
observed external content or blob reference
observation metadata/time if supported
current semantic snapshot
parser/adapter identity and version
```

The original observation must remain distinguishable from any parsed candidate.

## Conflict Object

Define a structured conflict capable of representing at least:

```text
base projection/reference
current canonical snapshot
observed external evidence
candidate parse/revision if one exists
ambiguous mappings
conflicting entities/relations
conflict kind
status
```

Support unresolved and resolved states through immutable history/operations rather than by erasing the original conflict.

## Reconciliation Behavior

When matching is confident, normal reconciliation may continue.

When matching is ambiguous, the reconciler must return/persist an explicit conflict or candidate alternatives. It must not choose an uncertain lineage silently.

The canonical root remains unchanged until a later resolution produces a normal migration that passes the standard validation/promotion path.

## Resolution

Provide an application-facing resolution input that references the exact conflict and selected interpretation. The result should produce a normal migration/candidate plus provenance linking back to the conflict and captured observation.

Do not make conflict resolution a privileged direct storage mutation.

## Tests

Create fixtures for:

1. clean external edit -> no conflict;
2. ambiguous paragraph merge/split -> conflict persisted;
3. conflicting concurrent canonical change -> conflict references both states;
4. original observed content remains accessible after parse failure;
5. parser output is distinguishable from original evidence;
6. unresolved conflict does not change canonical root;
7. resolution creates migration provenance back to conflict;
8. resolving stale conflict against changed canonical state requires re-evaluation;
9. conflict history preserves the original competing states.

## Validation

Run workspace formatting, check, tests, and lint. Use deterministic small projection fixtures.

## Do Not

Do not insert textual conflict markers into canonical semantic objects as the primary conflict representation. Do not discard the external observation after parsing. Do not auto-promote a parser's best guess when the matcher reports ambiguity.

## Completion Checklist

- [ ] external observations are immutable evidence;
- [ ] ambiguity becomes a first-class conflict;
- [ ] canonical state is unchanged by unresolved conflicts;
- [ ] conflict resolution creates a normal migration/candidate;
- [ ] provenance reaches back to original observation;
- [ ] tests cover ambiguity and concurrent changes.
