# Implement: Bootstrap Persistence Workspace and Core IDs

## Objective

Create the initial Rust workspace and the four persistence crates prescribed by Level 2. Implement only the foundational identifier/value types needed by later storage work.

This task must leave the repository compiling and ready for the next implementation task.

## Read first

Read these documents before editing code:

1. `design/level-1/004. persistence and storage model.md`
2. `design/level-2/001. persistence crate boundaries.md`
3. `design/level-2/002. canonical encoding and revision identity.md`

Do not implement agents, Markdown, sessions, CLI commands, HTTP APIs, or web code.

If a file already exists because another task ran first, preserve compatible work and modify only what is required.

## Workspace setup

The root `Cargo.toml` must declare a Cargo workspace containing the four crates.

Use the repository's selected Rust edition consistently. If none has already been selected, use the current stable edition supported by the local toolchain and record it only in Cargo metadata; do not create a design decision outside this task.

## `sr-core` requirements

Implement strongly typed wrappers for:

- `EntityId`
- `RevisionId`
- `SnapshotId`
- `RootName`
- `ObjectType`
- `EncodingVersion`

Requirements:

- identifiers are not type aliases to `String`;
- `RevisionId` and `SnapshotId` can hold a fixed BLAKE3 digest;
- IDs implement the ordinary traits needed for map keys and tests: equality, ordering where sensible, hashing, clone/copy where sensible, and debug formatting;
- textual display and parsing of digest IDs are deterministic and round-trip;
- invalid textual IDs return an error instead of panicking;
- `RootName` validates obvious invalid empty names;
- backend-specific information must not appear in these types.

`encoding.rs` should define the `EncodingVersion` type and a placeholder/public boundary for canonical encoding used by the next task. Do not invent a full domain value model yet.

## Dependency rules

- `sr-core` depends on no Scriberig crate.
- `sr-store` depends on `sr-core`.
- `sr-store-memory` depends on `sr-store` and `sr-core` as needed.
- `sr-store-sqlite` depends on `sr-store` and `sr-core` as needed.
- No inverse dependency is allowed.

Add BLAKE3 only where needed for digest representation/testing. Do not add SQLite implementation dependencies yet unless required only to make the empty backend crate compile.

## Tests

Add unit tests for:

- `RevisionId` display/parse round trip;
- `SnapshotId` display/parse round trip;
- invalid digest text is rejected;
- two different digest bytes are different IDs;
- empty `RootName` is rejected;
- the workspace compiles with all four crates.

## Commands to run

Run at minimum:

```text
cargo fmt --check
cargo test --workspace
```

If formatting fails, run `cargo fmt`, then rerun the checks.

## Do not do

- Do not create SQL tables.
- Do not implement snapshots.
- Do not implement an agent API.
- Do not add CLI binaries.
- Do not create semantic/domain types such as `Paragraph` or `Function`.
- Do not make IDs depend on file paths or database row IDs.
