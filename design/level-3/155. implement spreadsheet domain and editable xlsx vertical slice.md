# Implement Spreadsheet Domain and Editable XLSX Vertical Slice

## Status

Planned.

All completion items remain unchecked until implemented and verified.

## 1. Goal

Implement the first rich-artifact vertical slice: a format-independent spreadsheet domain plus an XLSX adapter that can safely inspect and edit a bounded workbook through normal Scriberig semantic change flow.

The minimum product scenario is:

```text
onboard workbook.xlsx
inspect Workbook
list worksheets
inspect used range on sheet Budget
inspect B3
change B3 value or formula semantically
create candidate
validate candidate
review/apply
materialize workbook.xlsx
reopen workbook and prove the edit
```

This task depends on task 154.

## 4. Architectural Prohibitions

Do not:

- treat XLSX ZIP/XML/package parts as the canonical spreadsheet model;
- make the external XLSX library's workbook structs public Scriberig semantic types;
- eagerly create semantic records for every possible empty Excel cell;
- treat cell display formatting as the same thing as cell value/formula semantics;
- treat cached formula results as authoritative recalculation;
- mutate `xl/worksheets/*.xml` directly from agent/UI code;
- expose insert-row/ref-rewrite operations until their formula/reference semantics are correct;
- silently drop macros, signatures, charts, relationships, unknown package parts, or other source-significant content;
- claim write fidelity when the chosen library cannot preserve encountered workbook structures.

## 5. Phase A — Choose Package Layout and XLSX Dependency

Create a format-independent spreadsheet domain.

Preferred layout:

```text
crates/domains/scriberig-domain-spreadsheet/
```

Place XLSX-specific code either in focused modules there initially or create:

```text
crates/domains/scriberig-domain-xlsx/
```

Use a separate XLSX crate if external dependencies/package logic would otherwise leak into the generic domain.

Before adding a dependency:

- [ ] Evaluate at least the practical current Rust XLSX read/write options available to the repository.
- [ ] Record why the selected library is suitable for the first vertical slice.
- [ ] Record known preservation/write limitations.
- [ ] Verify license compatibility.
- [ ] Update `THIRD_PARTY_NOTICES.md` if required.
- [ ] Keep the library behind adapter-private modules.

Do not make library choice an architectural commitment.

## 6. Phase B — Define Spreadsheet Semantic Schema

Implement minimum semantic types/schema equivalent to:

```text
Workbook
Worksheet
Cell
Range
Formula
DefinedName
Table
CellStyleRef
```

Requirements:

- [ ] Workbook and Worksheet have stable semantic identities.
- [ ] Worksheet ordering is represented by owning collection structure.
- [ ] Cell identity is semantic and snapshot-aware, not merely a display string.
- [ ] Empty cells are not eagerly materialized across the full Excel grid.
- [ ] Cell values distinguish at least blank/string/number/boolean/error/formula where source safely supports them.
- [ ] A formula preserves authored formula text/expression.
- [ ] Formula references can be inspected or derived without making cached result authoritative.
- [ ] Defined names are imported at least for inspection if supported by the selected adapter.
- [ ] Tables are imported at least as semantic ranges/metadata if supported.
- [ ] Cell style reference is separated from cell value/formula semantics.
- [ ] Schema and adapter versions are registered using existing domain version conventions.

Focused tests:

- [ ] create workbook semantic graph with two sheets;
- [ ] stable cell handle resolves in exact snapshot;
- [ ] one changed cell creates local revision/change set;
- [ ] empty surrounding grid does not appear as thousands of semantic entities.

## 10. Phase F — Implement Safe Spreadsheet Operations

Implement first operations:

```text
spreadsheet.set_cell_value
spreadsheet.set_formula
spreadsheet.rename_sheet
```

`spreadsheet.insert_rows` is optional in this task unless formula/reference rewriting is fully correct.

Requirements:

- [ ] Operations resolve Workbook/Worksheet/Cell semantic handles in exact base snapshot.
- [ ] Operations produce candidate semantic state through shared change model.
- [ ] No operation writes the live XLSX file directly.
- [ ] `set_cell_value` rejects invalid target/kind changes cleanly.
- [ ] `set_formula` preserves formula source semantics.
- [ ] `rename_sheet` updates dependent formula/name references only if the implementation can do so correctly; otherwise block rename when dependencies exist and explain why.
- [ ] Changed-set/diff identifies target sheet/cell/formula, not the whole workbook by default.
- [ ] Provenance identifies user/agent/application operation.

Focused tests:

- [ ] set B3 formula to `=A3*3` creates candidate only;
- [ ] canonical project snapshot remains unchanged before apply;
- [ ] semantic diff reports B3/formula change;
- [ ] invalid stale-base operation fails without mutation.

Requirements:

- [ ] Candidate workbook renders to staged XLSX bytes.

- [ ] Cached formula result mismatch is not treated as semantic failure unless explicitly recalculated by a supported engine.
