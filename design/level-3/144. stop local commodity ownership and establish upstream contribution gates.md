# Stop Local Commodity Ownership and Establish Upstream Contribution Gates

**Status: [ ] Not Started**

## 1. Objective

Begin the correction defined by `design/level-2/032. upstream first agent runtime and terminal product ownership correction.md`.

This task does not yet replace large production subsystems. It creates the authoritative ownership/deletion map, freezes further local duplication, and identifies every generic capability that must be consumed from or contributed to upstream before later tasks proceed.

The result must make it impossible for a later implementation agent to interpret “use upstream” as “wrap one upstream helper but keep the Scriberig framework.”

## 7. Establish Upstream Contribution Gates

For every generic missing capability, create a gate entry conceptually equivalent to:

```text
Capability:

Current upstream limitation:
Required upstream public API:

Temporary Scriberig workaround, if user-authorized:
Removal condition:
Consumer task:
```

Likely candidates include:

```text
reusable model registry/catalog outside rpi-cli
reusable provider auth/config service outside rpi-cli

reusable package-manager API if currently CLI-only
generic tree/virtualized hierarchy component if rpi-tui lacks one
plugin-visible panel/component extension point if third-party terminal panels are required
provider continuation primitives not yet exposed by rpi-ai
```

Acceptance:

- [ ] Every later task can distinguish “blocked on upstream” from “implement locally.”
- [ ] Temporary local exceptions require explicit user authorization and a removal condition.
- [ ] No upstream gap is hidden behind an adapter named as if the feature were already delegated.
