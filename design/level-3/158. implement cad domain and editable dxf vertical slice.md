# Implement CAD Domain and Editable DXF Vertical Slice

## Status

In Progress. A format-independent CAD crate now models typed drawing geometry,
layers, spaces, blocks, layouts, viewports, and external references. It retains
native handles as external provenance. A DXF read adapter imports line, circle,
arc, and text entities, and project onboarding stores drawing/layer/entity
revisions separately. The adapter maps line, classic/lightweight polyline,
circle, arc, and text entities; the focused R14 fixture verifies line and
lightweight-polyline import. Project onboarding stores the import completeness
flag and safe unsupported-entity diagnostics in the drawing summary, while the
exact source bytes remain available as artifact evidence. Typed line, layer,
and text edits patch existing raw record values when unknown content is present
and exact preservation is provable; output reopens with the same native handle.
Exact
snapshot project/application readers return layer summaries and bounded typed
entity pages, and Rust/web clients expose those reads. The project service also
supports exact-snapshot, case-insensitive CAD annotation and dimension-override
text search with bounded semantic results. Project
line edits create exact-base shared candidates and the `dxf-package` validator
reopens staged output before the shared apply path can materialize it. Exact
layer changes now resolve both entity and destination layer in the same drawing,
create shared candidates, and preserve the selected native handle through
reopen. The layer-change operation is exposed through app authorization and the
typed Rust and web protocol/client paths, plus the RPI TUI's shared candidate
review flow. Focused web wire/model/component checks and TUI local/remote
projection tests pass. The app now authorizes project-level text, layer, and
spatial-bounds queries against exact snapshots. Projection bounds anchors, selection-bound agent
composition, broader operations, and full fidelity and reconciliation
contracts remain open. The project query service also filters bounded entity
pages by semantic layer, geometry kind, and approximate space-scoped bounds;
resolves external handles back to snapshot semantic entities; and finds
authored annotation text. Dedicated reconciliation/index-backed handle
evidence remains open.

Implementation update (2026-10-27): DXF artifact fidelity derives from the
persisted source digest and exact raw-edit support. Complete imports use the
lossless parser writer. Incomplete imports with supported, uniquely handled
entities advertise opaque-preserving editability; unsupported-only sources
remain read-only. Candidate validation proves exact raw-record preservation
for typed line, layer, and text edits. External-file reconciliation remains
open and disabled. Opaque-source candidate validation also binds the staged
semantic field to the candidate's recorded before/after values, so a valid
raw-field change cannot substitute a different semantic intent.

## 4. Architectural Prohibitions

Do not:

- make DXF group-code records the canonical CAD domain model;
- make native DXF handles equal Scriberig `EntityId`;
- make screen/canvas pixels canonical geometry coordinates;
- flatten all entity types into one generic string/property bag when meaningful CAD semantics are known;
- discard unsupported DXF sections/entities merely because first vertical slice does not understand them;
- write live DXF directly from agent/UI code;
- couple generic CAD schema to task-161 DWG provider implementation.
