# Enforce Capabilities in Application Queries

> Implemented against the current workspace on 2026-10-11. The shared
> application boundary is `GuardedQueryService`; reusable query and traversal
> providers remain policy-free and are wrapped before product use.

## Objective

Make the shared application layer enforce effective capability scope for inspection, traversal, search, reverse lookups, summaries, and derived views.

The generic graph/query libraries remain reusable below policy. Scriberig product surfaces must use the guarded application operations.

1. `design/level-1/013. trust validation capabilities and provenance.md`, especially sections 8–13, 30–31, 52, 62–63.

## Expected Area

Work primarily in the application layer. Typical files may include:

```text
crates/scriberig-app/src/authorization.rs
crates/scriberig-app/src/query.rs
crates/scriberig-app/src/inspect.rs
crates/scriberig-app/src/lib.rs
```

Adapt names to the actual repository. Do not move authorization into `scriberig-store` or make the reusable query engine agent-specific.

## Guarded Operations

Create or extend application operations for at least:

```text
inspect entity
list/follow relations
reverse relation lookup
search/find
get description/summary
diff/history lookup where data exposure occurs
```

Every operation must receive or resolve an effective principal/capability context before returning semantic data.

## Traversal Rule

Authorization must be checked at each exposed result boundary, not only on the root object.

A caller permitted to inspect `Function F` must not automatically receive every entity reachable from `F` through arbitrary relations.

Search and reverse indexes must not reveal restricted entity names, descriptions, snippets, counts, or existence when the policy says those facts are confidential.

Choose one consistent behavior for hidden results through the existing application error/result conventions:

- filtered from result sets; or
- represented by an explicit redacted/denied result when the caller already knows the identifier.

Document that behavior in code comments and tests.

## Derived Views

Descriptions, summaries, cached semantic views, and convenience projections must be checked against the dependencies they expose. Do not treat them as public merely because they are derived.

This task does not implement cache partitioning; it must ensure the application path cannot fetch a derived artifact whose effective scope is broader than the principal's authority.

## Structured Denials

Use the denial type from the capability task. Do not convert a capability denial into `NotFound` unless an existing confidentiality policy explicitly requires non-disclosure of existence.

Do not include restricted content in error messages.

## Tests

Build fixtures with at least two allowed entities and one restricted entity. Test:

1. direct allowed inspection succeeds;
2. direct restricted inspection is denied;
3. allowed root traversal does not leak a restricted neighbor;
4. reverse lookup does not leak a restricted source;
5. global search omits restricted text/snippets;
6. summary lookup respects the subject's access scope;
7. a caller with broader capability sees the same hidden entity;
8. denial does not disclose hidden payload text;
9. lower-level query APIs remain callable without application policy for intentional embedded-library use;
10. official application operations never bypass the guard.

## Validation

Run workspace formatting, check, tests, and lint. Add integration tests at the application boundary rather than only unit-testing helper predicates.

## Do Not

Do not add authorization checks to every storage read. Do not modify query semantics to contain agent-specific concepts. Do not create a second search implementation for authorized callers. Do not assume UI filtering is a security boundary.

## Completion Checklist

- [x] all application read/query paths use one capability guard;
- [x] relation traversal is scope-aware;
- [x] search/reverse indexes do not leak restricted content;

- [x] tests demonstrate both allowed and denied traversal.
