# Reconcile Repository Scaffold and Quality Automation

**Status: [x] Complete**

## Objective

Record and verify the repository-level scaffold and source-quality mechanisms described by `design/level-2/020. repository scaffold conventions and native command surface.md`.

This task concerns repository structure and developer/agent enforcement only. It does not implement semantic storage, query, projection, server, TUI, agent, or editor behavior.

---

## Required Repository Guidance

The repository must contain a root `AGENTS.md` that defines the global source rules and describes the major repository areas.

Important architectural directories must contain focused `AGENTS.md` files explaining their purpose and their relationship to adjacent layers.

At minimum, guidance must exist around:

```text
crates/
crates/domains/
apps/
web/
web/packages/
web/apps/
tools/
tests/
design/
```

Additional guidance should be placed at high-risk subsystem boundaries such as storage, graph/query/migration, projection, sessions, protocol, agent runtime, editor-core, MUI, and integrated applications.

---

## Required Source Conventions

The root guidance must require:

- source files no longer than 400 lines after excluding the leading preamble;
- Markdown and prose/text files exempt from that size limit;
- same-stem directory/module splitting as a preferred oversized-file strategy;
- a file-level description in every source file;
- documentation for every public or private function and method;
- parameter, return, and error documentation where applicable;
- class/class-like documentation including member documentation;
- a blank line followed by a one- or two-line `Block:` intent comment before each logical code block.

The conventions must apply to tooling code as well as product/library code.

---

## Required Formatting Policy

Repository configuration must encode:

```text
TypeScript / JavaScript: 2 spaces
Rust:                    4 spaces
```

Prettier must be the formatter for supported web source files.

Rustfmt must be the formatter for Rust source files.

---

## Required Automation

The repository must provide:

```text
tools/repo_lint.py
tools/repo_lint/
tools/fix.sh
tools/check.sh
tools/install-hooks.sh
.pre-commit-config.yaml
.github/workflows/quality.yml
```

The custom linter should automatically fix safe deterministic violations where practical and produce precise diagnostics for violations that require manual judgment.

The linter implementation must obey the same 400-line source rule rather than exempting itself.

---

## Pre-Commit Formatting

The web formatting hook must format staged JavaScript/TypeScript source with Prettier `--write` and re-stage only those exact files.

The hook must not format or stage unrelated workspace files.

CI remains verification-only and uses a non-mutating formatting check.

---

## Reconciliation Notes

The implemented repository includes the Rust workspace, domain adapter crate directories, native product composition root, pnpm web workspace, reusable web packages, integrated web application, test directories, repository tooling, nested `AGENTS.md` guidance, licensing artifacts, pre-commit hooks, and quality CI.

The existence of these files marks the scaffold itself as established. It does not mark the semantic implementation tasks for those crates/packages complete.
