# Implement CAD Domain and Editable DXF Vertical Slice

## Status

Planned.

All completion items remain unchecked until implemented and verified.

## 1. Goal

Implement a reusable CAD drawing semantic domain and an editable DXF adapter. DXF is the first required CAD materialization target; native DWG integration is handled separately by task 161.

Minimum scenario:

```text
onboard drawing.dxf
inspect Drawing
list layers
inspect entity on layer PARCELS
change supported entity semantically
create candidate
validate
review/apply
materialize DXF
reopen and verify
```

This task depends on task 157.

## 4. Architectural Prohibitions

Do not:

- make DXF group-code records the canonical CAD domain model;
- make native DXF handles equal Scriberig `EntityId`;
- make screen/canvas pixels canonical geometry coordinates;
- flatten all entity types into one generic string/property bag when meaningful CAD semantics are known;
- discard unsupported DXF sections/entities merely because first vertical slice does not understand them;
- write live DXF directly from agent/UI code;
- couple generic CAD schema to task-161 DWG provider implementation.

Requirements:

- [ ] Drawing/Layer/Block/Entity identities use Scriberig semantic identity.
- [ ] Native CAD handles are stored as external identifiers/provenance/reconciliation evidence.
- [ ] Entity geometry uses exact domain values with documented coordinate/unit semantics.
- [ ] Layer membership is semantic structure/relation, not inferred only from display color/name.
- [ ] Block definitions and references remain distinct.
- [ ] Model/paper/layout space is represented explicitly where encountered.
- [ ] Entity ordering is preserved when author/tool significance requires it.
- [ ] Schema version is registered.

Focused tests:

- [ ] edit one entity without revising unrelated entities;
- [ ] move entity between layers changes relation/structure explicitly;
- [ ] native external handle survives as provenance without becoming EntityId.

## 8. Phase D — CAD Queries and Anchors

Implement bounded semantic navigation/query sufficient for large drawings.

Required capabilities:

```text
list entities by layer

query by entity kind
query/intersect geometric bounds when practical
```

Requirements:

- [ ] Queries are snapshot-bound and paged.
- [ ] Results return semantic handles.
- [ ] Drawing projection can expose geometric bounds anchor separate from semantic identity.
- [ ] Large layer does not serialize every entity by default.
- [ ] Native handle lookup resolves through reconciliation/index evidence, not direct replacement for EntityId.

## 9. Phase E — Implement Safe CAD Operations

Implement at least two operations from:

```text
cad.move_entity
cad.change_layer
cad.update_text
cad.insert_polyline
```

Minimum required for golden path: one existing-entity edit plus one structural/geometry edit.

Requirements:

- [ ] Operations resolve exact semantic target/base snapshot.
- [ ] Candidate state is created without live file mutation.
- [ ] Geometry operation validates coordinate dimensionality/units.
- [ ] Layer operation verifies destination layer exists or uses explicit layer-create operation.
- [ ] Text operation preserves untargeted entity properties.
- [ ] Native handle behavior for edited entities is deterministic and documented.
- [ ] Operation provenance is recorded.
- [ ] Semantic diff identifies affected entity/layer relation rather than whole file blob.

Focused tests:

- [ ] move/update target creates candidate only;
- [ ] stale base fails/conflicts;
- [ ] unrelated entity revision stays unchanged;
- [ ] invalid geometry is rejected before materialization.

## 10. Phase F — Deterministic DXF Rendering and Preservation

Requirements:

- [ ] Candidate drawing renders through shared projection/artifact infrastructure.
- [ ] Supported entity semantics render deterministically.
- [ ] Untargeted supported entities survive.
- [ ] Opaque preserved sections/entities survive when fidelity advertises preservation.
- [ ] Native handles are preserved when safe or remapped with explicit provenance according to documented adapter rule.
- [ ] Expected external baseline is checked before replacement.
- [ ] Successful materialization records new artifact digest/baseline.
- [ ] Unsupported nonpreservable records block editability instead of being silently lost.

Do not require byte-identical DXF formatting unless adapter deliberately guarantees it.

## 11. Phase G — DXF Reconciliation

If external DXF editing synchronization is enabled:

- [ ] Reconciliation uses native handle as strong evidence but not sole identity authority.
- [ ] Fallback matching may use entity kind/layer/geometry/text/structural context.
- [ ] Ambiguous continuity creates conflict/new entity rather than invented identity.
- [ ] Concurrent semantic change participates in normal three-way reconciliation.
- [ ] Opaque preserved records absent from semantic parse are not automatically deleted.

If safe reconciliation is not ready:

- [ ] Keep external DXF synchronization read-only while semantic operations/materialization remain editable.
- [ ] Document the exact gap and do not fake completion.
