# Extend Session Records for Model Execution and Branch Results

**Status: [ ] Pending**

## Objective

Extend `scriberig-session` so the durable session graph can represent model-driven branch execution without introducing provider-specific canonical message types.

## Required Provider-Neutral Records

Represent at least these semantic records:

```text
ModelInvocation
ModelOutput
ToolInvocation
ToolResult
BranchResult
AgentOutput
```

Reuse existing `Branch`, `Turn`, `Summary`, `Observation`, `Decision`, and relation primitives.

### `ModelInvocation`

Must be able to retain non-secret provenance equivalent to:

```text
branch
turn/sequence position
agent profile reference/revision
context identity/fingerprint
provider profile display id
model id
request fingerprint
cache disposition
started/completed timestamps or ordering metadata
usage/result references when available
```

Do not store API keys, Authorization headers, or secret environment values.

### `ModelOutput`

Must represent externally meaningful complete output:

```text
assistant text or structured output reference
complete requested tool calls
finish/termination category
usage metadata when available
provider request/fingerprint metadata when safe
```

Do not require hidden chain-of-thought.

### `ToolInvocation` / `ToolResult`

Use stable Scriberig tool identity and structured arguments/results. Provider-native tool-call ids may be optional correlation metadata only.

### `BranchResult`

Must support:

```text
branch reference
terminal outcome/status
compact summary
result kind
result handles
touched entities
produced migration/workspace handles
validation handles
unresolved question handles
```

The result must be usable by the parent without loading all child turns.

## Branch Relationships

Add/verify relations equivalent to:

```text
Branch --parent--> Branch
Branch --contains--> ModelInvocation
ModelInvocation --produced--> ModelOutput
ModelInvocation --requested--> ToolInvocation
ToolInvocation --produced--> ToolResult
Branch --produced--> BranchResult
BranchResult --references--> semantic results
Branch --child--> Branch
```

Avoid duplicating existing generic containment/ordering relations when they already express the same semantics.

---

## Ordering

Execution activity within a branch must have deterministic explicit ordering independent of database row order.

The branch view must be able to interleave:

```text
HumanInput
ModelInvocation
ModelOutput
ToolInvocation
ToolResult
child branch start/result reference
AgentOutput
```

Do not derive chronology from UUID lexical order or insertion accidents.

---

## Compact Branch Descriptor

Extend the existing branch descriptor/view so a caller can read without loading activity bodies:

```text
purpose
status
outcome summary
child branch count
activity count
active operation/reference when modeled outside canonical branch state
result reference
important touched semantic handles
```

Runtime-transient scheduler phases do not belong in the durable branch lifecycle unless they have durable semantic value.

---

## Parent Collapse Support

Add a view/helper that returns a parent-consumable child result equivalent to:

```text
ChildBranchSummary {
  branch
  title/purpose
  terminal status
  outcome
  result handles
}
```

It must be possible to obtain this without loading the child's model/tool history.

---

## Provider Independence

Do not add canonical types named after specific wire payloads such as:

```text
ChatCompletionMessage
OpenAIResponse
AnthropicMessage
GeminiPart
```

Provider-specific raw JSON may later be linked as optional artifact/evidence but cannot be required to interpret the session graph.

---

## Tests

Prove at least:

- model invocation/output can be recorded in one branch;
- tool invocation/result are separately addressable and ordered;
- a child branch can produce a compact `BranchResult`;
- parent code can retrieve child descriptor/result without child activity bodies;
- nested child branches preserve parent identity;
- provider/model provenance contains no secret field;
- deterministic session views preserve execution ordering;
- historical exact references remain exact after unrelated session/project changes;
- the crate requires no HTTP client or model provider.

Run:

```text
cargo fmt --all -- --check
cargo test -p scriberig-session
cargo clippy -p scriberig-session --all-targets -- -D warnings
```

---

## Do Not Do

- Do not implement HTTP model calls.
- Do not implement the model/tool loop.
- Do not put provider credentials into session entities.
- Do not store hidden chain-of-thought as required session state.
- Do not create a transcript-only execution representation.
- Do not add TUI/web presentation code.
