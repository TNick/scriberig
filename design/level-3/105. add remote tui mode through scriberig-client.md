# Add Remote TUI Mode Through `scriberig-client`

**Status: [ ] Pending**

## Objective

Allow the same TUI state machine and views—including branch-aware agent/session workflows—to operate against a remote Scriberig server through the public `scriberig-client`/protocol boundary.

This task proves that the TUI is a peer product surface rather than a privileged local database or model-provider console.

This task is dependency-gated on a usable public client/server transport for the operations exposed by the TUI.

---

## Command Surface

Extend TUI startup with a mutually exclusive remote form equivalent to:

```text
srig tui --connect <ENDPOINT>
```

The local form remains:

```text
srig tui --db <PATH>
```

Define clear parser behavior when both local and remote selectors are supplied. Prefer a Clap argument group or equivalent parser-level mutual exclusion.

If neither is supplied, retain the documented local default unless product policy changes in a higher-level design.

The CLI crate parses endpoint text. It does not implement the client transport and does not accept model-provider credentials for remote mode.

---

## Remote Adapter

Add a remote implementation of the TUI service port using `scriberig-client`.

The adapter must preserve the same TUI-facing semantics as the embedded adapter for:

```text
stable references
explicit snapshot/branch context
structured errors
capability discovery
operation IDs/status
operation cancellation
event observation
pagination/cursors
agent start/continue
session and nested branch queries
BranchResult / AgentResult navigation
```

Do not make views branch on HTTP status codes or protocol serialization details. Translate transport/protocol results at the adapter boundary.

Do not depend on `scriberig-server` internals.

The local and remote adapters should implement the same service trait/port expected by the TUI reducer/effect runner.

---

## Agent Execution in Remote Mode

Remote TUI agent work follows exactly the same public flow as local TUI work:

```text
composer
-> AgentStartRequest / AgentContinueRequest
-> remote scriberig-client
-> server scriberig-app AgentService
-> server-hosted agent runtime/model provider
-> OperationId + SessionRef + BranchRef
-> protocol events/session queries back to TUI
```

The TUI must not:

```text
connect directly to OpenAI-compatible endpoint
hold provider API key
serialize provider tool definitions
run a second local model loop while connected remotely
```

Provider configuration and secrets live on the server host in remote mode.

---

## Connection State

Add explicit connection presentation states equivalent to:

```text
connecting
connected
reconnecting
disconnected
failed
```

Connection state is product/runtime state, not canonical semantic state.

A disconnected remote client may retain previously loaded view models as visibly stale. It must not present them as current or allow state-changing actions that require a live authority unless the shared client/application model explicitly supports queued/offline operations.

No offline mutation or offline agent queue is required by this task.

---

## Capability Discovery

After connection, obtain runtime/server capabilities through the public protocol/client path.

The command palette and view actions must use the same capability-driven behavior as local mode.

Agent-related capabilities include concepts equivalent to:

```text
agent_start
agent_continue
session_branch_tree
session_branch_activity
agent_event_subscription
agent_streaming_output
operation_cancel
```

Do not enable an action in remote mode merely because it exists locally.

If the server/protocol/provider configuration cannot support a required operation, render it unavailable with a safe compatibility reason where the client contract provides one.

---

## Authentication and Secrets

Use only authentication mechanisms defined by the public client/server design at implementation time.

Do not invent provider credentials or persist secrets inside TUI view state.

Sensitive server-authentication values must not appear in debug/status messages, command history, snapshots, or rendered error details.

Provider API credentials never cross this boundary at all.

If interactive server credential entry is required, use a dedicated protected input flow defined by the client/auth design; do not implement ad-hoc secret persistence in this task.

---

## Events and Resume

Use the public client event-subscription mechanism implemented by the remote transport task.

Track the latest event cursor/sequence where the client exposes it.

On reconnect:

```text
attempt resume from last cursor
-> if replay succeeds, reduce retained events
-> if cursor is too old/unavailable, mark affected views stale
-> query authoritative operation/session/branch state
-> subscribe from current cursor
```

Never infer that an agent operation stopped merely because the event connection dropped.

Transient model text may be lost across a disconnect. Durable `AgentOutput`, `BranchResult`, and `AgentResult` must recover through normal queries.

---

## Remote Branch Tree

The branch-tree behavior from task 103 must be unchanged in remote mode.

In particular:

- completed child branches remain compact/collapsed by default;
- expanding a branch loads child descriptors/activity through client queries;
- full child history is not eagerly downloaded merely to draw the parent tree;
- nested result handles navigate through the same TUI semantic navigation;
- active operation markers come from shared status/events.

Network transport must not force a flat transcript presentation.

---

## Remote Streaming

Agent streaming events arrive as Scriberig protocol events, not provider-native SSE/JSON.

The remote adapter converts those events to the same TUI actions used by embedded mode.

Rules remain:

```text
ModelTextDelta -> transient TUI stream buffer
AgentOutputCommitted -> authoritative session refresh/output
BranchResultProduced -> result handle/branch refresh
terminal operation event -> operation/result refresh
```

Do not persist remote stream fragments as a TUI-owned transcript.

---

## Cancellation

Remote cancellation calls the same public operation cancellation endpoint used by other clients.

The TUI shows cancellation as pending until the remote server reports terminal state.

Closing the connection, closing a view, or exiting a branch screen is not equivalent to cancellation.

If the entire TUI process exits while remote work continues, server product policy determines whether the operation remains running; client disconnect alone must not implicitly cancel unless explicitly defined by the operation contract.

---

## Transport Errors

Separate transport failures from semantic application/agent failures in presentation.

Examples:

```text
transport unavailable / timeout / TLS / incompatible protocol
vs.
not found / permission denied / stale base / validation failure
vs.
provider authentication / rate limit / runtime budget failure returned safely by server
```

The remote adapter performs this mapping. Views consume the same TUI error model used by local mode where semantic categories match.

Provider diagnostics received from the server are already sanitized; the TUI must not attempt to reconstruct provider details.

---

## Pagination and Lazy Loading

Remote branch/session/object lists must preserve pagination/bounded loading.

Do not fetch:

```text
all branches
all activity in every branch
all tool result bodies
all session history
```

when the current view needs only descriptors or one selected page.

The same progressive-disclosure behavior required for model context should also keep remote UI bandwidth bounded.

---

## Tests

Use localhost/in-process deterministic server/client test infrastructure. Do not require public network or model access.

Cover at least:

- parser rejects simultaneous `--db` and `--connect`;
- same inspect fixture produces equivalent semantic TUI model in local and remote adapters;
- same deterministic `agent_start` returns equivalent operation/session/root branch state locally and remotely;
- nested child branch tree/result appears equivalently through both adapters;
- remote capability absence disables the same action path;
- transport failure is distinct from semantic/provider-safe failure;
- disconnect marks cached state stale but does not mark operation cancelled;
- recent event cursor reconnect resumes when supported;
- too-old cursor causes authoritative operation/session refresh;
- lost text deltas do not prevent durable final result recovery;
- remote cancellation uses shared operation lifecycle;
- secrets/auth material are not included in formatted TUI errors;
- provider credential fields do not exist in remote TUI service state;
- remote adapter does not depend on server private modules.

---

## Conformance

Compare local-TUI and remote-TUI adapter semantics using the deterministic agent conformance fixtures from task 115 when available.

Compare semantic references/result fields, not terminal cell snapshots.

Advance TUI capability entries to `verified` only when both local and remote paths required by that capability are actually tested according to the capability matrix policy.

## Out of Scope

Do not implement:

- offline canonical mutations;
- offline agent execution while disconnected;
- a private TUI-only protocol;
- direct server-internal calls;
- direct model-provider calls/credentials;
- automatic credential persistence;
- a separate remote-only view hierarchy;
- eager download of entire session/branch histories.
