# Integrate Universal Read, Diff, History, Render, and Change Operations

## Objective

Implement the `scriberig-app` service layer that dispatches the universal application grammar onto the canonical subsystems already owned by query, history/change, projection, and migration libraries.

This task is about composition, not duplication.

The application layer must provide one transport-independent execution boundary for:

```text
inspect
list
follow
find
query
diff
history
render
branch
apply
commit
```

while preserving exact snapshot context, structured results, explicit change semantics, and subsystem ownership.

## 1. Define the Application Service Boundary

In `src/service.rs`, define a public service trait or concrete facade following existing project conventions.

It must execute the universal request vocabulary and return the universal result vocabulary.

A simple conceptual boundary is:

```text
execute(ApplicationRequest) -> ApplicationResult
```

Typed convenience methods such as `inspect(...)` or `render(...)` may also be provided.

Do not force every caller to construct one enum if typed methods improve Rust ergonomics, but all methods must share the same semantic implementation path.

---

## 2. Inject Canonical Subsystem Providers

The application service should depend on provider traits/objects for:

```text
query/read service
history/diff service
projection/render service
change/migration service
snapshot/named-root resolution
```

Use generics, trait objects, or another existing project pattern.

Do not instantiate SQLite, an HTTP client, or a model provider directly in the app crate.

The service must be testable with in-memory doubles.

---

## 3. Resolve Snapshot Selectors Before Reads

When a request specifies an exact snapshot, use it directly.

When a request specifies a named root/current-root selector:

1. resolve it to one exact `SnapshotId` before starting the semantic operation;
2. rewrite/build the downstream query request with that exact snapshot;
3. execute entirely against that snapshot;
4. return the exact `SnapshotId` in the application result.

Never allow a long read to re-resolve the named root midway through execution.

If the named root disappears or cannot be resolved, return a structured application error.

---

## 4. Delegate Read Operations

Dispatch:

```text
Inspect
List
Follow
Find
Query
```

to `scriberig-query` service contracts.

Do not reproduce graph traversal/search/query logic in `scriberig-app`.

Preserve result handles, continuation tokens, provenance, and exact snapshot context unchanged except for application-level wrapping.

---

## 5. Delegate Diff and History

Dispatch `Diff` and `History` to the canonical change/history subsystem.

Requirements:

- accept only exact comparable states where the owning subsystem requires them;
- preserve semantic diff/history structures;
- do not render them to text in the app layer;
- map subsystem failures into structured application errors without losing conflicting/subject handles;
- preserve ancestry, migration, and provenance handles returned by the history layer.

If the canonical subsystem uses different names such as `compare` or `lineage`, adapt those operations rather than adding duplicate engines.

---

## 6. Delegate Render

Dispatch `Render` to `scriberig-projection` or the canonical projection service.

Preserve:

```text
subject
exact semantic state
projection/view identifier
style identifier/options
semantic correspondence/anchors where returned
```

A render operation must not mutate canonical knowledge.

If render-cache population occurs below this layer, it must not advance the canonical snapshot.

---

## 7. Delegate Branch

Dispatch `Branch` to the canonical change/workspace subsystem.

The request must identify an exact base snapshot after selector resolution.

Return the canonical branch/workspace handle and base state.

Do not create a separate application-only branch graph.

If the underlying system uses `WorkspaceId`, wrap/adapt it through the application result without manufacturing duplicate branch state.

---

## 8. Delegate Apply

Dispatch `Apply` to the canonical change/migration subsystem.

Preserve:

```text
branch/workspace
base/candidate state
migration proposal/change set
diagnostics
conflicts
validation requirements
```

Applying a change must **not** advance a canonical named root.

Add a test double that fails the suite if `Apply` invokes root promotion.

High-level domain operations, once registered later, must eventually route through this same apply/change mechanism.

---

## 9. Delegate Commit

Dispatch `Commit` to the canonical promotion/commit operation.

Preserve:

```text
base snapshot
candidate snapshot
accepted migration
validation/provenance handles
ancestry
resulting promoted/retained snapshot
```

Commit is the explicit universal promotion boundary.

Do not embed authorization or validation policy rules in this task beyond invoking the owning subsystem/policy service where required.

---

## 10. Map Structured Errors

In `src/error.rs`, map subsystem failures into application-level categories without reducing them to strings.

Support at least:

```text
NotFound
InvalidRequest
UnsupportedCapability
Conflict
ValidationFailed
Ambiguous
PermissionDenied
SnapshotUnavailable
OperationFailed
Internal
```

Where the source error includes handles such as:

```text
subject entity
base revision
current revision
left/right migration
candidate matches
```

retain them in the mapped error payload.

Use an internal/source error chain for diagnostics where project conventions permit it.

---

## 11. Do Not Add Surface Formatting

Application results must remain structured.

Do not add:

```text
ANSI text
Markdown-formatted status messages
JSON strings as a shortcut
HTML
terminal tables
agent prompt prose
```

Later adapters decide how to present the result.

---

## 12. Tests

In `tests/universal_operation_model.rs`, use deterministic test doubles for each subsystem.

Test at least:

1. all eleven operation kinds dispatch to the expected provider;
2. a named root is resolved exactly once before a read;
3. the resolved snapshot is visible in the read result;
4. `inspect/list/follow/find/query` do not invoke history/projection/change providers;
5. `diff/history` delegate to the history provider;
6. `render` delegates to projection and does not invoke canonical mutation;
7. `branch` records the exact base snapshot;
8. `apply` updates only branch/candidate state and never promotes a named root;
9. `commit` invokes the canonical promotion boundary;
10. structured conflict data survives error mapping;
11. validation failure remains distinguishable from conflict and internal failure;
12. result values contain no presentation-only strings as their sole semantics.

Run:

```text
cargo test -p scriberig-app
cargo check --workspace
```

If a canonical subsystem prerequisite does not yet compile, use local test traits/doubles only where the Level 2 design explicitly permits it; do not commit duplicate domain logic to work around the missing prerequisite.

---

## 13. Non-Goals

Do not implement:

- HTTP/server endpoints;
- CLI commands;
- TypeScript bindings;
- React hooks/components;
- agent tool schemas;
- authorization policy;
- background scheduling;
- domain high-level operation algorithms;
- storage/index algorithms.

---

## Completion Criteria

This task is complete when:

- one application service executes all eleven universal operations;
- read operations are snapshot-resolved before execution;
- each operation delegates to its canonical owning subsystem;
- no diff/history/render/change algorithm is duplicated in the app crate;
- apply and commit preserve the explicit candidate-versus-promotion boundary;
- structured errors and handles survive subsystem mapping;
- the service is testable entirely with in-memory providers;
- the resulting public API is transport-independent.
