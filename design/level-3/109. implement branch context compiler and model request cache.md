## Context Input

Define a `BranchExecutionContext` or equivalent containing stable inputs such as:

```text
session reference
branch reference
branch purpose/goal
current user instruction
parent descriptor/result inheritance
recent current-branch activity selector
semantic selection/scope
pinned semantic handles
accepted decision/open-task selectors
agent profile revision
context policy revision
provider capability descriptor
tool catalog descriptor
context budget
```

The compiler receives resolved semantic/session data through application/session query interfaces. It must not query SQLite directly.

---

## Compiled Context

Produce a provider-neutral ordered context with explicit blocks/messages and a dependency manifest.

Each block should preserve enough metadata to explain its origin without sending that metadata verbatim to the model unless useful.

Conceptual block categories:

```text
system/profile instructions
branch purpose
delegation/parent summary
current user instruction
recent branch activity
accepted decisions/open tasks
semantic object descriptions/content
tool-result summaries
child branch results
tool catalog metadata handled separately
```

The provider adapter later serializes this form.

---

## Branch Isolation Rules

For a child branch, default context inheritance is:

```text
child purpose/delegation instruction
parent compact descriptor
explicitly selected parent result handles
explicit semantic scope/base snapshot
selected accepted decisions
capability/tool subset
```

Do not automatically copy:

```text
all parent turns
all sibling turns
all child history from completed siblings
all project/session objects
```

A policy may explicitly request a bounded excerpt, but that choice must be represented in the compiled context and dependency manifest.

Add a test where a secret/unrelated marker in the parent's old activity is absent from the child compiled context unless explicitly selected.

---

## Current-Branch Recency

Implement a deterministic recent-activity policy.

Use semantic activity items rather than a provider transcript blob.

The policy should be able to retain recent:

```text
human inputs
committed model outputs
tool calls/results
child branch result references
```

Large tool results should prefer compact stored projections or semantic handles and remain reopenable.

Do not silently truncate structured identifiers out of summaries.

---

## Dependency Manifest

Record exact dependencies actually used in compilation.

A dependency entry should identify a stable kind and exact immutable identity where available, for example:

```text
session entity + revision
project entity + revision
branch result + revision
derived summary result id/revision
agent profile revision
context policy revision
tool schema hash
```

Do not include an entire current global snapshot merely because compilation happened while it was current.

Where a current selector is resolved, record the exact resulting revision/snapshot used.

---

## Determinism

Given the same resolved inputs, profile/policy revisions, provider capability descriptor, and tool catalog, compilation must produce the same canonical provider-neutral representation and dependency manifest ordering.

Avoid nondeterministic map iteration.

Timestamps that do not affect model input must not perturb the canonical representation.

---

## Budgeting

Implement deterministic bounded selection using a size/token estimate abstraction.

The compiler should prioritize conceptually:

1. required system/profile instructions;
2. branch purpose/current user instruction;
3. required result/selection handles;
4. recent current-branch activity;
5. relevant decisions/summaries;
6. optional deeper context.

When content cannot fit, preserve stable handles and short descriptors so the model can request deeper information.

Provider-specific token counting may be approximate initially, but the budgeting algorithm must be deterministic for a fixed estimator.

## Tool Catalog Contribution

The selected tool definitions participate in context identity even when serialized outside the message list.

Canonicalize each exposed tool descriptor using:

```text
tool id
description
argument schema
result description
execution mode
```

Sort or preserve an explicit deterministic catalog order.

Capability-denied tools must not appear in the compiled catalog.

## Request Fingerprint

Create a canonical model request fingerprint over at least:

```text
fingerprint schema version
provider compatibility profile
provider/model id
provider capabilities affecting serialization
agent profile revision
context policy revision
compiled context canonical form
dependency manifest
tool definitions
structured-output schema
output-affecting generation parameters
```

Use the repository's preferred cryptographic content hash/canonical encoding primitives where available.

Explicitly exclude:

```text
credentials
Authorization headers
non-semantic request UUIDs
wall-clock timestamp
UI focus/scroll state
unrelated snapshot changes
```

## Cache Policy

Implement at least:

```text
Disabled
RecordOnly
ReuseExact
```

### Disabled

Never reads/writes model response cache.

### RecordOnly

Calls the provider and records a successful complete result under the fingerprint.

### ReuseExact

Checks for an exact successful cached response first. On hit, returns it without provider invocation and records a reuse provenance relation/event for the new invocation.

Do not treat cache lookup as permission to bypass current capability checks or branch creation. The execution still exists in the current session/branch.

---

## Cache Record

Store enough metadata to audit reuse:

```text
request fingerprint
fingerprint schema version
provider profile/model identity
provider fingerprint/version metadata if available
complete normalized response
usage metadata
original model invocation reference
created/retention metadata
```

Do not store provider credentials.

Incomplete/cancelled/failed responses are not successful cache hits.

---

## Reuse Provenance

When a cached result is reused:

- create the current model-invocation/session record;
- mark it as cache-reused;
- reference the original cache/model invocation;
- preserve the current branch and dependency context;
- do not fabricate a new provider request id.

Later audit must be able to distinguish provider execution from cache reuse.

---

## Tests

Cover at least:

- identical input produces identical compiled context/fingerprint;
- unrelated global/session change outside dependencies does not change fingerprint;
- changing one referenced revision changes fingerprint;
- changing agent profile/context policy changes fingerprint;
- changing exposed tool schema changes fingerprint;
- secret credential value does not affect or appear in fingerprint material;
- child branch excludes unselected parent history;
- bounded compilation preserves handles for omitted detail;
- `RecordOnly` calls provider/cache write path;
- `ReuseExact` hit avoids provider invocation;
- reused response preserves origin provenance;
- incomplete/failed response cannot be reused as success.

Run:

```text
cargo fmt --all -- --check
cargo test -p scriberig-agent-runtime
cargo clippy -p scriberig-agent-runtime --all-targets -- -D warnings
```

## Do Not Do

- Do not implement the complete model/tool loop.
- Do not flatten entire sessions into provider messages.
- Do not key cache only by global snapshot id.
- Do not include secrets in fingerprints or cache records.
- Do not make cache reuse invisible in provenance.
- Do not require provider-specific DTOs for context compilation tests.
