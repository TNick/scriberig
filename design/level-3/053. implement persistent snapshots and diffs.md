# Implement Persistent Snapshots and Snapshot Diffs

## Mission

Implement immutable snapshots as a persistent Merkle radix map from `EntityId` to `RevisionId`.

This task is the core answer to the change-propagation problem: one entity revision change must produce a new global `SnapshotId` without forcing unrelated semantic entities to receive new revisions.

Do not implement named roots in this task.

## Required Snapshot Model

A snapshot is exactly a mapping:

```text
EntityId -> RevisionId
```

The mapping must be immutable.

Operations that appear to modify a snapshot must return a new `Snapshot` and leave the input snapshot fully usable.

The semantic containment graph must not be used as the storage Merkle tree.

## Persistent Trie

Implement a private immutable 16-way radix trie over all 128 bits of `EntityId`.

Each tree level consumes one 4-bit nibble.

There are therefore at most 32 branch levels before a leaf.

Logical node kinds:

```text
Empty
Branch(children[16])
Leaf(EntityId, RevisionId)
```

You may represent empty children compactly internally, but the logical hash must behave as though all nibble positions are ordered and explicit.

Use `Arc` or another immutable shared pointer so unchanged branches are physically shared between related snapshots.

## Node Hashing

Use BLAKE3.

Define different fixed domain tags for:

```text
empty trie node
branch trie node
leaf trie node
snapshot root
```

Every node hash must include `EncodingVersion`.

### Leaf hash

Hash the canonical encoding of:

```text
leaf domain tag
encoding version
EntityId bytes
RevisionId bytes
```

### Branch hash

Hash the canonical encoding of:

```text
branch domain tag
encoding version
16 child node digests in nibble order
```

### Empty hash

Define one deterministic empty-node hash per encoding version.

### Snapshot ID

The `SnapshotId` must be derived from:

```text
snapshot-root domain tag
encoding version
root trie digest
```

Do not use the internal root node digest directly as `SnapshotId` without the extra snapshot-root domain separation.

## Required `Snapshot` Operations

Expose behavior equivalent to:

```text
Snapshot::empty(version)
snapshot.id()
snapshot.len()
snapshot.resolve(entity)
snapshot.with_revision(entity, revision)
snapshot.without_entity(entity)
snapshot.iter()
snapshot.diff(other)
```

Exact Rust signatures may differ, but the semantics must match.

### `with_revision`

- [x] Returns a new snapshot.
- [x] Old snapshot remains unchanged.
- [x] If the entity already resolves to the exact requested revision, return an equivalent snapshot with the same `SnapshotId`.
- [x] Only nodes on the entity's radix path may be newly allocated, except for harmless implementation metadata.

### `without_entity`

- [x] Returns a new snapshot when the entity exists.
- [x] Returns an equivalent snapshot with the same ID when the entity is absent.
- [x] Must not mutate the previous snapshot.
- [x] May collapse now-empty internal branches if canonical hashing stays deterministic.

### `resolve`

Resolve only against the supplied snapshot. Do not consult a global current root.

## Deterministic Iteration

Iteration order must be ascending by `EntityId` bytes.

Do not expose hash-table ordering.

This deterministic order is also the required order for diff results.

## Snapshot Diff

Define public diff result cases equivalent to:

```text
Added(entity, revision)
Removed(entity, revision)
Changed(entity, from_revision, to_revision)
```

`snapshot.diff(other)` must return only entity resolutions that actually differ.

The first implementation may compare the deterministic iterators if that is simpler and clearly correct.

Do not block this task on an optimized Merkle-aware diff.

Keep trie internals private so a later optimized implementation can skip equal subtrees by digest without changing the public API.

## Structural-Sharing Verification

Add a test-only mechanism to determine whether unchanged trie subtrees are pointer-shared.

This mechanism must not become part of the normal public production API.

Construct two snapshots that differ in one entity whose first nibble differs from at least one unchanged entity.

Verify that an unaffected top-level child subtree is shared between old and new snapshots.

## Required Tests

In `crates/sr-store/tests/snapshots.rs`, test at least:

- [x] empty snapshot ID is deterministic;
- [x] two independently built empty snapshots have identical IDs;
- [x] inserting one mapping changes the snapshot ID;
- [x] old snapshot does not resolve the newly inserted mapping;
- [x] new snapshot resolves it;
- [x] setting the same revision again preserves `SnapshotId`;
- [x] removing an absent entity preserves `SnapshotId`;
- [x] removing an existing entity changes `SnapshotId`;
- [x] insertion order does not affect final `SnapshotId`;
- [x] two snapshots with the same complete mapping have the same ID;
- [x] iteration is deterministic by `EntityId`;
- [x] diff reports added entities;
- [x] diff reports removed entities;
- [x] diff reports changed revisions;
- [x] diff omits unchanged entities;
- [x] an unaffected trie branch is structurally shared;
- [x] many entities sharing long nibble prefixes resolve correctly.

Also add a regression test demonstrating the architectural rule:

```text
changing P2 from PR8 to PR9
```

changes only the `P2` mapping while `F`, `P1`, and `B` continue resolving to their previous revision IDs.

## Performance Guardrail

Do not add a benchmark requirement yet, but ensure one mapping update does not rebuild an iterator-sized copy of the whole mapping.

The implementation path for one update must be bounded by trie depth, not by total entity count.

## Do Not

- Do not recursively hash the semantic object graph.
- Do not include parent entity revisions automatically in a child update.
- Do not use a mutable `HashMap` as the authoritative snapshot state.
- Do not make `SnapshotId` an incrementing integer.
- Do not create a global current snapshot.
- Do not implement named roots or CAS in this task.
- Do not expose `Arc` or trie nodes as public semantic API.
