# Implement Spreadsheet Domain and Editable XLSX Vertical Slice

## Status

In Progress. The format-independent sparse spreadsheet schema, bounded range
collection, and a retained-package XLSX import/cell-edit adapter are implemented.
Project onboarding creates separate workbook, worksheet-summary, and cell
entities; worksheet revisions do not embed their complete cell collection.
The XLSX adapter reports read-only capability when `rxls` cannot establish safe
package editing. Exact-base cell candidates now retain package edits without
changing live files, and a registered isolated validation profile reopens
staged XLSX bytes. The shared apply path materializes the candidate, reimports
it, records the new source digest, and preserves the unrelated Notes sheet.
Applying the edit changes only the target cell among spreadsheet cell
revisions. Rust and web protocol/client APIs expose exact-base spreadsheet
candidate creation under trusted Propose grants. The web model controller
requests bounded pages and the reusable component renders them with semantic
cell IDs; the web client also normalizes candidate handles and exact-snapshot
workbook/table summaries. The integrated agent catalog exposes a capability-
gated typed cell edit that returns a normal candidate while leaving live bytes
unchanged. Bounded multi-cell proposals now write one retained-package update
into one exact-base candidate, with typed before/after values for every changed
cell. The application, authorized HTTP protocol, and Rust/web clients expose
this operation; live bytes remain unchanged until shared apply. Focused package,
project apply, protocol, server authorization, and web client tests pass.
Interactive multi-cell range editing controls remain open.

XLSX import now maps parser-owned worksheet table names and ranges into shared
semantic `Table` records. Table IDs derive from the worksheet handle and authored
table name, so sibling ordering does not change their identity. The deterministic
vertical-slice fixture verifies table range normalization and repeat-import
identity. Workbook-global and worksheet-local defined names are both exposed;
the fixture verifies the local name resolves to the exact semantic worksheet ID.
The spreadsheet domain now registers schema version 1, and XLSX artifact
evidence records the adapter package version independently of that schema
version; focused domain registration and artifact-manifest tests pass.

The project service and shared application expose snapshot-bound sparse
worksheet pages with coordinates and semantic IDs. Shared project and
application APIs also expose exact-snapshot workbook and ordered worksheet
summaries with bounded used ranges. The project service exposes an exact-base
worksheet cell-edit operation that writes retained-package bytes into a durable
source candidate. Focused
coverage proves candidate reopen, formula preservation, stale-base rejection,
unchanged pre-apply bytes/current snapshot, targeted semantic revision change,
corrupt-package rejection, shared apply, and remote typed cell reads and edit
candidates. The bounded page controller, workbook summary API, and exact-cell
inspection contract are verified; agent workflows remain open. Completion items are
checked only where focused validation evidence exists.

Implement the first rich-artifact vertical slice: a format-independent spreadsheet domain plus an XLSX adapter that can safely inspect and edit a bounded workbook through normal Scriberig semantic change flow.

## 4. Architectural Prohibitions

Do not:

- treat XLSX ZIP/XML/package parts as the canonical spreadsheet model;
- make the external XLSX library's workbook structs public Scriberig semantic types;
- eagerly create semantic records for every possible empty Excel cell;
- treat cell display formatting as the same thing as cell value/formula semantics;
- treat cached formula results as authoritative recalculation;
- mutate `xl/worksheets/*.xml` directly from agent/UI code;
- expose insert-row/ref-rewrite operations until their formula/reference semantics are correct;
- silently drop macros, signatures, charts, relationships, unknown package parts, or other source-significant content;
- claim write fidelity when the chosen library cannot preserve encountered workbook structures.

## 5. Phase A — Choose Package Layout and XLSX Dependency

Repository decision (2026-10-26): spreadsheet semantics live in the independent
`scriberig-domain-spreadsheet` crate, while XLSX package logic lives in
`scriberig-domain-xlsx`. `rxls` 0.1.4 is pinned because it supports the
workspace Rust 1.85 MSRV, is MIT licensed, and exposes retained-package edits;
the adapter test proves an unknown OOXML ZIP member and another worksheet
survive a cell edit. Calamine is read-only, and the evaluated umya-spreadsheet
release requires a newer Rust version. The selected adapter does not recalculate
formulas and maps dates to numeric serials; styles, table metadata, local name
scopes, and edits beyond scalar/formula cell values are not yet represented.
Those semantics must remain read-only or explicitly unsupported until fidelity
is established. The library remains private to the adapter crate.

Create a format-independent spreadsheet domain.

Preferred layout:

```text
crates/domains/scriberig-domain-spreadsheet/
```

Place XLSX-specific code either in focused modules there initially or create:

```text
crates/domains/scriberig-domain-xlsx/
```

Use a separate XLSX crate if external dependencies/package logic would otherwise leak into the generic domain.

Before adding a dependency:

- [x] Evaluate at least the practical current Rust XLSX read/write options available to the repository.
- [x] Record why the selected library is suitable for the first vertical slice.
- [x] Record known preservation/write limitations.
- [x] Verify license compatibility.
- [x] Review `THIRD_PARTY_NOTICES.md`; the MIT dependency metadata and upstream license are sufficient, so no central notice text is required.
- [x] Keep the library behind adapter-private modules (the public adapter exports only Scriberig semantic types and byte-oriented operations).

Do not make library choice an architectural commitment.
