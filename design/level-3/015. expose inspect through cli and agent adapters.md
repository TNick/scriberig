# Expose Inspect Through CLI and Agent Adapters

## Objective

Expose the existing `inspect entity` application capability through two additional consumers:

- the command-line surface;
- the reusable agent-tool adapter.

Also wire the `scriberig` executable far enough to run the CLI inspect path locally.

Read first:

1. `design/level-1/011. runtime libraries protocol and product surfaces.md`
2. `design/level-2/011. application operations protocol and runtime boundaries.md`
3. `design/level-3/012. implement application operation primitives.md`
4. `design/level-3/014. implement server client inspect transport.md`

This task proves that CLI and agent consumers reuse application semantics instead of reaching into storage.

## CLI Command

Add an `inspect` command with input concepts equivalent to:

```text
scriberig inspect <entity-id> [--snapshot <snapshot-id>]
```

Use the CLI parsing framework already chosen by the repository. If none has been prescribed, choose one established Rust CLI parser and keep all parser-specific types inside `scriberig-cli`.

The command must:

1. parse the entity identifier using canonical ID parsing;
2. optionally parse an explicit snapshot;
3. invoke the shared application inspect operation;
4. render a concise human-readable result;
5. return a non-zero exit status on structured failure.

The CLI must not query graph/store crates directly.

---

## CLI Output

`output.rs` owns terminal presentation.

For a successful inspect include at least:

```text
entity
resolved revision
snapshot
semantic type/name or short description when available
```

Do not make the text format the public machine API.

Do not duplicate protocol DTOs solely to format terminal output.

For errors, map application categories to clear human-readable messages while retaining category information internally.

---

## Application Construction

The final executable must construct the local application stack through a composition function/builder already present or a minimal composition path added for this purpose.

`main.rs` should only:

```text
parse/receive CLI entry
construct dependencies
invoke scriberig-cli dispatcher
map final result to process exit
```

Do not place inspect semantics in `main.rs`.

If the actual storage backend is not yet ready, tests may use an injected fake application service. Do not commit a fake production database implementation merely to make the command run.

---

## Agent Tool Model

In `scriberig-agent-core`, define a generic tool contract that can describe and invoke application-backed tools without knowing a specific model provider.

The first concrete adapter is an inspect tool.

Its input must contain semantic fields equivalent to:

```text
entity
optional snapshot
detail level if supported
```

Its result must contain a compact structured summary with stable handles.

Do not return raw source files or unrestricted database data.

Do not add prompt templates tied to one model vendor.

---

## Agent Capability Filtering

`capability.rs` should expose whether the inspect tool is available under the current application capability context.

Do not rely on merely hiding the tool description for security.

The application operation must still enforce capability/authorization checks.

The agent layer only reflects the allowed surface.

---

## Progressive Disclosure

The inspect tool should default to a compact result.

It should expose enough information for a model to choose a next semantic action:

- object type;
- short description if available;
- counts or relation summaries when already provided by the application layer;
- stable handles for follow-up inspection.

Do not serialize the entire underlying object graph by default.

Do not invent summaries in the agent adapter if the shared semantic/derived layer already provides them.

---

## Tests

### CLI tests

Test command dispatch against an injected deterministic application fixture:

- known entity succeeds;
- explicit snapshot is preserved;
- missing entity returns failure without panic;
- output includes stable entity/revision/snapshot handles;
- CLI code never requires direct store access.

Avoid snapshot-testing incidental whitespace as the primary semantic assertion.

### Agent adapter tests

Verify:

- tool input maps to the same application inspect request;
- snapshot identity is preserved;
- result exposes stable handles;
- denied capability produces a structured failure;
- the tool does not access storage directly.

---

## Do Not Do

- Do not implement an LLM/provider client.
- Do not implement the full agent runtime loop.
- Do not add TUI widgets.
- Do not add server-specific code to the CLI.
- Do not call SQLite, graph internals, or domain parsers from CLI/agent adapter code.
- Do not create a second inspect implementation.
- Do not make CLI output a wire protocol.
