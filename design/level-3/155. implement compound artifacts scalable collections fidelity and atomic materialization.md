## 4. Architectural Prohibitions

Do not:

- create a second project catalog;
- create a second canonical blob/file database disconnected from the universal store/projection evidence model;
- equate an artifact with exactly one filesystem path;
- use absolute machine paths as semantic identity;
- make parser-library object IDs canonical Scriberig identities;
- make fidelity a UI-only flag;
- silently drop unknown source-significant package members;
- report successful multi-member materialization after only some required members were written;
- bypass candidate/migration/validation/promotion for artifact edits;
- add unrestricted ZIP/XML/SQLite mutation as the model-facing normal editing API;
- eagerly serialize huge spreadsheet/GIS collections merely to satisfy `inspect` or `list`.
