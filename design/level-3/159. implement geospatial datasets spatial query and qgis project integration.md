# Implement Geospatial Datasets, Spatial Query, and QGIS Project Integration

## Status

Planned.

All completion items remain unchecked until implemented and verified.

## 1. Goal

Implement geospatial dataset semantics, bounded spatial/attribute query, editable vector-layer operations, and a distinct QGIS project domain that references those datasets rather than absorbing them.

Minimum scenario:

```text
onboard QGIS project + parcels.gpkg
inspect QGIS project
resolve referenced parcels layer
find parcel_id=124
inspect feature
change area attribute or geometry semantically
create candidate
validate
review/apply
materialize dataset
reopen dataset
refresh QGIS project view/reference without rewriting unrelated project configuration
```

This task depends on task 154. It may use optional system/native geospatial libraries, but universal/public semantic contracts must remain provider-neutral.

## 4. Architectural Prohibitions

Do not:

- make QGIS project XML the canonical GIS dataset model;
- copy every feature from referenced datasets into the QGIS project entity;
- make GDAL/QGIS/native library types public protocol/domain types;
- make provider feature IDs equal Scriberig `EntityId`;
- use screen/map pixel coordinates as canonical geometry;
- serialize an entire large layer into one inspect/list response;
- mutate GeoPackage SQLite tables directly from agent/UI code as the normal semantic write path;
- treat Shapefile component files as unrelated independent artifacts when the adapter understands them as one dataset;
- require a remote network service for acceptance tests;
- bypass candidate/validation/materialization because a geospatial library has an update API.

## 10. Phase F — Add Spatial and Attribute Query Extensions

Implement geospatial query forms using shared query extension mechanics.

Minimum queries:

```text
attribute equality/predicate
bbox intersection
geometry intersection or within (if provider supports robustly)
nearest with explicit max results/distance policy
layer extent
```

Requirements:

- [ ] Every query is snapshot-bound.
- [ ] Results are paged/bounded.
- [ ] Results return semantic Feature handles plus requested summaries.
- [ ] Query execution may use derived/provider indexes without making those indexes canonical identity.
- [ ] CRS of query geometry is explicit; transform/reject mismatched CRS deterministically.
- [ ] No hidden use of UI map CRS as semantic query CRS.
- [ ] Query provenance/diagnostics identify transformation/provider where relevant.

Focused tests:

- [ ] find parcel_id=124 by attribute;
- [ ] bbox returns known bounded feature set;
- [ ] wrong/unknown CRS returns structured error or explicit transform path;
- [ ] page size prevents full-layer serialization.
