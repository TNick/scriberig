## 5. Remove the Double-Rendering Bridge

The current path that uses upstream components internally and then strips/reconstructs their output through Ratatui must be removed from the normal product path.

Forbidden final pattern:

```text
rpi-tui component.render()
  -> strip ANSI / flatten lines
  -> Ratatui Text/Paragraph/Block
```

Required final pattern:

```text
ScribeRig semantic component
  + upstream components
  -> upstream TUI child/overlay composition
  -> upstream render/runtime
```

Static baseline audit (2026-10-20):
`crates/scriberig-tui/src/render_conversation.rs::conversation_text` calls
`scriberig_tui_kit::render_markdown`; that wrapper sanitizes the row text,

parser is already upstream-owned. The remaining duplicate is the flattening
bridge into the active Ratatui shell. Do not remove the wrapper in isolation:
it is currently the sanitization boundary, and its consumer still requires
Ratatui text. Replace this entire path when the semantic conversation
component is composed directly into the upstream TUI runtime. No acceptance
item below is satisfied by this inventory alone.

Application keybinding registration (2026-10-21): the controlled `pi-rust`
fork now exposes registration and enumeration on upstream `Keybindings`.
ScribeRig registers its product actions in the upstream manager under stable
`scriberig.*` IDs. The composer, global quit handler, help overlay, and footer
read configured keys from that same manager; user remapping can therefore
change the active controls and their displayed hints together. The API change
is on a separate fork branch and is not yet included in the ScribeRig pin. No
