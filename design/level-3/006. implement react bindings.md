# Implement React Bindings

## Objective

Implement `@scriberig/react` as a thin React integration over `@scriberig/client`, `@scriberig/model`, and `@scriberig/editor-core`.

The package must expose providers and hooks that subscribe React components to reusable model/controller state without moving semantic logic into hooks.

Read before editing:

1. `design/level-1/012. web platform and integrated editor.md`
2. `design/level-2/001. web workspace packages and integrated editor.md`
3. `design/level-3/004. implement client semantic model and incremental events.md`
4. `design/level-3/005. implement headless editor core primitives.md`

Prerequisite: model and editor-core packages compile and provide framework-independent subscription interfaces.

## Provider

Create a public React provider that supplies the reusable runtime objects needed by hooks.

The provider should accept already-created objects rather than constructing hidden global singletons.

Expected dependencies include equivalents of:

```text
ScriberigClient
WorkspaceModel
SelectionController
CommandRegistry/ExtensionRegistry as required
```

The provider must support tests with fake objects.

Do not couple provider creation to one server URL or authentication mechanism.

---

## Subscription Strategy

Hooks must subscribe to reusable model/controller state using React-compatible external-store subscription patterns.

Prefer `useSyncExternalStore` or an equivalent correct React mechanism for framework-external stores.

Do not duplicate model state into per-component React state merely to trigger renders.

Do not introduce Redux or another React state framework.

---

## Object Hook

`use-object.ts` should expose the state needed to inspect a semantic object/reference.

It should distinguish where possible:

```text
not requested/loading
loaded
not found/error
stale relative to current snapshot
historical exact state
```

Loading must go through `WorkspaceModel`/client APIs.

Do not silently replace an exact historical revision with a current revision.

---

## Children Hook

`use-children.ts` should bind relation/collection loading to React.

Support:

- initial page load;
- loading state;
- error state;
- loaded children;
- child counts when known;
- load-more/cursor behavior;
- snapshot-aware cache reuse.

Do not recursively load descendants.

---

## Snapshot Hook

`use-snapshot.ts` should expose at least:

- current canonical snapshot known by the model;
- viewed snapshot when supplied by context/controller;
- whether the view is current, historical, candidate, or stale.

Do not reduce snapshot awareness to a boolean if the model exposes richer state.

---

## Operation Hook

`use-operation.ts` observes one long-running operation by `OperationId`.

Expose lifecycle, progress, result references, error information, and cancellation capability when available.

Do not tie an operation to the lifecycle of the initiating component.

Unmounting a view must not implicitly cancel a server operation.

---

## Session Hook

`use-session.ts` exposes loaded session/branch semantic summaries and loading operations.

It must not reinterpret sessions as only chat message arrays.

Preserve branch IDs, descriptions, outcomes, decisions, tasks, and migration/result references exposed by protocol/model.

---

## Selection Hook

`use-selection.ts` binds the shared `SelectionController` to React.

Expose:

```text
selection
setSelection
clearSelection
```

plus any small helper required to update relation/projection context.

All editor views must be able to share the same controller instance.

---

## Commands Hook

`use-commands.ts` returns command descriptors applicable to the current or supplied selection/capability context.

It must use editor-core command discovery.

Do not hard-code command lists in the hook.

Execution should invoke the operation descriptor/client path defined by editor-core.

---

## Knowledge Tree Hook

Wrap the headless knowledge tree controller for React consumption.

Expose rows/nodes and actions such as:

```text
expand
collapse
select
loadMore
refresh
```

Do not implement tree markup in this package.

---

## Migration Review Hook

Bind the headless migration review controller to React.

Expose selected change, affected objects, validation/stale/conflict state, and public apply/reject actions.

Do not perform direct state mutation outside controller/client APIs.

---

## Tests

Use React Testing Library or hook test utilities compatible with the workspace.

Required cases:

1. provider can use fake client/model/controller objects;
2. one model subscription updates multiple consumers consistently;
3. selection changed by one consumer is observed by another;
4. historical snapshot state remains exact after current snapshot advances;
5. operation hook survives initiating component removal when observed elsewhere;
6. commands update when capabilities or selection change;
7. no hook requires MUI context.

## Do Not Do

- Do not add MUI.
- Do not create visual components.
- Do not hard-code app routes.
- Do not create a global singleton client/model.
- Do not duplicate cache logic from `@scriberig/model`.
- Do not duplicate selection/tree/command state machines from `@scriberig/editor-core`.
- Do not treat sessions as only message arrays.
- Do not cancel server operations automatically on component unmount.
