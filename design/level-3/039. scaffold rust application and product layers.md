# Scaffold Rust Application and Product Layers

## Objective

Extend the Rust workspace created by `001. initialize rust foundation workspace.md` with the application, transport, agent, native UI, CLI, and final executable crates prescribed by `design/level-2/001. workspace and package layout.md`.

This task creates dependency boundaries only. Do not implement application operations, wire payloads, HTTP endpoints, agent tools, TUI screens, or CLI commands beyond the minimum required for the workspace to compile.

Read before editing:

1. `design/level-1/001. vision and principles.md`
2. `design/level-2/001. workspace and package layout.md`
3. `design/level-3/001. initialize rust foundation workspace.md`

The important architectural rules are:

- product surfaces consume shared application capabilities;
- the server is an adapter, not the owner of semantics;
- agents are consumers of the same application capabilities;
- foundation crates must never depend on these higher layers;
- the final executable contains composition, not business logic.

## Source File Content

Every library `src/lib.rs` should contain crate-level documentation only.

Document the role accurately:

- `scriberig-app`: shared application-operation boundary used by all surfaces;
- `scriberig-protocol`: serializable external transport contract boundary;
- `scriberig-client`: reusable Rust client boundary for a remote server;
- `scriberig-agent-core`: reusable agent-facing abstractions over application/session capabilities;
- `scriberig-agent-runtime`: integrated agent execution/orchestration boundary;
- `scriberig-server`: remote adapter over `scriberig-app` plus `scriberig-protocol`;
- `scriberig-tui`: terminal UI adapter over application capabilities;
- `scriberig-cli`: command parsing/dispatch boundary for the product executable.

Do not create speculative public functions, DTOs, command enums, HTTP server setup, model provider abstractions, or terminal components.

---

## Product `main.rs`

`apps/scriberig/src/main.rs` must remain minimal.

It may contain an empty `main` function and a short comment saying product composition will be added by later designs.

Do not invent CLI flags or runtime modes in this task.

The `scriberig` package should depend on `scriberig-cli` so the intended composition edge exists in the manifest even if no runtime invocation is implemented yet.

- Do not create actual agent tools.

- Do not invent CLI syntax.

- Do not edit Level 1 or Level 2 design documents.
