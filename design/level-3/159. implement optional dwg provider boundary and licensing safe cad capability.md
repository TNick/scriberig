# Implement Optional DWG Provider Boundary and Licensing-Safe CAD Capability

## Status

In Progress. The CAD domain now defines an optional provider contract with
separate read/write/validation capabilities, source-byte preservation input,
staged output, provider-neutral errors, and an explicit unavailable status.
A fake read-only provider verifies the capability boundary. Provider opaque
preservation claims now map through the project adapter into shared artifact
fidelity, with writing restricted unless validation is advertised. `.dwg` files
are retained as exact-evidence read-only artifacts and report that no provider
is configured through artifact inspection. No real DWG provider is selected or
shipped; provider selection remains a host composition decision.

Provider status now distinguishes normal absence from a configured provider that
failed initialization. The failure status carries only a format and closed
provider-neutral error category, so the shared CAD contract cannot expose
provider-controlled diagnostics or license paths.

The shared application now accepts a host-injected immutable provider registry.
It validates safe provider identifiers and versions, rejects duplicate format
ownership atomically, and represents initialization failure separately from
absence. Deployment requirements and native feature declarations use closed
provider-neutral enums rather than provider-supplied strings, and descriptor
collections are bounded before retention. The remote runtime capability
response reports server-side format availability, safe provider id/version,
read/write/validation flags, and opaque-preservation state. No client-side
native provider installation is required. The protocol keeps this field
optional when decoding older responses.

The product server composition now accepts that registry through
`ServerProviderCatalog` and installs it on the server-owned application
service. Host-side project routes obtain the configured `ProjectService` from
the application boundary, while remote surfaces receive only provider-neutral
capability DTOs. Normal CLI startup supplies an empty registry because no
licensed provider is selected. A host embedding the server can inject an
initialized provider through `ServerProviderCatalog`; stock product startup
does not discover or activate provider plugins. Project re-import reconciles a changed provider
identity/version by exact typed CAD semantics and preserves the matched project
entity IDs despite changed native handles. If exact matches are missing or
ambiguous, import fails closed; removing the provider while prior provider-derived
semantics exist also fails closed. Project import rejects a provider
whose returned identity/version differs from its registered descriptor, or whose
returned semantic drawing exceeds its advertised read features.

## 1. Goal

Add native DWG capability without coupling the reusable CAD semantic domain to one mandatory proprietary, copyleft-incompatible, native, or platform-specific implementation.

This task must establish a provider boundary that can support:

```text
DWG inspect/read
optional DWG semantic import
optional DWG write/materialization
provider-specific validation
explicit fidelity/capability diagnostics
```

The CAD schema from task 158 remains canonical. A DWG provider maps to that schema; it does not create a second CAD model.

This task depends on tasks 155 and 160.

## 4. Architectural Prohibitions

Do not:

- change `scriberig-domain-cad` semantic identity/types to match a provider's native object model;
- make DWG support mandatory for using CAD/DXF support;
- add a provider dependency with incompatible licensing to the reusable platform without explicit licensing approval reflected in repository metadata/design;
- expose native provider pointers/handles through protocol or persistent semantic records;
- store provider credentials/license keys as semantic project/session content;
- silently downgrade a DWG write to DXF conversion unless the user explicitly requests/export policy permits it;
- report write capability when provider only supports reading;
- bypass Scriberig candidate/change/materialization semantics because a vendor SDK has its own save API.

## 6. Phase B — Choose Integration Strategy

Pick one of these implementation forms based on licensing/deployment evidence:

```text
optional in-process library
optional dynamically loaded/native bridge
out-of-process adapter service/tool
user-supplied provider plugin
```

### Current strategy decision

The reusable CAD crate ships only the provider-neutral `CadExternalProvider`
contract. A future product host may inject an implementation at composition
time; no native loader, SDK, binary, or license dependency is part of the
workspace. This keeps DXF and the semantic platform usable without a DWG
provider. The official LibreDWG project states that it is GPL-3.0-or-later
([GNU project licensing](https://www.gnu.org/software/libredwg/)); the ODA
Drawings SDK is a paid membership product with distribution limits at its
Commercial tier and a separate Sustaining tier for unlimited distribution and
web/SaaS use ([ODA pricing and terms](https://www.opendesign.com/pricing)).
Neither is bundled or selected: adding LibreDWG requires a product-level GPL
compatibility decision, while adopting ODA requires an explicit commercial
license, distribution model, and deployment owner. The provider contract stays
host-injected until those decisions are made. Product selection therefore uses
the host's explicit `ServerProviderCatalog.cad_provider_registry` composition
boundary: a host may register an already initialized, licensed provider, while
the stock CLI passes an empty registry. There is no dynamic loading, implicit
activation, or end-user plugin discovery while no provider distribution has
been approved. Initialization failures remain represented as a closed status
and do not fall back to another provider.

Requirements:

- [x] Document why chosen strategy preserves the repository's platform/product licensing boundary (no provider binary/dependency ships; GPL-3.0-or-later and ODA commercial terms are recorded above).
- [x] Make native/system dependency optional at build/runtime when it cannot be assumed on all systems (the workspace has no native DWG dependency; hosts inject implementations).
- [x] Provide a deterministic fake provider for CI (`cargo test -p scriberig-domain-cad`).
- [x] Shared provider rendering rejects output without advertised reopen validation or proven preservation of non-empty baselines, and returns bytes only after provider validation (`cargo test -p scriberig-domain-cad` verifies the capability guards and propagated reopen-validation failure).
- [x] Do not require proprietary SDK/license in ordinary workspace tests (`cargo test -p scriberig-domain-cad` uses fake/no-provider implementations).
- [x] Update license/notice/package docs for any shipped dependency/bridge code (no DWG dependency or bridge is shipped, so no third-party notice is needed).

If no acceptable real DWG provider can be shipped under current project constraints:

- [x] Implement the provider boundary and fake/conformance provider only (`cargo test -p scriberig-domain-cad`).
- [x] Expose real DWG as `provider required/unavailable` rather than weakening licensing rules (`cargo test -p scriberig-project --test artifact_manifest`).
- [x] Leave real-provider-specific checkboxes unchecked and document the blocker: LibreDWG distribution needs an explicit GPL compatibility decision, and ODA requires an explicit paid license/deployment owner before product integration.

## 8. Phase D — Optional DWG Write/Materialization

Only implement if chosen provider supplies safe write capability.

Requirements:

- [ ] DWG output is generated from exact candidate CAD semantic state plus required preserved provider evidence.
- [ ] Provider save/export occurs in candidate staging, not directly against live project file.
- [ ] Shared expected-baseline verification runs before replacement.
- [ ] Provider-reported unsupported semantic operation blocks output rather than dropping data.
- [ ] Resulting DWG is reopened/validated through provider before live replacement.
- [ ] Materialization records provider/version and exact new digest.
- [ ] Failure leaves canonical/project external state recoverable under task-157 materialization rules.

If write is unavailable:

- [x] Capability is read-only/provider-inspect (`cargo test -p scriberig-app --test cad_provider_registry application_reports_configured_provider_descriptor_and_fidelity` verifies read=true, write=false, and unproven opaque preservation for an injected DWG provider).
- [ ] Explicit DXF export may be offered as a separate operation, never as hidden DWG overwrite.

## 10. Phase F — Validation and Failure Modes

Add tests for:

- [x] provider unavailable (`cargo test -p scriberig-project --test artifact_manifest` retains source evidence and reports no configured provider);
- [x] provider initialization failure remains distinct from normal absence and is represented without provider-controlled diagnostic text (`cargo test -p scriberig-app --test cad_provider_registry application_reports_provider_initialization_failure_without_secret_text`; `cargo test -p scriberig-server --test transport provider_initialization_failure_survives_remote_capability_discovery`);
- [x] read-only provider reports read without write (`cargo test -p scriberig-domain-cad optional_provider_status_and_read_only_capability_are_explicit`; `cargo test -p scriberig-server --test transport configured_cad_provider_capability_survives_remote_round_trip`);
- [x] unsupported entity class is rejected when it is absent from advertised writer features (`cargo test -p scriberig-domain-cad`).
- [x] configured provider without read capability is not invoked and exact source evidence remains inspect-only (`cargo test -p scriberig-project --test artifact_manifest dwg_provider_without_read_capability_is_not_invoked`).
- [x] provider identity/version changes use exact semantic reconciliation, and unmatched provider results fail before replacing imported semantics (`cargo test -p scriberig-project --test artifact_manifest dwg_provider_switch` runs both matched and unmatched provider-switch regressions).
- [x] provider import identity and represented features must match the registered descriptor (`cargo test -p scriberig-project --test artifact_manifest dwg_import_identity_must_match_registered_provider`; `cargo test -p scriberig-domain-cad provider_import_cannot_exceed_advertised_read_features`).
- [x] stale external DWG baseline (`cargo test -p scriberig-project --test artifact_manifest stale_dwg_manifest_cannot_replace_imported_source_baseline` confirms an old reviewed manifest is rejected after the source changes, the active snapshot/drawing mapping remains intact, and the new exact source digest is visible from the persisted scan).
- [x] provider render/write failure before candidate bytes are returned (`cargo test -p scriberig-domain-cad provider_render_failure_returns_no_candidate_bytes` verifies the safe `RenderFailed` category and no candidate output).
- [x] provider reopen validation failure (`cargo test -p scriberig-domain-cad provider_render_reopens_candidate_and_propagates_validation_failure` verifies no output bytes are returned after validation rejects provider-rendered output);
- [x] optional provider absent while DXF tests continue to pass (`cargo test -p scriberig-app --test cad_provider_registry application_reports_provider_initialization_failure_without_secret_text`; `cargo test -p scriberig-domain-dxf`).

Every failure must be structured and must not corrupt canonical state or live external artifact.
