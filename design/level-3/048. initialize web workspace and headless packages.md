# Initialize Web Workspace and Headless Packages

## Objective

Create the TypeScript/web workspace and the reusable non-visual/headless packages prescribed by `design/level-2/001. workspace and package layout.md`.

This task creates package boundaries only. Do not implement server calls, state management behavior, React hooks, semantic tree controllers, protocol generation, or application screens.

Read before editing:

1. `design/level-1/001. vision and principles.md`
2. `design/level-2/001. workspace and package layout.md`

The important architectural rules are:

- the official editor must be buildable from public reusable packages;
- the TypeScript client must not depend on React or MUI;
- client-side model and editor behavior must remain usable independently of the integrated editor;
- transport types must reflect one wire contract shared with Rust rather than becoming a separate conceptual protocol;
- MUI must not appear in the packages created by this task.

---

Create:

```text
web/package.json
web/pnpm-workspace.yaml
web/tsconfig.base.json

web/packages/protocol/package.json
web/packages/protocol/src/index.ts
web/packages/client/package.json

```

Also extend the repository root `.gitignore` with web/Node generated artifacts as described below.

Do not create `components`, `components-mui`, `agent-ui`, or the integrated editor app in this task. They are created by Level 3 task 004.

---

## `web/package.json`

Create a private workspace-root package.

Requirements:

- mark it `private`;
- do not publish it;
- do not add an application framework;
- do not add MUI;
- do not add a bundler unless required by a later design;
- do not add repository-wide scripts that assume tools not yet selected.

The purpose of this file at this stage is to establish the package-manager root.

---

## `web/pnpm-workspace.yaml`

Configure pnpm to discover:

```text
packages/*
apps/*
```

The `apps/*` pattern is included now so the later editor app joins the same workspace without restructuring it.

---

## `web/tsconfig.base.json`

Create a strict reusable TypeScript base configuration suitable for library packages.

Requirements:

- enable strict type checking;
- use modern ECMAScript syntax;
- do not assume browser-only globals at the base level;
- do not configure React JSX globally for all packages;
- do not include package-specific source files from the root config.

Keep the configuration small. Package-specific build details may be added later when the build tooling is designed.

## Package Names and Roles

Use these names exactly:

```text
web/packages/protocol     -> @scriberig/protocol
web/packages/client       -> @scriberig/client
web/packages/model        -> @scriberig/model
web/packages/editor-core  -> @scriberig/editor-core
web/packages/react        -> @scriberig/react
```

All packages start at version `0.1.0`.

At this scaffold stage, package manifests may be private to prevent accidental publishing before packaging/release design exists. The architectural intention is still that these are reusable public packages later.

---

## Internal Dependency Direction

Represent these workspace dependencies in package manifests:

```text
@scriberig/protocol

@scriberig/client
└── @scriberig/protocol

@scriberig/model
├── @scriberig/protocol
└── @scriberig/client

@scriberig/editor-core
└── @scriberig/model

@scriberig/react
└── @scriberig/model
```

Use pnpm workspace references for internal packages.

Do not make `@scriberig/model` depend on React.

Do not make `@scriberig/editor-core` depend on MUI.

Do not make any package depend on the future integrated editor application.

---

## `src/index.ts` Content

Each `src/index.ts` should contain only package-level documentation comments and an empty module export such as:

```ts
export {};
```

Do not create speculative classes, hooks, DTOs, stores, controllers, query clients, event streams, or selection models yet.

The documentation should accurately state each intended role:

- `@scriberig/protocol`: TypeScript representation of the shared wire contract;
- `@scriberig/client`: reusable browser/Node server client boundary;
- `@scriberig/model`: UI-framework-independent client state/model boundary;
- `@scriberig/editor-core`: headless semantic editor/browser behavior boundary;
- `@scriberig/react`: React bindings over public model/client behavior, without styling assumptions.

Do not claim generated protocol support is implemented until the generation mechanism exists.

## Required Checks

If pnpm is available, run from `web/`:

```text

```

Verify that all five packages are discovered and their workspace dependency links resolve.

Do not introduce a compile/build command solely to satisfy this task if no TypeScript build toolchain has yet been selected. Validate JSON/YAML syntax and package discovery instead.

Also run the existing Rust workspace checks after changing `.gitignore` only to ensure no unrelated repository damage occurred:

```text

```

if the Rust workspace already exists.

- Do not create visual components.
