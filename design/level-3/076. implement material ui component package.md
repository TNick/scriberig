# Implement Material UI Component Package

## Objective

Implement `@scriberig/components-mui` as the opinionated Material UI interpretation of Scriberig's public web model and interaction primitives.

The package may make strong visual and composition choices, but it must not reimplement protocol access, caching, selection, command discovery, migration semantics, or event processing.

Read before editing:

1. `design/level-1/012. web platform and integrated editor.md`
2. `design/level-2/001. web workspace packages and integrated editor.md`
3. `design/level-3/005. implement headless editor core primitives.md`
4. `design/level-3/006. implement react bindings.md`
5. `design/level-3/007. implement neutral reusable components.md`

Prerequisite: public React bindings and neutral components compile.

## MUI Boundary

MUI is allowed only in this package and consuming applications.

Do not modify lower reusable packages to accept MUI-specific props, theme types, icons, or component instances.

Where a lower component already provides sufficient structure, wrap or compose it.

Where an MUI implementation needs different markup for quality, consume the same hooks/controllers directly rather than copying their state logic.

---

## Theme Contract

Provide a small optional Scriberig theme helper in `theme.ts`.

It may define component defaults and semantic tokens for concepts such as:

- current/historical/stale state;
- success/warning/error/conflict;
- selected semantic objects;
- agent/operation status.

Do not create a hard requirement that consumers use the provided theme.

Components must work within an existing host MUI theme.

---

## Tree and Inspector

`MuiObjectTree` must use MUI controls/layout while preserving lazy loading, semantic selection, pagination, and keyboard behavior from the reusable layers.

`MuiObjectInspector` should use application-ready sections/cards/tables where appropriate for identity, revision, description, properties, relations, and stale/historical state.

Do not query the client directly if a public hook/controller already exposes the required data.

---

## Relation, History, and Diff Views

Implement MUI versions of relation browsing, history navigation, and semantic diff display.

The semantic diff renderer must clearly distinguish:

- added;
- removed;
- changed;
- moved/structural changes when protocol supports them;
- conflicts/ambiguous states where relevant.

Do not compute semantic diffs in the UI package.

---

## Migration Preview

`MuiMigrationPreview` should provide a review-oriented composition suitable for accepting or rejecting a proposed migration.

Display:

- base/candidate snapshot context;
- affected objects;
- semantic changes;
- validation result;
- stale/conflict warnings;
- permitted apply/reject actions.

Mutating actions must use public command/client operations.

---

## Session and Agent Components

`MuiSessionTree` and `MuiBranchView` preserve the structured session model.

`MuiAgentPanel` should combine:

- active session/branch context;
- current semantic selection/scope;
- command input;
- durable operation progress;
- streamed agent output if available;
- resulting branch/migration/validation/snapshot references.

The panel must not construct line-number-oriented prompts from source text when semantic selection is available.

Do not make the agent panel a private transport client; use public agent operations.

---

## Command Palette

Implement `MuiCommandPalette` over the universal command descriptors from editor-core/React bindings.

It should:

- show commands applicable to current semantic selection and capabilities;
- support keyboard invocation/search;
- distinguish mutating commands where useful;
- invoke the same command descriptor used by other controls.

Do not maintain a separate hard-coded list of application commands.

---

## Projection Host

`MuiProjectionHost` provides MUI framing around registered domain projection handlers.

It may add toolbars, status indicators, snapshot/stale banners, and command access, but domain rendering/editing remains supplied through public extension handlers.

Do not hard-code one source editor implementation in this task.

---

## Accessibility

Use MUI accessibility support but preserve explicit semantic labels and keyboard operation.

Required:

- keyboard-accessible tree and command palette;
- visible focus;
- labeled icon-only controls;
- status messages that are not communicated by color alone;
- stale/conflict states exposed textually and semantically.

---

## Tests

Required tests:

1. components render under a normal external MUI theme;
2. components also render under the optional Scriberig theme helper;
3. selection propagates through `MuiObjectTree` to shared selection state;
4. command palette uses editor-core command discovery;
5. migration preview invokes public apply operation rather than local mutation;
6. agent panel sends structured semantic scope with commands;
7. no import reaches into another package's private `src` path;
8. stale/conflict state is visible without relying only on color.

## Do Not Do

- Do not add semantic caches.
- Do not reimplement event handling.
- Do not hard-code server endpoint URLs.
- Do not import database/server internals.
- Do not modify lower packages to require MUI.
- Do not make agent commands textual/file-line based when semantic selection exists.
- Do not implement the reference app's routing/layout here.
