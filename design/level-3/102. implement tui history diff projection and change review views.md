# Implement TUI History, Diff, Projection, and Change Review Views

**Status: [x] Complete**

## Objective

Extend semantic browsing beyond a single current entity by adding primary views for history, semantic diff, rendered projections, validation, conflicts, and reviewable changes using only shared application operations.

Read first:

1. `design/level-1/005. changes migrations branches and merge.md`;
2. `design/level-1/006. projections and bidirectional editing.md`;
3. `design/level-1/013. trust validation capabilities and provenance.md`;
4. `design/level-2/021. terminal ui runtime and state architecture.md`;
5. `design/level-2/022. terminal ui views interaction and conformance.md`;
6. tasks 099 through 101.

This task is dependency-gated: implement only views whose public `scriberig-app` operations exist. If an operation is still missing, add it to the correct application/domain layer in its owning task before exposing it here. Do not bypass that layer from the TUI.

---

## Target Views

Add focused modules equivalent to:

```text
src/view/history.rs
src/view/diff.rs
src/view/projection.rs
src/view/changes.rs
```

Each view consumes a small TUI view model built from public application results.

---

## History View

Use the shared history operation for the current semantic selection.

The view must show stable revision/snapshot references and useful descriptions/timestamps/provenance summaries when provided by the application result.

Activating a history row creates an exact historical selection. It must not silently resolve back to the current entity revision.

History loading must be bounded/paginated if the application contract supports or requires it.

---

## Diff View

Use the shared semantic diff operation.

The view header must keep both sides explicit:

```text
left/base reference
right/target reference
```

Render structured change groups when returned by the application/domain layer. Text-oriented hunks may be displayed when they are part of a public diff/projection result, but the TUI must not compute semantic diff by comparing rendered strings.

Provide navigation among changed semantic objects using their stable references.

---

## Projection View

Render a projection through the shared projection/application operation.

Display, when available:

```text
projection identity
source semantic reference
style identity
rendered content
synchronization state
last known base/reference needed for reconciliation
```

The first projection view may be read-only.

Do not open or write projection files directly from the widget. External-edit/reconcile behavior remains an application/projection operation.

Sanitize terminal control characters in rendered projection text before drawing it.

---

## Change and Validation Review

Add a review view for migration/change/validation results.

The view must make visible:

```text
base snapshot or branch
proposed target/change identity
affected semantic objects
conflicts
validation state/diagnostics
trust/provenance summary where relevant
state-changing action that will be invoked
```

Canonical application is never performed merely by opening the view.

A confirm action invokes the existing shared application command with the explicit reviewed base/context.

If the application reports a stale base or conflict after confirmation, retain the proposal/result and show the failure. Do not silently rebase and retry.

---

## Confirmation Overlay

Implement the modal confirmation/review behavior needed by state-changing operations.

The overlay must show at least:

```text
action label
semantic target
base snapshot/branch when relevant
short risk/change summary
explicit confirm and cancel keys
```

Confirmation only expresses user intent. Capability checks and semantic validation remain authoritative in `scriberig-app`.

---

## View Switching

Add local palette actions for switching among supported primary views without losing semantic selection:

```text
overview
history
diff
projection
changes/validation
```

When a view requires additional context, such as a diff comparison target, collect it explicitly through input/selection state.

Switching views must not push duplicate semantic history entries unless the semantic location itself changes.

---

## Loading, Refresh, and Freshness

Each view uses explicit request/generation state.

Application events or successful canonical changes may mark related cached views stale. Refresh through shared operations rather than mutating cached rows in ways that pretend to be authoritative.

After a successful canonical change, navigate or refresh according to the result's returned semantic references/snapshot rather than assuming the target ID remained current.

---

## Tests

Add deterministic tests for at least:

- exact historical revision activation;
- diff header preserves both explicit sides;
- diff rows link to stable semantic references;
- projection control characters are rendered harmlessly;
- view switching preserves selection;
- confirmation does not itself perform a mutation;
- confirmed command carries reviewed base context;
- stale-base/conflict result is surfaced without automatic retry;
- validation failure remains inspectable;
- late results cannot overwrite a newer comparison/projection request.

Use fake/public application adapters rather than storage internals.

---

## Capability Matrix

Advance only capabilities genuinely implemented by this slice. Where conformance coverage exists, move to `verified`; otherwise use `implemented`.

Do not mark generic mutation support verified because one confirmation overlay exists.

---

## Out of Scope

Do not add:

- a terminal source-code editor;
- TUI-specific merge semantics;
- direct projection file writes;
- direct migration application outside `scriberig-app`;
- session/agent UI;
- remote mode.
