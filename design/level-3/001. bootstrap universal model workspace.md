# Bootstrap Universal Model Workspace

## Objective

Create the initial Rust workspace and empty compiling crate structure prescribed by `design/level-2/001. universal knowledge model rust libraries.md`.

This task is only workspace/bootstrap work. Do not implement the semantic model yet.

The result must compile and provide the exact module/file structure expected by later implementation agents.

---

## Source Documents

Read before editing:

1. `design/level-1/002. universal knowledge model.md`
2. `design/level-2/001. universal knowledge model rust libraries.md`

If these documents conflict, the Level 1 semantic invariants win and the conflict must be reported rather than guessed around.

## Root Workspace Manifest

Create a Cargo workspace containing exactly these initial members:

```text
crates/sr-core
crates/sr-schema
crates/sr-graph
```

Use a current stable Rust edition consistently for all three crates.

Prefer workspace-level package metadata where it removes duplication.

Do not add application binaries.

---

## Crate Dependencies

Use this dependency direction:

```text
sr-core
   ↑
   ├── sr-schema
   └── sr-graph
          ↑
          └── sr-schema
```

Concretely:

- `sr-core` has no internal Scriberig dependencies;
- `sr-schema` has a path dependency on `sr-core`;
- `sr-graph` has path dependencies on `sr-core` and `sr-schema`.

Do not add database, async-runtime, HTTP, parser, model-provider, or UI dependencies.

For the bootstrap task, avoid third-party dependencies unless compilation requires one. Later tasks may add narrowly justified dependencies.

---

## Module Files

Every module file should contain only:

- a short module-level documentation comment describing its future responsibility;
- enough placeholder declarations, if any, for the crate to compile cleanly.

Do not prematurely design public structures in this task. Later Level 3 tasks own those decisions.

`lib.rs` in each crate must declare the prescribed modules and should re-export nothing unless required to keep compilation simple.

The integration test file may contain a temporary smoke test such as `assert!(true)` with a comment that the universal model scenarios will be implemented by the final conformance task.

---

## Required Documentation Boundaries

Module documentation should state these constraints where relevant:

- `sr-core` contains universal identifiers, values, provenance, and model-local errors only;
- `sr-schema` describes domain schemas without containing concrete domain schemas;
- `sr-graph` contains storage-independent semantic graph records and views;
- none of the three crates owns persistence;
- none of the three crates knows that agents exist.

Keep comments short. Do not duplicate the Level 1 document inside source files.

---

## Validation

Run:

```text
cargo check --workspace
cargo test --workspace
```

If formatting tools are available, also run:

```text
cargo fmt --check
```

The workspace must compile with no missing modules.

---

## Do Not

Do not:

- choose a database backend;
- implement hashing or content-addressing;
- implement snapshot storage;
- add SQLite;
- define `Function`, `Paragraph`, `PdfPage`, `SessionBranch`, or other domain entities;
- add agent tools;
- add server endpoints;
- add source rendering;
- add migrations;
- add query-language behavior;
- create code outside the prescribed workspace unless required to fix a repository-level build configuration problem.

---
