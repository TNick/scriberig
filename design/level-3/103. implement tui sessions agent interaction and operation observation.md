# Implement TUI Sessions, Agent Interaction, and Operation Observation

**Status: [x] Complete**

## Objective

Implement the TUI as an interactive observer/controller of the shared branch-aware agent runtime: session-tree navigation, nested branch inspection, agent input and continuation, operation progress, transient streaming, cancellation, result navigation, and promotion/review.

Read first:

1. `design/level-1/009. agent interaction and sessions.md`;
2. `design/level-1/016. model driven agent execution and branch isolation.md`;
3. `design/level-2/011. application operations protocol and runtime boundaries.md`;
4. `design/level-2/021. terminal ui runtime and state architecture.md`;
5. `design/level-2/022. terminal ui views interaction and conformance.md`;
6. `design/level-2/024. agent operations protocol and cross surface product contract.md`;
7. `design/level-3/111. expose agent execution through application protocol server and clients.md`;
8. tasks 099 through 102 and 107 through 111 as applicable.

This task must use public session/application/client agent boundaries. It must not call model providers directly from `scriberig-tui` and must not recreate branch orchestration in presentation code.

## TUI Service Port

Extend the existing TUI service/effect boundary with concepts equivalent to:

```text
StartAgent(AgentStartRequest)
ContinueAgent(AgentContinueRequest)
LoadSession(SessionRef)
LoadBranch(BranchRef)
LoadBranchChildren(BranchRef, page)
LoadBranchActivity(BranchRef, page)
LoadBranchResult(BranchResultRef)
ObserveOperation(OperationId)
CancelOperation(OperationId)
```

Use existing universal inspect/list/follow operations where they already cover session objects cleanly.

The same TUI state machine must work with:

```text
embedded local adapter -> scriberig-app
remote adapter -> scriberig-client
```

No view/reducer behavior may depend on whether the model provider is local, remote, OpenAI-compatible, or fake.

## Session/Branch View Model

Represent the session as a real branch tree rather than a flat chat list.

A branch row/view model should contain bounded public information equivalent to:

```text
BranchRef
parent/child relationship
short title/purpose
status
compact outcome
child count
activity count
BranchResultRef when terminal
important result/touched handles
running-operation marker when active
```

Do not load every branch activity item just to draw the tree.

Branch expansion triggers an explicit branch-child/activity load.

---

## Completed Branch Collapse

Completed child branches must default to a compact representation in the parent flow.

A compact branch card/row shows at least:

```text
purpose
terminal status
outcome summary
result handles
expand affordance
```

Expanding the branch reveals retained activity:

```text
human inputs
model outputs
structured tool calls/results
nested child branches
validation/result references
```

Collapsing a branch changes only presentation state. It must not delete or summarize-overwrite canonical session history.

This UI behavior should make the architectural context-collapse rule visible to users: parent work consumes the result, while full child provenance remains inspectable.

---

## Active Branches

Active/running branches should be distinguishable from completed/abandoned branches using text/symbols as well as color.

The tree may show bounded phase metadata such as:

```text
thinking/model request
tool operation
waiting for child branch
validation
completing
```

These phases come from shared operation/events and are not durable branch lifecycle states invented by the TUI.

---

## Agent Composer

Provide an explicit input composer for starting or continuing agent work.

Requirements:

- ordinary typed text;
- pasted text remains data rather than command-key replay;
- multiline content where supported;
- visible target session and branch;
- visible semantic scope/selection when present;
- start-vs-continue behavior is explicit;
- no provider credentials/configuration fields;
- submission invokes `StartAgent` or `ContinueAgent` through the TUI service port;
- returned `OperationId`, `SessionRef`, and `RootBranchRef` become observable state immediately.

The TUI never assembles provider messages/tool schemas itself.

---

## Universal Selection Binding

When the user starts agent work from a selected semantic object, construct the public agent request from the existing TUI semantic selection.

Preserve stable data equivalent to:

```text
entity reference
optional exact revision
snapshot/branch context
projection location when public selection supports it
```

Do not reduce the scope to an informal filename/line-range prompt before it reaches the shared agent operation.

The composer should show a concise human-readable scope summary and provide a way to inspect the exact selection.

## Start and Continue Workflows

### Start

```text
user enters prompt
-> StartAgent effect
-> start response returns operation/session/root branch
-> navigate/select root branch as appropriate
-> observe operation/events
```

### Continue

When a branch/session is selected and continuation is supported:

```text
user enters follow-up
-> ContinueAgent effect
-> application decides direct continuation vs continuation child branch
-> returned operation/branch handles drive UI
```

Do not locally reopen a completed branch if shared branch policy says continuation creates a child/sibling branch.

## Operations View

Use the shared operation lifecycle:

```text
queued
running
completed
failed
cancelled
```

Display when available:

```text
OperationId
operation kind
session/root branch
current phase summary
active branch count/handles
progress counters
final AgentResult/BranchResult reference
structured failure
```

Completed result references must be activatable through ordinary semantic navigation.

Do not create an agent-only lifecycle that disagrees with the standard operation view.

## Event Integration

Feed agent/session events through the existing event -> action -> reducer path.

Handle concepts equivalent to:

```text
BranchCreated
BranchStateChanged
ModelInvocationStarted
ModelTextDelta
ToolInvocationStarted
ToolInvocationCompleted
ChildBranchStarted
ChildBranchCompleted
BranchResultProduced
AgentOutputCommitted
AgentOperationCompleted/Failed/Cancelled
```

Events carry operation-local sequence/cursor metadata where available.

Out-of-order or duplicate transport events must not regress already newer local presentation state.

For durable objects, prefer event reference -> authoritative load/refresh rather than treating the whole event payload as canonical object state.

---

## Streaming Presentation

Maintain transient streaming buffers separately from durable session objects.

A stream buffer is keyed by operation/branch/invocation correlation and may contain partial model text.

Required rules:

- deltas may render immediately;
- deltas are labeled/inferred as in-progress;
- `AgentOutputCommitted` or an authoritative branch reload replaces the transient buffer with durable output;
- leaving a view does not cancel execution;
- returning to the view resolves durable state rather than trusting retained fragments;
- reconnect without stream replay still recovers from operation/session queries.

Do not insert every text delta into the canonical session view model as if it were a committed message.

---

## Branch Activity View

Opening a branch loads bounded/paginated activity using public handles.

Render semantically distinct rows for concepts such as:

```text
HumanInput
ModelOutput / AgentOutput
ToolInvocation
ToolResult
child branch reference/result
Decision/Observation/Summary
Migration/Validation result reference
```

Tool rows should default to compact summaries and expose exact result handles for deeper inspection.

Do not dump unbounded raw provider JSON or raw tool payloads into the terminal.

---

## Nested Branch Navigation

A branch activity row pointing to a child branch/result must be activatable.

Navigation should support:

```text
parent -> child branch
child -> nested child
child result -> semantic artifact
back -> previous semantic location
```

Branch depth must not be hard-coded into rendering logic. Use indentation/breadcrumb/compact tree strategies that remain usable at depth.

At narrow widths, preserve semantic hierarchy even if metadata columns collapse.

---

## Cancellation

Expose cancellation only when shared operation/capability state permits it.

Closing an overlay, navigating away, or pressing Esc to leave the current view is not equivalent to operation cancellation.

Cancellation flow:

```text
user requests cancel
-> optional confirmation if appropriate
-> CancelOperation effect
-> show cancellation requested/pending
-> wait for shared terminal operation state
```

Do not optimistically mark the operation cancelled.

Ctrl-C behavior must compose with the TUI's global quit/cancel interaction policy and terminal-restoration guarantees.

---

## Failures

Structured agent failures should remain inspectable after transient notifications disappear.

Render concise categories such as:

```text
provider configuration/auth/transport/rate limit
capability denied
tool failure
child branch failure
validation failure
budget exceeded
cancelled
internal failure
```

Link to operation/branch result handles when safe.

Never show provider secret values, Authorization headers, or complete sensitive compiled context in ordinary diagnostics.

---

## Trust, Candidate Changes, and Promotion

When an agent branch produces candidate changes or durable knowledge eligible for promotion:

- show result handles in branch/operation views;
- invoke existing shared review/validation/change surfaces;
- require the normal confirmation/capability path;
- handle stale-base/conflict results explicitly.

The session view cannot directly mutate canonical state because a model completed successfully.

---

## Concurrent Navigation

Users must be able to inspect unrelated project/session knowledge while an operation continues.

The runtime state should retain active operation handles globally enough that:

- status/progress remains visible;
- the user can return to active branches;
- completion can notify without stealing focus;
- completion does not automatically navigate away from the user's current work unless explicitly configured.

Rendering/navigation remains responsive while model/network/tool work is pending.

---

## Local and Remote Mode

The TUI presentation/reducer must be shared between:

```text
srig tui --db <PATH>       # local embedded service
srig tui --connect <URL>   # remote public client, once transport task exists
```

Provider configuration exists where the agent runtime is hosted:

- local composition for embedded mode;
- server composition for remote mode.

The TUI never needs provider credentials in either mode.

## Tests

Use deterministic fake TUI services/agent operations. No external model provider or public network is allowed.

Cover at least:

- nested branch tree renders with stable references;
- completed branches default to compact result rows/cards;
- expanding a child loads activity on demand;
- collapsing does not alter canonical/session service data;
- composer start request includes current semantic selection;
- continue request targets the selected session/branch;
- paste remains input data;
- start response immediately tracks stable operation/session/root branch handles;
- model deltas update only transient stream state;
- durable output replaces transient buffer;
- leaving the view does not cancel work;
- cancellation waits for shared operation terminal state;
- out-of-order/duplicate events do not regress state;
- child result handle activates semantic navigation;
- reconnect/reload can rebuild branch tree without stream history;
- promotion routes through shared change review;
- no provider configuration/credential type appears in TUI state/service API.

Use Ratatui test backend for representative branch tree/activity frames at wide, medium, and narrow sizes.

## Out of Scope

Do not add:

- model-provider credentials to TUI configuration;
- provider-specific APIs or DTOs in `scriberig-tui`;
- terminal-only branch/session persistence;
- a TUI-owned model/tool loop;
- automatic promotion of model output;
- direct canonical mutation from stream fragments;
- a requirement to load complete child histories to render the parent branch tree.
