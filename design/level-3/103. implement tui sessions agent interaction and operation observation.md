# Implement TUI Sessions, Agent Interaction, and Operation Observation

**Status: [x] Complete**

## Objective

Add the interactive workflows that make the TUI useful for long-running Scriberig work: session-tree navigation, agent input, operation progress/result inspection, cancellation, and event-driven refresh.

Read first:

1. `design/level-1/009. agent interaction and sessions.md`;
2. `design/level-1/011. runtime libraries protocol and product surfaces.md`;
3. `design/level-2/011. application operations protocol and runtime boundaries.md`;
4. `design/level-2/021. terminal ui runtime and state architecture.md`;
5. `design/level-2/022. terminal ui views interaction and conformance.md`;
6. tasks 099 through 102.

This task must use public session/application/agent operation boundaries. It must not call model providers directly from `scriberig-tui`.

---

## Dependency Gate

Before implementing a workflow, confirm that the shared layers expose the required public operation and result model.

Expected concepts include:

```text
open/list/navigate session
session branches and turns
submit agent command
OperationId
operation lifecycle/status
operation cancellation
event observation/subscription
result references
```

If a concept is missing, implement it in its semantic owner under the applicable Level 2/3 design before adding the TUI surface. Do not invent a TUI-only session store or operation lifecycle.

---

## Session View

Add a focused session view capable of rendering a semantic session tree.

Rows should represent public session objects/handles such as:

```text
session
branch
turn
summary
tool invocation
tool result
promoted durable knowledge reference
```

Use nesting to reflect the session branch model. A transient/exploratory branch must be visibly distinguishable from canonical project state.

Activating a durable result/reference should navigate to the corresponding semantic object through normal TUI navigation.

---

## Agent Composer

Implement an explicit input composer for agent commands.

Requirements:

- accepts ordinary typed text;
- accepts pasted text as data, not command-key replay;
- supports multiline content when the selected agent command API accepts it;
- clearly identifies the target session/branch;
- does not echo secrets or hidden configuration into status messages;
- submission invokes the shared agent/session application operation;
- the returned `OperationId` becomes the object observed by the UI.

The TUI does not call provider SDKs, assemble model tool schemas, or commit model output directly to canonical state.

---

## Operations View

Add `src/view/operations.rs` or equivalent.

Render shared operation states equivalent to:

```text
queued
running
completed
failed
cancelled
```

Include when available:

```text
OperationId
operation kind
input snapshot/branch
requester/provenance summary
progress
result reference
structured failure
```

Completed result references must be activatable through ordinary semantic navigation.

---

## Cancellation

Expose cancellation only when the application/client says the operation is cancellable and the caller has capability.

A local Esc key closing a view is not the same as cancelling application work.

Cancellation must produce the shared cancellation request and observe the shared terminal lifecycle result. Do not optimistically mark an operation cancelled before the application reports it.

---

## Event Integration

Attach application event observation to the runtime's event/action path.

Events may mark view models stale or trigger bounded refreshes, but the event payload is not automatically authoritative canonical state.

For an event concerning an object currently visible, prefer:

```text
event received
-> mark affected model stale/refresh-needed
-> request authoritative state through shared operation
-> apply result only if request generation still matches
```

Coalesce repeated refresh requests for the same visible object where practical so a burst of events does not create an unbounded queue.

---

## Streaming Presentation

If the agent/application layer exposes streaming text or progress, render it as observation of the running operation.

Streaming fragments must not be treated as committed project knowledge merely because they appear in the terminal.

The user must be able to change focus or inspect other semantic objects while an operation continues, unless the shared operation explicitly requires interactive exclusivity.

If the user returns to the session view, resolve the durable session state rather than relying solely on retained stream fragments.

---

## Status Region

Use the global status area for compact operation information such as:

```text
running operation count
focused operation short id
progress summary
connection/event state
last safe diagnostic
```

Important failures must also be reachable through a durable operation/session view and not disappear only as transient status text.

---

## Trust and Promotion

When a session/agent result offers promotion into durable/canonical knowledge, expose it as a normal semantic state-changing action.

Use the change-review/confirmation machinery from task 102. The session widget must not bypass migrations, validation, conflict handling, or capability checks.

---

## Tests

Use deterministic fake application/session/agent services. No external model provider or network is allowed in TUI tests.

Cover at least:

- session branch nesting and activation;
- pasted composer input remains data;
- submitting returns/tracks stable `OperationId`;
- progress events update operation presentation;
- closing an operation view does not cancel work;
- cancellation waits for application lifecycle state;
- repeated events are bounded/coalesced where designed;
- completed result reference activates semantic navigation;
- streamed text is not represented as canonical committed state;
- promotion action routes through change review rather than direct mutation.

---

## Capability Matrix

Advance TUI coverage for operation/session/agent capabilities only when the shared API and TUI path are real.

Candidates include:

```text
operation_status
operation_cancel
event_subscription
```

Use `verified` only when conformance tests prove semantics across the relevant surfaces.

---

## Out of Scope

Do not add:

- model-provider credentials to TUI configuration;
- provider-specific APIs in `scriberig-tui`;
- terminal-only session persistence;
- automatic promotion of model output;
- direct canonical mutations from stream fragments.
