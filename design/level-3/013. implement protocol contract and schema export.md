# Implement Protocol Contract and Schema Export

## Objective

Implement the first authoritative remote protocol contract in `scriberig-protocol` and provide a reproducible machine-readable schema export path.

Read first:

1. `design/level-1/011. runtime libraries protocol and product surfaces.md`
2. `design/level-2/011. application operations protocol and runtime boundaries.md`
3. `design/level-3/012. implement application operation primitives.md`

The protocol must preserve semantic meaning while remaining independent of server routing and persistence internals.

---

## Files to Create or Replace

Create:

```text
crates/scriberig-protocol/src/lib.rs
crates/scriberig-protocol/src/version.rs
crates/scriberig-protocol/src/refs.rs
crates/scriberig-protocol/src/request.rs
crates/scriberig-protocol/src/response.rs
crates/scriberig-protocol/src/error.rs
crates/scriberig-protocol/src/operation.rs
crates/scriberig-protocol/src/event.rs
crates/scriberig-protocol/src/capability.rs
crates/scriberig-protocol/src/bin/export-schema.rs
```

Update `crates/scriberig-protocol/Cargo.toml` with only dependencies required for serialization/schema export and shared low-level ID types.

Use the repository's normal serialization stack if one has already been established. Do not introduce a second serialization framework.

---

## Authoritative Contract Rule

The Rust types in `scriberig-protocol` are the authoritative first-version wire contract.

The schema exporter must derive its output from those types.

Do not hand-write a separate JSON schema that can drift from the Rust contract.

Do not create TypeScript protocol types manually in this task.

---

## `version.rs`

Define a protocol major version independent of crate version.

The initial value is:

```text
1
```

Provide typed structures for version exchange/capability negotiation rather than using an unstructured string.

The design must allow future minor/additive metadata without redefining the major version concept.

---

## `refs.rs`

Define transport-safe wrappers or DTOs for stable references required by the initial protocol:

```text
EntityReference
RevisionReference
SnapshotReference
OperationReference
```

Use canonical low-level identifiers from `scriberig-core` when they are already serializable and suitable for public use.

If the internal representation should not be exposed directly, wrap it while preserving round-trip identity.

Never expose database row IDs or backend-specific coordinates.

---

## `request.rs`

Implement the first requests needed for vertical runtime validation:

```text
InspectEntityRequest
RuntimeCapabilitiesRequest
OperationStatusRequest
CancelOperationRequest
SubscribeRequest or equivalent subscription specification
```

`InspectEntityRequest` must support explicit snapshot-aware resolution.

Requests must contain semantic inputs, not endpoint paths or HTTP concepts.

---

## `response.rs`

Implement typed responses for the requests above.

`InspectEntityResponse` must identify:

- entity;
- exact resolved revision;
- exact snapshot;
- semantic type/summary data needed by generic clients.

Keep response values presentation-neutral.

No ANSI formatting, UI labels, or prompt text belongs here.

---

## `error.rs`

Define a serializable protocol error form that preserves the structured application error category.

It may contain:

```text
code/category
human-readable message
structured details when safe
correlation/request ID where useful
```

Do not require clients to parse the message string.

Do not encode HTTP status as the primary semantic category.

---

## `operation.rs`

Mirror the public semantic operation lifecycle without importing private `scriberig-app` implementation structures directly.

Represent at least:

```text
operation reference
kind
Queued
Running
Completed
Failed
Cancelled
progress
final result reference/summary
```

Add explicit conversion code between app and protocol forms in the appropriate adapter layer rather than making the protocol crate depend on `scriberig-app`.

---

## `event.rs`

Define serializable event forms for the application event categories supported by the current runtime.

Events must carry stable references and concise metadata.

Do not serialize a full canonical entity as the event payload merely for convenience.

---

## `capability.rs`

Define runtime capability discovery response types.

They must be suitable for generic clients and simpler agents to answer:

- what operation families are available;
- what protocol version is active;
- what optional runtime features are present.

Do not merge authorization rules or `capabilities.toml` planning state into this protocol model.

---

## Schema Export

`src/bin/export-schema.rs` must generate a deterministic machine-readable schema bundle from the public protocol types.

Preferred output location when invoked by tooling:

```text
target/scriberig-protocol-schema/
```

Do not commit generated files in this task unless another repository policy explicitly requires committed generated artifacts.

The exporter must fail clearly if schema generation fails.

The same source revision should produce semantically identical schema output.

---

## Serialization Tests

Add tests covering:

- every request and response round trip;
- every structured error category round trip;
- operation states round trip;
- representative events round trip;
- protocol version data round trip;
- stable ID/reference round trips;
- schema exporter executes successfully.

Tests must not depend on a running server.

---

## Compatibility Discipline

For protocol-facing enums expected to evolve additively, choose serialization behavior deliberately.

Do not silently use Rust enum representation details as an accidental wire format.

Document the chosen tagged representation in crate-level docs or tests.

Avoid renaming serialized fields casually after this task lands.

---

## Do Not Do

- Do not add server routes.
- Do not add an HTTP framework.
- Do not add TypeScript convenience clients.
- Do not expose internal database rows.
- Do not make `scriberig-protocol` depend on `scriberig-app` or `scriberig-server`.
- Do not encode product presentation strings as semantic contract fields.
