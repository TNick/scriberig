# Bootstrap Ratatui Terminal Runtime and Shell

**Status: [ ] Pending**

## Objective

Replace the documentation-only `scriberig-tui` crate with the smallest real terminal runtime that can safely enter/leave terminal mode and render a responsive Scriberig shell without performing semantic work inside rendering.

This task implements the terminal foundation from:

1. `design/level-1/015. terminal user interface principles.md`;
2. `design/level-2/021. terminal ui runtime and state architecture.md`;
3. `design/level-2/022. terminal ui views interaction and conformance.md`.

Do not wire `srig tui` to a database in this task. Product composition is a later task.

---

## Required Dependencies

Add Ratatui and a compatible Crossterm dependency arrangement to `crates/scriberig-tui/Cargo.toml`.

Keep one compatible Crossterm line in the resolved dependency graph. Prefer workspace dependency declarations if the repository already centralizes versions by the time this task is implemented.

Do not add SQLite, server, HTTP, agent-provider, or domain-parser dependencies to the TUI crate.

---

## Target Modules

Create an initial structure equivalent to:

```text
crates/scriberig-tui/src/
├── lib.rs
├── runtime.rs
├── terminal.rs
├── event.rs
├── state.rs
├── layout.rs
└── render.rs
```

Additional focused modules are allowed if needed to remain under the repository source-file size limit.

Every Rust file/function/type must follow the repository documentation/comment conventions from Level 2 document 020.

---

## Terminal Guard

Implement a terminal lifecycle wrapper that owns setup and restoration.

It must support the equivalents of:

```text
raw mode on/off
alternate screen enter/leave
cursor hide/show where appropriate
bracketed paste enable/disable when supported
optional mouse capture kept disabled by default initially
```

Restoration must be attempted for normal exit and event-loop error paths.

Install a panic-restoration strategy that composes with the previous panic hook rather than swallowing it.

Keep the guard concerned only with terminal state. It must not own application/store cleanup.

---

## Event Types

Define TUI-level terminal events independent of view semantics, at minimum:

```text
Key(...)
Paste(String)
Resize { width, height }
Tick
Shutdown
```

Translate Crossterm events at the terminal/event boundary. Do not expose raw Crossterm event types throughout view state.

Ignore unsupported terminal events safely.

---

## Initial State

Create a minimal `TuiState` containing only presentation/runtime state needed by this task, such as:

```text
should_quit
terminal_size
focus
shell_message
```

Do not add fake entity/snapshot data to make the shell look populated.

The shell may state that no semantic service is attached in this task's test harness.

---

## Responsive Shell

Implement the layout classes defined by Level 2:

```text
>= 120 columns -> explorer + primary + inspector
80..119       -> explorer + primary
< 80          -> primary only
```

Render a context bar, body region, status region, and key-hint row.

At very small sizes render a clear small-terminal message while keeping quit/help key handling possible.

Resize must not panic.

---

## Rendering Rules

`render` functions take state and a Ratatui frame/rectangle only.

They must not:

- open files;
- call application services;
- wait on channels;
- query the database;
- mutate semantic state.

Keep frame rendering deterministic from state.

---

## Runtime Loop

Implement a minimal runtime loop that:

1. initializes the terminal guard;
2. draws the initial state;
3. waits for terminal events without busy-spinning;
4. updates local state;
5. redraws only when state/size requires it;
6. exits on the local quit action;
7. restores terminal state.

This task may keep event/action handling simple. The full action/reducer/effect architecture is task 100.

---

## Test Support

Use Ratatui's `TestBackend` or equivalent in-memory backend to test the shell without touching the developer's real terminal.

Add focused tests for at least:

```text
140x40 wide layout
100x30 medium layout
72x24 narrow layout
very small terminal guard rendering
resize state change
quit event
```

Terminal lifecycle tests should abstract terminal commands so tests do not leave CI runners in raw mode.

---

## Out of Scope

Do not implement in this task:

- application queries;
- semantic selection;
- command palette;
- history/diff/projection views;
- sessions or agents;
- SQLite composition;
- remote mode;
- capability matrix changes claiming semantic TUI support.
