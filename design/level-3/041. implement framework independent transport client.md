# Implement Framework-Independent Transport Client

## Objective

Implement `@scriberig/client` as the framework-independent client for shared Scriberig application operations and events.

The package must be usable from browser code, Node-based tooling, tests, and non-React applications.

Read before editing:

1. `design/level-1/010. universal query and operation model.md`
2. `design/level-1/011. runtime libraries protocol and product surfaces.md`
3. `design/level-1/012. web platform and integrated editor.md`
4. `design/level-2/001. web workspace packages and integrated editor.md`
5. `design/level-3/002. implement protocol package boundary.md`

Prerequisite: `@scriberig/protocol` compiles and exposes the authoritative public protocol shapes.

Do not guess server endpoint paths if the server protocol has not defined them. In that case implement the transport abstraction and client operation mapping first, and keep HTTP endpoint mapping isolated behind the transport implementation.

## Transport Abstraction

Define a small transport contract that supports:

- typed request/response operations;
- cancellation through `AbortSignal` or equivalent;
- transport-level failures separate from semantic protocol errors;
- event subscription or a companion event transport;
- authentication metadata injection without coupling the client to one auth system.

The transport contract must not expose React concepts.

Tests must be able to provide an in-memory fake transport.

---

## Public Client

Implement one public client class or factory that maps shared application capabilities to typed methods.

Required conceptual method groups:

```text
inspect
list/follow
query/search
diff/history
branch/change/migration
validate
render/projection
session/branch operations
agent operations
operation inspection/cancellation
event subscription
capability discovery
```

Use protocol types for inputs and outputs.

Do not duplicate protocol interfaces inside the client package.

Do not return raw `Response` objects from public semantic methods.

---

## HTTP Transport

`http-transport.ts` owns HTTP-specific behavior only.

It should handle concerns such as:

- base URL;
- request headers;
- authentication header callback/provider;
- JSON encoding/decoding;
- abort/cancellation;
- structured protocol error decoding;
- network/HTTP error normalization.

Endpoint paths and HTTP verbs must follow the canonical server protocol if present.

If that contract is not yet implemented, centralize provisional endpoint mapping in one private table or function and mark it as blocked on the server protocol design. Do not scatter guessed URLs throughout client methods.

---

## Event Stream

Implement an event subscription abstraction in `event-stream.ts`.

Requirements:

- expose typed protocol events;
- expose connected/disconnected/resuming state when available;
- allow consumers to unsubscribe/close;
- support cancellation;
- isolate WebSocket/SSE details from semantic consumers;
- preserve resume/cursor metadata if the server protocol provides it.

Do not build a React hook here.

Do not automatically mutate semantic caches; that belongs to `@scriberig/model`.

---

## Error Model

Separate at least:

```text
TransportError
ProtocolError
Structured server/application error
```

Protocol/application errors from `@scriberig/protocol` should remain inspectable by callers.

Do not turn stale-base, conflict, capability-denied, or validation errors into generic `Error("request failed")` values.

---

## Fake Transport Tests

The tests must verify that client methods:

- send the expected operation and payload through the transport abstraction;
- return typed protocol results;
- propagate structured application errors;
- pass cancellation signals;
- do not require DOM or React globals for non-browser tests.

Also test event subscription wiring with a fake event source.

---

## Public Exports

Export from `src/index.ts`:

- the public client;
- transport interfaces needed by alternate implementations;
- HTTP transport;
- event subscription interfaces;
- client/transport error classes that callers must distinguish.

Do not export private endpoint tables or internal codecs unless they are intentionally part of the compatibility contract.

## Do Not Do

- Do not add React.
- Do not add MUI.
- Do not add entity/revision caches.
- Do not add selection state.
- Do not add route or component logic.
- Do not implement optimistic editing.
- Do not bypass public protocol types with `unknown`/`any` to make calls compile.
- Do not access SQLite or filesystem state.
- Do not hide semantic errors behind transport-only errors.
