# Implement Reusable Rich-Artifact Web and RPI-TUI Semantic Surfaces

## Status

Planned.

All completion items remain unchecked until implemented and verified.

## 1. Goal

Expose the spreadsheet, document, CAD, geospatial, QGIS, and generic artifact capabilities implemented by tasks 154–159 through reusable web packages and the current RPI-based TUI without duplicating domain semantics in product code.

The surfaces must support:

```text
semantic navigation
bounded rich projections
semantic selection
shared semantic operations
candidate review
fidelity/diagnostic inspection
history/diff/materialization status
```

The web editor should provide the richer interactive grid/document/canvas/map experiences. The TUI must provide useful semantic navigation and operation/review workflows, but is not required to recreate Excel, Word, AutoCAD, or QGIS in a terminal.

This task depends on tasks 154–159 to the extent each domain is implemented. It is constrained by the active RPI adoption work, especially Level-2 032.

## 4. Architectural Prohibitions

Do not:

- parse XLSX/DOCX/DXF/QGIS/GeoPackage directly in TypeScript/React or TUI code to recover semantics already available through application APIs;
- implement a web-only or TUI-only mutation path;
- make grid row, DOM node, canvas object ID, map feature layer index, or terminal row canonical identity;
- duplicate domain operation semantics in reducers/components;
- put huge layer/workbook contents into one client model snapshot;
- make personal UI projection style rewrite shared materialized artifacts;
- equate RPI-TUI theme/style with Scriberig document/source/domain projection style;
- require the TUI to support direct graphical manipulation before the semantic workflow is usable;
- bypass shared candidate/change review because a rich editor can locally modify a visual model.

## 5. Phase A — Extend Shared Client/Model Selection for Rich Anchors

Build on existing semantic selection contracts.

Requirements:

- [ ] Selection always carries semantic handle plus exact snapshot/revision context where applicable.
- [ ] Spreadsheet selection can represent cell/range anchors without using UI grid row objects as identity.
- [ ] Document selection can identify paragraph/table cell semantics independent of DOM nodes.
- [ ] CAD selection can carry entity plus projection-space bounds/anchor as presentation metadata.
- [ ] Map selection can carry feature plus CRS-aware geometry/bounds anchor as presentation metadata.
- [ ] QGIS layer selection can resolve to QGIS LayerReference and linked GeoLayer separately.
- [ ] Switching projection/view does not silently change the selected semantic entity.
- [ ] Remote and embedded clients normalize equivalent selections the same way.

Focused tests:

- [ ] serialize/normalize spreadsheet cell selection;
- [ ] serialize/normalize feature selection with CRS anchor;
- [ ] view-local anchor changes do not mutate semantic selection identity;
- [ ] stale snapshot selection refresh preserves EntityId when still present or clears meaningfully when absent.

## 7. Phase C — Spreadsheet Web Grid and TUI Range View

### Web

Implement a reusable spreadsheet grid/controller.

Requirements:

- [ ] Grid requests bounded ranges/pages from shared client APIs.
- [ ] Scrolling/viewport changes fetch only required ranges with bounded prefetch.
- [ ] Cell selection resolves to semantic Cell handle.
- [ ] Formula/value inspector shows semantic value and formula distinctly.
- [ ] Edit commit invokes `spreadsheet.set_cell_value` or `spreadsheet.set_formula` shared operation.
- [ ] Dirty local editor state is distinguishable from candidate/canonical state.
- [ ] Candidate result opens existing shared review workflow.
- [ ] Read-only/fidelity state disables edit affordances with diagnostic reason.
- [ ] Changing personal display settings does not materialize the XLSX.

### TUI

Provide a bounded range/table projection.

- [ ] User can choose worksheet and range/page.
- [ ] Cells are rendered in bounded table/text form using RPI-TUI primitives.
- [ ] Selected cell semantic details/formula are inspectable.
- [ ] User can invoke shared set-value/set-formula operation through command/prompt flow.
- [ ] No custom full spreadsheet widget is required if bounded range interaction is usable.

Tests:

- [ ] web scrolling does not request entire worksheet;
- [ ] cell edit creates candidate, not immediate materialization;
- [ ] TUI and web target same semantic cell in fixture.

Requirements:

- [ ] View requests features by spatial window/bbox with explicit CRS and paging.

- [ ] Layer list distinguishes QGIS LayerReference from resolved GeoLayer.
- [ ] Feature click resolves semantic Feature handle.

## 11. Phase G — Candidate Review for Rich Domains

Extend existing review components rather than creating per-domain approval systems.

Requirements:

- [ ] Spreadsheet diff shows target cell/range value/formula changes semantically.
- [ ] Document diff shows paragraph/table cell changes semantically.
- [ ] CAD diff shows entity property/geometry/layer changes semantically.
- [ ] Geo diff shows feature attribute/geometry changes semantically.
- [ ] QGIS diff shows layer/order/project configuration changes semantically.
- [ ] Raw/projected artifact bytes may be inspectable as secondary evidence but are not the only diff.
- [ ] Validation status/evidence is visible.
- [ ] Apply uses existing expected-base promotion path.
- [ ] Materialization failure/recovery status is visible after promotion attempt.

TUI and web may render these differently but must consume the same semantic review model.

## 13. Phase I — Reusable Package Boundaries

Preserve web dependency direction:

```text
protocol -> client -> model -> editor/react -> reusable components -> web app
```

- [ ] Protocol package contains transport DTOs only.
- [ ] Client package owns transport normalization.
- [ ] Model/editor packages own semantic selection/query/edit orchestration.
- [ ] Reusable components accept models/controllers rather than direct server internals.
- [ ] Integrated web app composes reusable packages only.
- [ ] No public package depends on `web/apps/`.
- [ ] TUI consumes shared app/client semantics rather than TypeScript/web packages.
