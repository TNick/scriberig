# Implement Workspace and Identity Types

> Reconciled with the current workspace on 2026-10-11. The repository's
> reusable foundation is `scriberig-core` rather than the obsolete `sr-core`
> name from the original bootstrap specification. Existing callers construct
> deterministic IDs with `new(bytes)`; fresh entity allocation is exposed as
> `EntityId::fresh()` so the established byte constructor remains compatible.

## Mission

Create the initial Rust workspace and the `scriberig-core` identity types
required by the identity/revision/snapshot design.

This task is intentionally narrow. Do not implement revisions, snapshot tries, stores, migrations, SQLite, agents, or domain models.

## Required Result

Create a Cargo workspace containing `crates/scriberig-core`.

Implement these public opaque types:

```text
EntityId
RevisionId
SnapshotId
TypeId
EncodingVersion
```

### `EntityId`

Requirements:

- [x] Stored as exactly 16 bytes.
- [x] `EntityId::fresh()` creates a fresh non-content-derived identity.
- [x] Provide `from_bytes([u8; 16])` and `as_bytes()`.
- [x] Implement `Clone`, `Copy`, `Eq`, `Ord`, and `Hash`.
- [x] Implement deterministic `Display` and `FromStr`.
- [x] Display form starts with `ent_`.
- [x] Parsing rejects another identity prefix.
- [x] Do not expose the UUID crate's type in the public API.

Use UUID v4 generation internally unless the currently selected dependency makes another random 128-bit implementation materially simpler.

### `RevisionId`

Requirements:

- [x] Stored as exactly 32 bytes.
- [x] Opaque newtype distinct from `SnapshotId`.
- [x] Provide byte construction/access needed by later hashing code.
- [x] Display form starts with `rev_`.
- [x] `FromStr` round-trips exact bytes.
- [x] Parsing rejects `snp_` and `ent_` values.

Do not compute revision hashes yet.

### `SnapshotId`

Requirements:

- [x] Stored as exactly 32 bytes.
- [x] Opaque newtype distinct from `RevisionId`.
- [x] Provide byte construction/access needed by later hashing code.
- [x] Display form starts with `snp_`.
- [x] `FromStr` round-trips exact bytes.
- [x] Parsing rejects `rev_` and `ent_` values.

Do not implement snapshot hashing yet.

### `TypeId`

Requirements:

- [x] Owns a UTF-8 string.
- [x] Constructor rejects an empty identifier.
- [x] `Display` returns the exact identifier.
- [x] Examples such as `markdown.paragraph` and `rust.function` are valid.
- [x] Does not hard-code a registry of known type names.

### `EncodingVersion`

Requirements:

- [x] Small integer newtype.
- [x] Define public constant/version constructor for version 1.
- [x] Do not silently accept arithmetic overflow or use it as a mutable global.

## Error Handling

Use one small typed parse/validation error for invalid textual identities and invalid `TypeId` construction. Do not use stringly typed errors in the public API if a compact enum is sufficient.
