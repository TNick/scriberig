# Implement Workspace and Identity Types

## Mission

Create the initial Rust workspace and the `sr-core` identity types required by the identity/revision/snapshot design.

This task is intentionally narrow. Do not implement revisions, snapshot tries, stores, migrations, SQLite, agents, or domain models.

## Read Before Editing

Read these documents completely:

```text
design/level-1/003. identity revisions and snapshots.md
design/level-2/001. identity revision snapshot implementation.md
```

The Level 1 invariants are authoritative. The Level 2 document defines the concrete file layout for this implementation.

## Files You Own

Create or modify only these files unless compilation requires a trivial adjacent change:

```text
Cargo.toml
crates/sr-core/Cargo.toml
crates/sr-core/src/lib.rs
crates/sr-core/src/ids.rs
```

Do not create `sr-store` in this task.

## Required Result

Create a Cargo workspace containing `crates/sr-core`.

Implement these public opaque types:

```text
EntityId
RevisionId
SnapshotId
TypeId
EncodingVersion
```

### `EntityId`

Requirements:

- [ ] Stored as exactly 16 bytes.
- [ ] `EntityId::new()` creates a fresh non-content-derived identity.
- [ ] Provide `from_bytes([u8; 16])` and `as_bytes()`.
- [ ] Implement `Clone`, `Copy`, `Eq`, `Ord`, and `Hash`.
- [ ] Implement deterministic `Display` and `FromStr`.
- [ ] Display form starts with `ent_`.
- [ ] Parsing rejects another identity prefix.
- [ ] Do not expose the UUID crate's type in the public API.

Use UUID v4 generation internally unless the currently selected dependency makes another random 128-bit implementation materially simpler.

### `RevisionId`

Requirements:

- [ ] Stored as exactly 32 bytes.
- [ ] Opaque newtype distinct from `SnapshotId`.
- [ ] Provide byte construction/access needed by later hashing code.
- [ ] Display form starts with `rev_`.
- [ ] `FromStr` round-trips exact bytes.
- [ ] Parsing rejects `snp_` and `ent_` values.

Do not compute revision hashes yet.

### `SnapshotId`

Requirements:

- [ ] Stored as exactly 32 bytes.
- [ ] Opaque newtype distinct from `RevisionId`.
- [ ] Provide byte construction/access needed by later hashing code.
- [ ] Display form starts with `snp_`.
- [ ] `FromStr` round-trips exact bytes.
- [ ] Parsing rejects `rev_` and `ent_` values.

Do not implement snapshot hashing yet.

### `TypeId`

Requirements:

- [ ] Owns a UTF-8 string.
- [ ] Constructor rejects an empty identifier.
- [ ] `Display` returns the exact identifier.
- [ ] Examples such as `markdown.paragraph` and `rust.function` must be valid.
- [ ] Do not hard-code a registry of known type names.

### `EncodingVersion`

Requirements:

- [ ] Small integer newtype.
- [ ] Define public constant/version constructor for version 1.
- [ ] Do not silently accept arithmetic overflow or use it as a mutable global.

## Error Handling

Use one small typed parse/validation error for invalid textual identities and invalid `TypeId` construction. Do not use stringly typed errors in the public API if a compact enum is sufficient.

## Dependencies

Keep dependencies minimal.

Allowed reasons for dependencies in this task:

- random UUID generation;
- optional serde support if it does not complicate the crate.

Do not add:

- async runtime;
- SQLite;
- web framework;
- parser framework;
- agent SDK.

## Tests

Unit tests may live inside `ids.rs` for this task.

Implement at least these tests:

- [ ] two `EntityId::new()` calls produce different values;
- [ ] `EntityId` display/parse round-trip;
- [ ] `RevisionId` display/parse round-trip;
- [ ] `SnapshotId` display/parse round-trip;
- [ ] wrong prefixes are rejected;
- [ ] `RevisionId` and `SnapshotId` cannot be accidentally parsed as each other;
- [ ] empty `TypeId` is rejected;
- [ ] valid `TypeId` round-trips through display.

## Commands to Run

Before finishing, run:

```text
cargo fmt --check
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
```

Fix all failures and warnings introduced by this task.

## Do Not

- Do not make `EntityId` content-addressed.
- Do not alias `RevisionId` and `SnapshotId` to the same Rust type.
- Do not include parent or position information in any identity type.
- Do not create a global current snapshot.
- Do not add application, CLI, server, or agent code.
- Do not implement more of the Level 2 design than this task owns.

- [ ] Text identity prefixes are distinct and checked.
- [ ] Tests pass.
