## 5. Recursive Conversation Component

Preserve the distinctive conversation/session projection:

```text
recursive branch placement
stable branch/activity identity
historical reply anchors
nested ancestry rails/structure
compact BranchResult rows
expand/collapse by stable branch identity
plan/model/tool activity at structural location
streaming transient activity
```

Use upstream component/layout/scroll/text/theme machinery for presentation.

Acceptance:

- [ ] Conversation is an upstream `Component` or composition of upstream components.
- [ ] Navigation cursor, reply anchor, and plan coordinator remain distinct Scriberig identities.
- [ ] Historical continuation stays anchored by semantic identity after reorder/resize.
- [ ] Expand/collapse is presentation-only.
- [ ] Parent context never receives expanded child transcript merely because UI expanded it.
- [ ] Streaming rows use upstream rendering and do not become a second canonical transcript.

## 9. History and Diff Components

History is lineage; diff is semantic/domain diff data.

Do not derive semantic equality from terminal text.

Acceptance:

- [ ] Exact base/target revision/snapshot identity is preserved.
- [ ] Semantic changed objects/operations come from Scriberig shared results.
- [ ] Textual/projection diff fragments render through upstream safe text/Markdown/diff primitives where available.
- [ ] Navigating diff/history is read-only presentation state.

If upstream has a reusable diff component, use it. If not and a generic diff component would be broadly useful, contribute it upstream rather than building a general Scriberig diff widget.

## 16. Large Trees, Virtualization, and Responsiveness

Session and semantic trees may be large.

Use upstream viewport/scroll/virtualization primitives. If missing, contribute a generic upstream primitive.

Acceptance:

- [ ] Rendering is bounded to visible/needed rows.
- [ ] Deep recursive branches do not cause unbounded per-frame work.
- [ ] Resize preserves semantic selection/reply anchors.
- [ ] Unicode/wide/combining content behaves according to upstream width machinery.
- [ ] No local general-purpose virtualization engine is introduced.

## 17. Terminal Safety

All external/model/tool/source/document strings remain untrusted.

Use upstream safe rendering APIs and structured styles; never concatenate model-generated raw ANSI/OSC into terminal control output.

Acceptance:

- [ ] Hostile control-sequence corpus passes through conversation and auxiliary components.
- [ ] Projection/tool/error content cannot inject terminal controls through normal APIs.
- [ ] Clipboard/image behavior follows upstream product policy and Scriberig capability policy.
- [ ] No Scriberig component adds a `raw_ansi(external_string)` path.
