# Implement One-Shot Agent Command through Shared Runtime

**Status: [x] Complete**

## Objective

Replace the provisional one-shot provider behavior with a non-interactive product surface over the same branch-aware agent operation used by TUI, web, remote clients, and the integrated agent runtime.

Read first:

1. `design/level-1/016. model driven agent execution and branch isolation.md`;
2. `design/level-2/020. repository scaffold conventions and native command surface.md`;
3. `design/level-2/024. agent operations protocol and cross surface product contract.md`;
4. `design/level-3/111. expose agent execution through application protocol server and clients.md`;
5. `CLI_REFERENCE.md`.

The controlling rule is:

> `srig run` waits for a shared agent operation; it does not implement a private prompt-to-provider shortcut.

---

## User-Facing Command

Keep the stable top-level spelling:

```text
srig run <PROMPT>
```

The implementation may add options needed for real composition while preserving the positional prompt.

Recommended first option set:

```text
srig run <PROMPT>
  [--db <PATH>]
  [--provider <PROFILE>]
  [--model <MODEL>]
  [--base-url <URL>]
  [--api-key-env <NAME>]
  [--format <human|json>]
  [--no-stream]
  [--keep-session]
```

Do not add a raw `--api-key <SECRET>` flag. Secrets supplied on command lines are exposed through shell history and process listings.

If repository-wide configuration infrastructure already provides equivalent settings, use it instead of duplicating command-only configuration.

---

## Relationship to `srig agent`

The existing `srig agent <PROMPT>` command must not retain an independent orchestration engine.

For the first complete implementation choose one of these compatible behaviors:

1. make `agent` an alias/delegating command that starts the same shared operation; or
2. retain `agent` as the advanced/profile-selecting spelling while `run` uses the default agent profile.

In both cases:

```text
same AgentStartRequest semantics
same branch/session runtime
same provider boundary
same tool loop
same cancellation
same AgentResult
```

Document the selected behavior in `CLI_REFERENCE.md` in the same implementation change.

## Composition Flow

The one-shot path is:

```text
parse CLI
-> resolve database/runtime configuration
-> resolve model-provider profile and secret source
-> compose local application/session/agent runtime
-> build AgentStartRequest
-> start agent operation
-> receive OperationId + SessionRef + RootBranchRef
-> observe shared operation until terminal
-> resolve AgentResult/final output
-> print result and exit
```

The provider configuration belongs in the composition root/runtime configuration, not in `scriberig-app` protocol DTOs.

---

## Session and Branch Semantics

Every invocation creates or selects a real session and root execution branch.

The default one-shot behavior should create a fresh session/root branch unless an existing public configuration/request option explicitly asks to continue an existing session.

The command does not need to display the branch tree interactively, but the completed session/branch/result remains inspectable according to retention policy.

`--keep-session`, if implemented, requests durable retention beyond project defaults. Omitting it does not permit bypassing session creation; it only affects post-completion retention.

---

## Prompt and Semantic Scope

The required positional prompt becomes the human input/current instruction in the root branch.

If future one-shot options add a semantic target, pass stable semantic selection/reference data into `AgentStartRequest`. Do not pre-convert a semantic target into only raw filename/line text.

No implicit TUI/web selection exists in ordinary one-shot mode.

---

## Provider Configuration

The one-shot command may override safe provider configuration such as:

```text
provider profile
model id
base URL
streaming preference
```

Secrets are resolved indirectly, preferably by a named environment variable or shared secret source.

Precedence must be deterministic and documented, for example:

```text
explicit CLI non-secret override
-> selected provider profile/config file
-> product defaults
```

Secret lookup is separate and never printed.

Do not record the API-key environment variable value in session provenance. Recording the variable name may also be omitted unless useful and safe.

---

## Human Output

For `--format human`:

- final user-facing agent text goes to stdout;
- bounded progress/diagnostics go to stderr;
- no provider request JSON is dumped by default;
- on success with no final text but a structured semantic result, render a concise result summary and stable handles.

When stdout is not a terminal, avoid dynamic carriage-return progress rendering.

Do not make progress output part of the final answer stream consumed by shell pipelines.

---

## JSON Output

For `--format json`, emit one stable machine-readable terminal object after completion.

It should include concepts equivalent to:

```text
status
operation id
session ref
root branch ref
final output text when available
branch result ref
produced change refs
validation refs
structured failure when unsuccessful
```

Do not emit provider credentials or raw request/response payloads.

Progress may be disabled in JSON mode or written separately to stderr in a documented non-JSON human diagnostic format. Prefer no decorative progress by default.

---

## Streaming Presentation

Streaming is optional presentation over the same operation.

If enabled and supported:

- transient model text may be shown on stderr or in a clearly separated interactive terminal presentation;
- the durable final output is still resolved from operation/session state;
- a lost stream does not make the command unable to finish if operation polling/status remains available.

For the simplest first implementation, it is acceptable to show phase/progress on stderr and print only the final durable output on stdout.

`--no-stream` disables transient output without changing agent semantics.

---

## Cancellation and Signals

Handle Ctrl-C/SIGINT as a cancellation request for the shared `OperationId` when execution has started.

Required behavior:

1. request shared operation cancellation;
2. stop starting new work;
3. allow a bounded runtime shutdown path;
4. preserve already durable session/branch provenance;
5. exit using the documented cancellation status.

Do not simply drop the process and report success.

A second interrupt may use the platform's conventional immediate termination behavior if required, but document/test that path separately.

---

## Exit Status

Define and document a stable exit mapping.

At minimum distinguish:

```text
success
usage/configuration failure
permission denied
provider/runtime/application failure
validation/conflict terminal failure when the agent result is unsuccessful
user cancellation
```

Preserve the repository's existing permission-denied convention (`77`) where applicable.

Use conventional interrupt status (`130`) where the supported platform behavior permits.

Do not infer success only from whether the provider returned assistant text; use the shared terminal operation/result status.

---

## Failure Rendering

Map structured failures to concise terminal diagnostics.

Useful categories include:

```text
provider configuration/authentication
provider timeout/rate limit/transport
capability denied
tool/application failure
validation failure
budget exceeded
cancelled
internal runtime failure
```

Human diagnostics should include the operation/session short handle when useful for later inspection.

Never print API keys, Authorization headers, or full sensitive compiled context in ordinary errors.

---

## Deterministic Tests

Use a fake provider and temporary/in-memory application composition where practical.

Cover at least:

- `srig run "hello"` starts the shared agent operation rather than a direct provider call;
- start returns and the CLI waits until deterministic completion;
- final stdout contains only the final answer/result in human mode;
- progress/diagnostics do not pollute stdout;
- JSON output contains operation/session/branch/result handles;
- `--no-stream` changes presentation only;
- provider/model/base-url overrides affect runtime configuration but not public agent request semantics;
- secret environment value is never printed or serialized into result/session DTO fixtures;
- Ctrl-C requests shared cancellation and returns cancellation exit status;
- deterministic nested-child execution still produces the same final one-shot result;
- `srig agent` delegates to the same runtime path under the selected compatibility behavior.

No test may contact a public model endpoint.

## Do Not Do

- Do not call the model HTTP endpoint from CLI parsing code.
- Do not create a second one-shot-only model loop.
- Do not add raw API keys as command-line arguments.
- Do not bypass session/root-branch creation.
- Do not treat transient stream fragments as the durable final result.
- Do not print provider secrets or complete sensitive context by default.
- Do not make `run` and `agent` semantically divergent runtimes.
