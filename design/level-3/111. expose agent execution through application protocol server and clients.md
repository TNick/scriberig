# Expose Agent Execution through Application, Protocol, Server, and Clients

**Status: [ ] Pending**

## Objective

Expose the completed branch-aware agent runtime as one shared long-running application operation available to embedded callers, server/client transports, one-shot CLI, TUI, web, and third-party clients.

Read first:

1. `design/level-1/016. model driven agent execution and branch isolation.md`;
2. `design/level-2/011. application operations protocol and runtime boundaries.md`;
3. `design/level-2/024. agent operations protocol and cross surface product contract.md`;
4. tasks 107 through 110.

This task owns semantic/transport exposure. Product presentation is implemented by later tasks.

## Application Agent Service

Add an application-facing service boundary equivalent to:

```text
AgentService
  start(context, request)
  continue_branch(context, request)
```

Cancellation should reuse the shared operation cancellation API unless a thin convenience wrapper materially improves callers.

The concrete product composition wires this service to `scriberig-agent-runtime`.

Tests must be able to inject a fake agent service.

---

## Start Request and Response

Represent the Level-2 contract with typed application structures.

Request must support at least:

```text
prompt
create/select session
optional parent branch
optional semantic selection
optional exact base snapshot
optional agent profile/context policy
retention policy
optional runtime limits
```

Response must return immediately with:

```text
OperationId
SessionRef
RootBranchRef
accepted/base snapshot when meaningful
```

Do not block application `start` until the model finishes.

---

## Continue Request

Support follow-up input against an existing session/branch.

Validate:

- session and branch exist;
- caller has access;
- branch lifecycle permits direct continuation or the application creates the required continuation child;
- semantic selection/base context is explicit when supplied.

Return a new operation handle for the continuation execution.

---

## Operation Integration

Use the existing shared operation lifecycle.

Agent operation records must be able to expose safe metadata:

```text
kind = agent
session/root branch
current phase summary
active branch count or handles when appropriate
final AgentResult reference
structured failure
```

Do not create an independent `AgentOperationStatus` lifecycle that disagrees with normal application operations.

---

## Agent Result

Define a structured terminal result equivalent to:

```text
AgentResult {
  session
  root_branch
  final_output
  branch_result
  produced_changes
  validation_results
  unresolved_questions
}
```

The exact representation may use universal semantic references.

A final plain text answer is only one projection of this result.

---

## Application Events

Map runtime events into shared application events.

Durable event kinds should carry references to committed session objects. Transient streaming/progress events may carry bounded payloads.

Include operation-local sequence/cursor metadata sufficient for deterministic ordering and reconnection logic.

At minimum expose concepts equivalent to:

```text
branch created/state changed
model invocation started
model text delta
tool started/completed
child branch started/completed
branch result produced
agent output committed
agent operation terminal
```

Sanitize provider diagnostics before publishing them.

## Server Dispatch

Add server dispatch for agent start/continue/status/cancel/event observation.

The server must:

- authenticate/authorize as configured;
- decode public requests;
- invoke `scriberig-app`;
- return stable handles immediately;
- forward shared operation/event state;
- never build provider prompts itself.

If the repository still only has in-process transport, implement and test semantic dispatch first. HTTP/event transport remains the responsibility of the server transport work required by the remote/web surface, but protocol shapes must not need redesign when that transport arrives.

## Rust Client

Add semantic client methods equivalent to:

```text
start_agent
continue_agent
operation_status
cancel_operation
subscribe/observe agent events
```

Reuse universal session queries for branch/session inspection where possible.

The client must hide protocol envelopes and must not expose provider connection details.

## Authorization

Starting/continuing an agent must enforce both:

1. permission to create/modify the target session branch;
2. the capability scope available to tools the runtime may expose.

The runtime still checks each individual tool invocation at execution time. Start-time capability discovery is not a permanent authorization grant.

---

## Event Recovery

Tests should prove a client can recover after missing transient events by querying:

```text
operation status
session branch tree
branch activity/result
```

Do not make final result correctness depend on stream replay.

---

## Tests

Add tests at the lowest owning layers plus a vertical deterministic slice.

Cover at least:

- `start` creates/returns session and root branch handles before completion;
- fake runtime completion populates shared `OperationStatus` and `AgentResult`;
- continuation targets an existing branch/session correctly;
- provider secrets cannot serialize into protocol DTOs;
- agent runtime errors map to stable application/protocol categories;
- event sequence ordering is preserved through server/client dispatch;
- cancellation request uses shared operation lifecycle;
- missed stream events can be recovered from durable session/operation state;
- embedded app and client/server dispatch return semantically equivalent deterministic results.

Run relevant commands, including:

```text
cargo fmt --all -- --check
cargo test -p scriberig-app
cargo test -p scriberig-protocol
cargo test -p scriberig-server
cargo test -p scriberig-client
cargo test -p scriberig-conformance
cargo clippy --workspace --all-targets -- -D warnings
```

Narrow commands are acceptable during development; final verification must cover all changed crates.

---

## Do Not Do

- Do not put OpenAI wire DTOs into `scriberig-protocol`.
- Do not send provider credentials to clients.
- Do not block start until the model finishes.
- Do not invent a second operation lifecycle for agents.
- Do not make transient stream delivery authoritative.
- Do not implement product UI in server/client crates.
