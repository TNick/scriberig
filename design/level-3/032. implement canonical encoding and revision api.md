# Implement: Canonical Encoding and Revision API

## Objective

Implement deterministic canonical revision encoding and the backend-independent revision storage API.

This task must make exact revision identity executable without introducing any domain-specific schema.

Create test modules or integration tests where useful.

## Canonical encoding

Implement a small, versioned canonical encoding facility sufficient to encode storage-level revision envelopes.

A revision envelope contains:

```text
encoding version
object type
canonical payload bytes
```

Requirements:

- output is deterministic;
- object type is included in identity;
- encoding version is included in identity;
- payload length/boundaries are unambiguous;
- implementation does not depend on Rust struct memory layout;
- malformed encoded input returns a typed error;
- the byte format is documented in Rust module docs or comments near the encoder.

Do not build a universal domain serialization system in this task. Treat the canonical payload as bytes already prepared by the caller.

## Revision ID computation

Implement a function that computes `RevisionId` by hashing the complete canonical revision envelope with BLAKE3.

The same envelope must always produce the same ID.

Different `ObjectType`, encoding version, or canonical payload must produce a different encoded envelope and normally a different ID.

## Backend-independent revision record

In `sr-store`, define a logical immutable revision record containing at least:

- `RevisionId`;
- `ObjectType`;
- `EncodingVersion`;
- canonical payload bytes.

Provide construction that computes/validates identity rather than trusting an arbitrary caller-supplied ID.

## Revision store interface

Define a backend-independent trait or equivalent API with operations equivalent to:

```text
put_revision(revision) -> RevisionId
get_revision(RevisionId) -> revision or not-found
has_revision(RevisionId) -> bool
```

Inserting the same exact revision more than once must be idempotent from the caller's perspective.

The API must not expose SQL, file paths, row IDs, or backend handles.

## Errors

Add machine-readable storage errors for at least:

- not found;
- invalid canonical encoding;
- revision identity mismatch;
- invalid operation;
- backend failure wrapper/category for future implementations.

Do not use string matching in tests to determine error categories.

## Tests

Add tests proving:

- fixed fixture envelope produces fixed canonical bytes;
- same envelope constructed twice produces identical bytes and ID;
- different object type changes encoded bytes/ID;
- different encoding version changes encoded bytes/ID;
- changed payload changes ID;
- malformed envelope decode fails cleanly if decode is implemented;
- revision record construction rejects mismatched externally supplied identity if such constructor exists.

Use at least one golden fixture for canonical bytes so accidental encoding changes fail loudly.
