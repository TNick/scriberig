# Bootstrap Web Workspace and Package Scaffolds

## Objective

Create the TypeScript/pnpm workspace and empty compileable package/application scaffolds prescribed by `design/level-2/001. web workspace packages and integrated editor.md`.

This task creates structure only. Do not implement protocol semantics, transport behavior, caches, selection logic, components, or editor workflows.

Read before editing:

1. `design/level-1/012. web platform and integrated editor.md`
2. `design/level-2/001. web workspace packages and integrated editor.md`

The controlling rule is:

> Reusable web packages must exist independently of the reference editor, and lower layers must not acquire React or MUI dependencies accidentally.

---

---

## Workspace Configuration

Use pnpm workspaces.

`web/pnpm-workspace.yaml` must include:

```text
packages/*
apps/*
```

The root package must be private.

Provide root scripts that can run the workspace checks:

```text
typecheck
test
build
```

The scripts may delegate recursively to packages.

Do not add publishing configuration beyond what is needed for package boundaries.

---

## TypeScript Configuration

`web/tsconfig.base.json` must:

- enable strict TypeScript checking;
- use modern ECMAScript targets suitable for current browsers and Node tooling;
- use module settings compatible with Vite and package builds;
- enable JSX only where extended configs need it;
- avoid path aliases that bypass package exports.

Each package `tsconfig.json` extends the base configuration.

Library packages must be able to emit declarations when later built as libraries.

Do not create cross-package source aliases such as imports from `../protocol/src/...`.

---

## Package Names

Use exactly:

```text
@scriberig/protocol
@scriberig/client
@scriberig/model
@scriberig/editor-core
@scriberig/react
@scriberig/components
@scriberig/components-mui
@scriberig/app
```

`@scriberig/app` is private.

---

## Dependency Boundaries

Configure only the dependencies needed for scaffolding and the prescribed layer direction.

The reusable dependency direction is:

```text
protocol
  ^
client
  ^
model
  ^
editor-core / react
  ^
components / components-mui
  ^
app
```

Specific requirements:

- `@scriberig/protocol` has no Scriberig package dependency.
- `@scriberig/client` may depend on `@scriberig/protocol`.
- `@scriberig/model` may depend on `@scriberig/protocol` and `@scriberig/client`.
- `@scriberig/editor-core` may depend on `@scriberig/protocol` and `@scriberig/model`.
- `@scriberig/react` may depend on the public lower packages and React, but not MUI.
- `@scriberig/components` may depend on React bindings and editor-core, but not MUI.
- `@scriberig/components-mui` may depend on public lower packages plus MUI.
- `@scriberig/app` may depend on all public packages.

Do not add a client state framework.

---

## Scaffold Source Content

Each library `src/index.ts` should contain package documentation and no speculative semantic API.

It may export nothing initially.

Do not invent placeholder entity types, fake client calls, or empty classes merely to populate the package.

`web/apps/scriberig/src/main.tsx` should mount the application using React.

`App.tsx` should render a minimal static shell such as the application name and a message that semantic views are not yet implemented.

The app may use MUI only through the normal MUI dependency or `@scriberig/components-mui`; do not implement actual Scriberig components in the app during this task.

---

## Vite Application

Configure `web/apps/scriberig` as a Vite React application.

The app must import reusable packages by package name, never by `packages/.../src` path.

Do not implement routes, panels, API connections, or agent commands yet.

---

## Required Checks

From `web/`, run the workspace-equivalent checks for:

```text
pnpm install
pnpm typecheck
pnpm test
pnpm build
```

If the root scripts use recursive pnpm commands, they must succeed even when packages currently have no tests.

The Vite app must produce a successful production build.

---

## Do Not Do

- Do not edit Level 1 or Level 2 design documents.
- Do not add server endpoint assumptions.
- Do not define protocol wire types yet.
- Do not implement a transport client.
- Do not implement browser caches or stores.
- Do not create selection or command APIs.
- Do not create reusable visual components yet.
- Do not implement the integrated editor views.
- Do not add Redux, Zustand, MobX, or another state framework.
- Do not add Storybook.
- Do not add Electron or Tauri.
- Do not add a browser E2E framework.
