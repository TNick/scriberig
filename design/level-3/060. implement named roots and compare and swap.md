# Implement Named Roots and Compare-and-Swap

## Mission

Implement mutable named roots that point to immutable `SnapshotId` values.

Named roots provide familiar moving names such as `main` while preserving the rule that snapshots themselves never change.

This task adds the only mutable coordination primitive required by the initial identity subsystem.

## Root Name

Define a small validated root-name type or an equivalent checked string wrapper.

Requirements:

- [x] non-empty;
- [x] deterministic textual representation;
- [x] no hidden normalization;
- [x] suitable for names such as `main`, `active-workspace`, and `current-project`;
- [x] validation failure uses a typed error.

Keep validation conservative and simple. Do not invent a complex path hierarchy in this task.

## Root Store Contract

Define a backend-independent public trait with behavior equivalent to:

```text
get(name) -> Option<SnapshotId>
set(name, snapshot) -> Result<...>
compare_and_swap(name, expected, new) -> Result<CasOutcome, ...>
```

The exact signatures may return owned values or references as appropriate, but callers must not receive mutable access to internal storage.

### `get`

Returns the exact snapshot currently referenced by the name, or `None` if the root does not exist.

### `set`

Unconditionally points the name at the supplied immutable snapshot ID.

This changes only the mutable root pointer. It does not change either snapshot.

### `compare_and_swap`

This is the concurrency-sensitive operation.

It succeeds only when the currently stored value equals `expected`.

Support both cases if practical:

```text
expected = Some(snapshot)   # update an existing root only if still at this snapshot
expected = None             # create only if the root is currently absent
```

Return an explicit outcome containing enough information for a caller to distinguish success from stale expectation.

Do not silently retry inside the store.

## In-Memory Implementation

Create `MemoryRootStore` backed by an `RwLock`-protected map or an equivalent standard synchronization primitive.

The compare-and-swap check and update must happen while holding one exclusive critical section so another writer cannot change the root between them.

Do not expose the lock through the trait.

## Required Tests

In `crates/sr-store/tests/roots.rs`, test at least:

- [x] missing root returns `None`;
- [x] `set` creates a root;
- [x] `set` can move a root from `S1` to `S2`;
- [x] moving a root does not change `S1` or `S2`;
- [x] CAS succeeds when expected value matches;
- [x] CAS fails when expected value is stale;
- [x] failed CAS leaves the current root unchanged;
- [x] CAS with `expected = None` can create a missing root;
- [x] CAS with `expected = None` fails when root already exists;
- [x] two independent root names may point to the same snapshot;
- [x] one root moving does not affect another root.

Add one concurrency test using two threads if it can be written deterministically enough to avoid flaky timing assumptions. Prefer barriers/channels over sleeps.

The test should demonstrate that only one writer can successfully advance a root when both use the same old expected snapshot.

## Error and Outcome Types

Keep storage failures distinct from compare-and-swap conflicts.

A stale expectation is not an exceptional storage failure; it is a normal concurrency outcome.

A caller must be able to inspect the actual current snapshot after a failed CAS, either in the outcome or with a subsequent `get`.

## Public API Rule

Named roots are mutable aliases.

They must never be accepted where an exact `SnapshotId` is required without first resolving the name.

Do not create an API such as:

```text
SnapshotId::from_root_name(...)
```

A name and a snapshot ID are fundamentally different concepts.

## Do Not

- Do not mutate a `Snapshot` when moving a root.
- Do not put root names into snapshot hashes.
- Do not turn root names into snapshot identities.
- Do not silently overwrite after a failed compare-and-swap.
- Do not add SQLite or network coordination yet.
- Do not add retry loops that hide conflicts from higher layers.
