# Implement OpenAI-Compatible Model Provider Transport

**Status: [ ] Pending**

## Objective

Implement the first production model-provider adapter in `scriberig-agent-runtime` behind a provider-neutral contract.

Read first:

1. `design/level-1/016. model driven agent execution and branch isolation.md`;
2. `design/level-2/023. agent runtime model provider and branch orchestration.md`;
3. `design/level-3/107. extend session records for model execution and branch results.md`.

This task implements transport and provider normalization only. It does not implement nested branch orchestration or public UI surfaces.

## Provider-Neutral Contract

Define a provider abstraction that allows both a real HTTP adapter and a deterministic fake provider.

It must accept a provider-neutral request containing at least:

```text
model identifier
ordered context blocks/messages
tool definitions
structured tool-choice policy
optional structured-output schema
output-affecting generation options
safe request metadata
```

It must return or stream normalized concepts equivalent to:

```text
assistant text
structured output
tool calls with structured arguments
finish reason
usage metadata
provider request id
provider model/fingerprint metadata when returned
```

No higher layer should need to know the OpenAI wire field names.

---

## Configuration

Support a provider configuration structure equivalent to:

```text
profile id
base URL
model id
credential source
request timeout
connect timeout
stream default
compatibility profile
optional default model parameters
```

Credentials must be loaded at runtime and must not implement `Debug`/serialization in a way that leaks secret values.

Prefer a credential source abstraction that can initially read an environment variable while allowing future secret-store integration.

---

## OpenAI-Compatible Wire Support

Implement the compatibility subset required for the agent runtime:

- user/system/assistant-like context content;
- tool/function declarations;
- tool calls with JSON arguments;
- normal complete responses;
- streaming response assembly;
- usage metadata when present;
- structured HTTP/provider errors.

The adapter may initially target one well-defined OpenAI-compatible endpoint family. Keep serialization isolated so another endpoint style can be added behind the same provider-neutral trait without touching orchestration code.

Do not expose provider DTOs from the crate's main public agent API unless they are explicitly under a provider-specific module.

---

## Capability Detection/Profile

Define `ProviderCapabilities` and a compatibility profile.

Represent at least:

```text
streaming
tool_calls
parallel_tool_calls
structured_output
usage_reporting
provider_request_id
provider_model_fingerprint
```

The compatibility profile may configure known deviations rather than attempting unreliable runtime probing for every feature.

Unsupported required behavior must fail before dispatch where possible.

---

## HTTP Requirements

Use a production HTTP client with:

- HTTPS support;
- connect and request timeouts;
- bounded response bodies;
- cancellation support;
- explicit status handling;
- safe user-agent/product identification;
- no logging of Authorization headers;
- proxy behavior that is either standard library/client behavior or explicitly documented.

`reqwest` is preferred unless implementation constraints justify another client.

Keep async/runtime dependencies inside runtime/product layers.

---

## Streaming Assembly

Normalize provider stream fragments into internal events equivalent to:

```text
ResponseStarted
TextDelta
ToolCallDelta
UsageUpdate
ResponseCompleted
ResponseFailed
```

The adapter must assemble complete tool calls before presenting the final `ModelResponse` to orchestration.

Handle fragmented JSON argument strings safely; do not parse incomplete fragments as final arguments.

An interrupted stream must return an incomplete/failure result and must not be treated as a successful cacheable response.

---

## Error Mapping

Map transport/provider failures into stable categories equivalent to:

```text
Configuration
Authentication
Permission
RateLimited
Timeout
Transport
InvalidRequest
UnsupportedCapability
MalformedResponse
ServerFailure
Cancelled
```

Capture safe status/request identifiers where available.

Do not include full prompts or secret headers in ordinary error display text.

## Fake Provider

Implement a deterministic fake provider usable by later branch-orchestration tests.

It must support a scripted queue of normalized responses, including:

```text
text response
tool call response
multiple tool calls
provider failure
stream fragments
```

The fake records received provider-neutral requests for assertions.

No network access is allowed in fake-provider tests.

---

## Local Mock HTTP Tests

Use a local in-process mock HTTP server or equivalent fixture to test the concrete adapter.

Cover at least:

- configured base URL is honored;
- authorization is sent but never surfaced in diagnostics;
- assistant text is normalized correctly;
- tool definitions are serialized;
- tool calls are normalized;
- stream fragments assemble into the same semantic response as non-stream mode;
- rate-limit/auth/server failures map to structured errors;
- timeout/cancellation terminate correctly;
- malformed provider JSON is rejected;
- incomplete stream is not reported as success.

Tests must not contact the public internet.

---

## Logging and Diagnostics

Safe diagnostics may include:

```text
provider profile id
model id
HTTP status
provider request id
elapsed duration
usage counts
```

Do not log by default:

```text
API key
Authorization header
complete prompt/context
complete tool results
raw provider body containing sensitive context
```

A future explicit audit mode may retain sanitized payloads separately.

## Do Not Do

- Do not implement session branch orchestration.
- Do not directly call `scriberig-store`.
- Do not expose provider credentials through protocol types.
- Do not add provider SDK dependencies to TUI, CLI parsing, web, or foundation crates.
- Do not assume streamed deltas are durable session objects.
- Do not require the provider for unit tests of provider-neutral logic.
