# Expose Trust Inspection in Web Editor

## Objective

Add reusable web-platform support and an integrated-editor view for provenance, validation, policy evaluation, conflicts, approvals, and capability denials.

The full editor must consume public web libraries. Do not implement trust inspection only as private application code.

## Read First

1. `design/level-1/013. trust validation capabilities and provenance.md`, especially sections 37–39, 52–54 and 62–63.
2. `design/level-1/012. web platform and integrated editor.md`.
3. `design/level-2/001. web workspace packages and integrated editor.md`.
4. `design/level-3/007. expose trust state through protocol and events.md`.
5. Existing web workspace/bootstrap, client, model, React, component, and editor tasks.

If the public web packages have not been scaffolded, stop and report the prerequisite rather than adding a private one-off editor implementation.

## Expected Package Boundaries

Use the established packages, typically:

```text
web/packages/client
web/packages/model
web/packages/react
web/packages/editor-core
web/packages/components
web/packages/components-mui
web/apps/editor
```

Do not require consumers to use MUI to inspect trust state.

## Client and Model

Add client/model operations that can:

```text
load compact trust summary for an entity/revision
load provenance relations/details
load validation evidence
load policy/approval evidence
load conflict details
subscribe to trust-relevant events
```

Keep selection based on universal semantic IDs/snapshots. Trust panels should work for code, Markdown, PDF-derived objects, sessions, and future domains without separate navigation systems.

## Headless Editor Core

Provide headless controller/state suitable for third-party UIs. It should expose states such as:

```text
loading
ready
restricted/denied
validation failed
validation stale
conflict unresolved
approval required
```

Expose handles/actions, not hard-coded presentation.

## React Bindings

Add hooks following existing package conventions, equivalent to:

```text
useTrustSummary(selection)
useProvenance(selection)
useValidation(selection)
useTrustEvents(...)
```

Do not invent duplicate fetching/cache behavior outside the established web model/client layer.

## Reusable Components

Add neutral components for at least:

```text
TrustSummary
ProvenanceInspector
ValidationList
PolicyEvaluationView
CapabilityDeniedNotice
ConflictSummary
```

Then provide MUI wrappers/compositions only if the MUI package already exists.

Components must distinguish authored/observed/generated knowledge and current/stale/failed validation without converting them into one trust score.

## Integrated Editor

Add a trust/provenance inspector that works from the editor's universal selection. It should support:

- compact high-level status;
- following exact provenance edges;
- opening validation diagnostics;
- inspecting policy/approval evidence;
- opening conflicts;
- navigating back to source evidence when source coordinates are available.

The raw graph/relation browser must still be able to inspect the same underlying objects.

## Denials and Confidentiality

A denial is a normal UI state. Do not attempt alternative requests that widen scope automatically. Do not show hidden snippets, cached summaries, or relationship labels that reveal restricted data.

## Tests

Add tests for:

1. authored vs model-generated badge/state;
2. current vs stale validation;
3. failed validation diagnostics;
4. capability denial rendering without payload leak;
5. conflict view with exact handles;
6. universal selection drives trust inspector;
7. neutral component works without MUI;
8. MUI layer wraps public behavior rather than re-fetching privately;
9. event update refreshes affected trust state;
10. restricted derived summary is not rendered when subject access is denied.

## Validation

Run the repository's web lint, typecheck, unit/component tests, build, and any protocol conformance generation.

## Do Not

Do not add private API endpoints for the editor. Do not couple trust components to one domain. Do not compute authorization in React. Do not expose secret values.

## Completion Checklist

- [ ] public web packages expose trust inspection;
- [ ] headless behavior exists independently of MUI;
- [ ] integrated editor uses public components/hooks;
- [ ] universal selection links semantic object to provenance;
- [ ] denial/conflict/stale states are explicit;
- [ ] tests cover restricted and generated data.
