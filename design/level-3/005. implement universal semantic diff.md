# Agent Task: Implement Universal Semantic Diff

## Goal

Implement backend-independent comparison of two exact snapshots.

A diff answers what differs between states. It must work whether the snapshots are directly related, distant ancestors, siblings, or historically unrelated but available in the same store.

Do not implement merge resolution in this task.

## Read before editing

Read:

1. `design/level-1/005. changes migrations branches and merge.md`, especially sections 10 through 13, 21, 23, 24, 29, 30, 42, 43, 44, and 48.
2. `design/level-2/002. change history and merge crate design.md`.
3. Existing `sr-store` snapshot enumeration/diff capabilities.

## Files to modify

```text
crates/sr-change/src/diff.rs
crates/sr-change/src/summary.rs
crates/sr-change/src/lib.rs
crates/sr-change/tests/change_conformance.rs
```

Extend `sr-store` only if a generic efficient snapshot-mapping comparison capability is missing and cannot be implemented correctly through the existing public API.

## Universal diff result

Implement a result containing, at minimum:

```text
left SnapshotId
right SnapshotId
entity deltas
```

Reuse the universal `EntityDelta` model rather than defining another incompatible changed-entity type.

The diff must classify:

```text
introduced entities
removed entities
modified entities
```

Do not include unchanged entities in the main result.

## No ancestry requirement

The API must accept arbitrary snapshots.

Do not require one snapshot to be an ancestor of the other.

Add tests for:

```text
S1 -> S2 -> S3: diff(S1, S3)

       S1
      /  \
    S2    S3: diff(S2, S3)
```

## Snapshot-level optimization

If `left == right`, return an empty diff immediately.

If storage provides a persistent-map structural diff, use it through the backend-independent interface.

Correctness must not depend on a specific Merkle/trie implementation.

## Relation and collection details

If generic relation/collection state is available through universal graph/storage APIs, define optional detail structures for:

```text
relation added/removed
collection member inserted/removed
collection order changed
```

These details must be subordinate to the authoritative revision/entity delta.

Do not parse domain-specific payloads in the generic diff engine.

## Domain enrichment interface

Expose a narrow extension point that allows a domain crate to turn a universal diff into richer meaning.

The generic crate must remain useful without any domain adapter installed.

The extension point should receive exact entity/revision references and return additional interpretation without mutating the universal diff.

## Determinism

Diff output must have deterministic ordering independent of backend iteration order.

Choose and document a stable ordering for entity deltas using canonical identifier ordering.

Do not use timestamps or insertion sequence for ordering.

## Summary support

Implement a compact deterministic summary containing at least:

```text
introduced count
removed count
modified count
total changed entities
```

This summary should be obtainable without rendering textual source or opening domain-specific details.

## Large diffs

Design the API so it can later support pagination/streaming without changing semantic meaning.

Do not prematurely implement a complex streaming framework unless the storage API already supports one. Avoid forcing all higher layers to rely on a giant formatted string.

## Tests

Add tests for:

- identical snapshots produce empty diff;
- one modified entity;
- one introduced entity;
- one removed entity;
- multiple changes sorted deterministically;
- ancestor-to-descendant comparison;
- sibling comparison;
- same final revision reached through different histories still compares as state, not history;
- unrelated unchanged entities are absent from result;
- summary counts exactly match deltas;
- generic diff requires no domain adapter.

## Constraints

- Diff is not migration.
- Diff is not textual file diff.
- Do not infer historical intent.
- Do not declare conflicts; merge owns that.
- Do not mark all entities changed because `SnapshotId` differs.
- No concrete backend dependency.

## Verification

Run:

```text
cargo fmt --check
cargo test -p sr-change
cargo check --workspace
```

Run shared store conformance tests if the storage API changed.

## Completion checklist

- [ ] Arbitrary snapshots can be compared.

- [ ] No unchanged entities are emitted.
- [ ] Result ordering is deterministic.
- [ ] Compact summary exists.
- [ ] Sibling snapshot tests pass.
- [ ] Domain enrichment is optional and dependency-safe.

## Final response from implementing agent

Report the diff API, any storage capability added, deterministic ordering rule, performance shortcut used for equal snapshots, and tests added.
