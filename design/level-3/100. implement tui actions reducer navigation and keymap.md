# Implement TUI Actions, Reducer, Navigation, and Keymap

**Status: [x] Implemented**

## Objective

Replace ad-hoc event handling from the bootstrap slice with the stable TUI interaction core: typed actions, a pure reducer, navigation history, focus, overlays, and a data-driven keymap.

Read first:

1. `design/level-2/021. terminal ui runtime and state architecture.md`;
2. `design/level-2/022. terminal ui views interaction and conformance.md`;
3. `design/level-3/099. bootstrap ratatui terminal runtime and shell.md`.

This task is presentation-only. It must not invent semantic application behavior.

---

Add or complete modules equivalent to:

## Action Model

Define typed actions for local interaction and future service results. The initial set must cover concepts equivalent to:

```text
QuitRequested
OverlayClosed
FocusNext
FocusPrevious
CursorMoved
Activated
Back
Forward
RefreshRequested
HelpOpened
PaletteOpened
FindOpened
InputChanged
InputSubmitted
TerminalResized
```

Leave semantic result actions extensible for later tasks.

Do not use string command names as the reducer's primary internal dispatch mechanism.

---

## Reducer Contract

Implement one deterministic update boundary equivalent to:

```text
reduce(state, action) -> Vec<Effect>
```

or a result that contains `next_state + effects`.

Reducer responsibilities include:

- changing focus;
- changing local cursor/scroll state;
- opening/closing overlays;
- updating navigation stacks;
- recording local input;
- requesting effects without executing them.

The reducer must not call `scriberig-app`, filesystem APIs, or terminal APIs.

---

## Navigation State

Implement back/forward navigation locations that can eventually carry:

```text
semantic selection
primary view kind
snapshot/branch context
optional comparison target
```

For this task, define the stable structure even if only empty/no-selection locations are exercised.

Rules:

- pushing a new location clears forward history;
- back/forward does not mutate canonical state;
- pane focus changes do not create semantic history entries;
- resize does not change history;
- cursor indexes are presentation state, not semantic identity.

---

## Keymap

Represent bindings as data mapping key chords + interaction context to action identifiers.

Implement the default Level 2 bindings for at least:

```text
Ctrl-C
Esc
Tab
Shift-Tab
Enter
arrow keys
Backspace
:
/
?
r
q
```

Optional `h/j/k/l` aliases may be included for ordinary browse mode.

Text-input mode must consume printable keys as text rather than triggering browse commands.

Paste must arrive as one input-data event, not as a replay of command keystrokes.

---

## Help and Key Hints

Generate the help overlay and contextual key-hint labels from the same keymap/action metadata.

Do not duplicate a manually maintained help table that can drift away from actual bindings.

The help overlay must be reachable from every non-fatal state and closable without changing semantic navigation.

---

## Command Palette Foundation

Create the palette state/model with two future action sources:

```text
local presentation actions
semantic contextual actions
```

Implement filtering and selection for local actions in this task.

Semantic actions may remain empty until task 101 attaches the service/capability model.

Palette filtering may be simple case-insensitive substring matching initially. Keep the filtering function isolated so ranking can evolve later.

---

## Effects

Define an `Effect` enum or equivalent boundary now even if most effects are local placeholders.

At minimum distinguish:

```text
NoEffect / none
RequestRefresh
RequestFind { text }
RequestSemanticAction { id, inputs }
RequestQuit
```

The runtime executes effects outside the reducer. Later tasks expand effect variants with typed application operations.

---

## Rendering Updates

Update the shell so focused regions, overlays, and key hints are visibly represented by more than color alone.

A focus marker, border label, prefix, or equivalent textual cue is required.

Do not make mouse support a prerequisite.

---

## Tests

Add reducer/keymap tests for at least:

- focus cycling;
- overlay precedence/close behavior;
- text input not triggering global printable-key actions;
- paste treated as input data;
- navigation push/back/forward invariants;
- forward history cleared after a new activation;
- resize preserving navigation;
- help/key hints derived from actual bindings;
- palette filtering local actions;
- quit request from browse mode.

Use pure tests where possible; do not require a real terminal.

---

## Out of Scope

Do not implement:

- database/application adapters;
- real entity rows;
- capability discovery;
- semantic action execution;
- history/diff/projection data loading;
- session/agent behavior;
- remote connections.
