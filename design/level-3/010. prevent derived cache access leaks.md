# Prevent Derived Cache Access Leaks

## Objective

Ensure summaries, descriptions, search indexes, analysis results, and other derived/cached artifacts cannot expose knowledge that the requesting principal is not allowed to observe.

This task connects the derived-knowledge cache model to application-level capability enforcement without moving authorization policy into the generic cache implementation.

## Read First

1. `design/level-1/013. trust validation capabilities and provenance.md`, especially sections 11, 33, 62–64.
2. `design/level-1/008. derived knowledge caching and incrementality.md`.
3. `design/level-3/002. enforce capabilities in application queries.md`.
4. Existing derived-knowledge runtime/cache Level 2 and Level 3 designs.

If the derivation/cache subsystem or application authorization boundary does not exist yet, stop and report the prerequisite.

## Expected Area

Reuse the existing derivation/cache implementation. Likely changes span:

```text
existing derived-knowledge/cache crate modules
crates/scriberig-app/src/authorization.rs
crates/scriberig-app/src/query.rs or derived-view adapter
```

Do not fork a second secure cache.

## Dependency Access Semantics

Every derived artifact must retain enough dependency information to identify the semantic inputs from which its visible content was produced.

For an application request, access to a derived artifact is allowed only if the effective policy permits the caller to observe the information that the artifact reveals.

At minimum, implement the conservative rule:

> If the caller cannot read every declared semantic dependency that contributes visible content, do not return the derived artifact.

Later policies may support redacted derivations, but this task must not invent partial-redaction inference.

## Cache Keys vs Authorization

Keep cache identity independent from principal identity where possible. Immutable input/profile keys should continue to deduplicate computation globally.

Authorization is checked when returning an artifact through the application layer.

Do not duplicate identical summary computation once per user merely to enforce access control unless the existing architecture explicitly requires per-principal derivation.

## Search Indexes

If the derived subsystem owns a searchable index, ensure the application search path filters results before exposing:

```text
entity identity when confidential
matched text/snippet
summary text
relation context
counts that reveal restricted entities when policy forbids existence disclosure
```

The lower-level index may remain complete; the trusted application boundary must not return forbidden hits.

## Nested Derived Artifacts

A derived artifact may depend on another derived artifact. Access calculation must ultimately account for canonical/observed semantic dependencies, not merely conclude that a cached summary is public because its direct dependency is another summary.

Reuse the existing derivation dependency graph rather than adding ad hoc recursive database scans.

## Tests

Create fixtures for:

1. principal can read subject and receives cached summary;
2. principal cannot read subject and cannot receive cached summary;
3. restricted entity is absent/redacted from authorized search result according to application policy;
4. cache hit does not bypass capability check;
5. artifact derived from allowed + restricted dependencies is denied conservatively;
6. nested derived artifact still carries effective restrictions;
7. broader principal reuses the same cached artifact successfully;
8. authorization denial does not invalidate/delete the shared cache entry;
9. formatting/profile cache behavior remains unchanged by authorization;
10. no restricted snippet appears in denial/error text.

## Validation

Run workspace format/check/tests/lint and existing cache/derivation tests. Include an application-level integration test proving the same cache key can serve an authorized caller while being denied to an unauthorized caller.

## Do Not

Do not put mutable ACLs inside immutable content hashes. Do not make principal identity part of semantic revision identity. Do not return cached text before checking access. Do not assume generated summaries are safe to expose because they are not canonical.

## Completion Checklist

- [ ] derived artifacts retain usable dependency provenance;
- [ ] application access checks cover cache hits and misses;
- [ ] search cannot leak restricted snippets;
- [ ] nested derivations preserve effective restrictions;
- [ ] shared immutable cache entries remain reusable across authorized principals;
- [ ] tests prove denial does not destroy cache reuse.
