# Scaffold Web UI Packages and Editor Shell

## Objective

Extend the web workspace created by `003. initialize web workspace and headless packages.md` with reusable UI packages and the integrated Scriberig editor shell prescribed by `design/level-2/001. workspace and package layout.md`.

This task creates package boundaries and a minimal application shell only. Do not implement semantic browsers, editors, agent panels, MUI widgets, routing, server communication, or application state behavior.

Read before editing:

1. `design/level-1/001. vision and principles.md`
2. `design/level-2/001. workspace and package layout.md`
3. `design/level-3/003. initialize web workspace and headless packages.md`

The important architectural rules are:

- the integrated editor is a consumer of public packages;
- low-level database/revision views and high-level semantic/agent views must eventually resolve through the same public model;
- reusable components must not depend on the private integrated editor app;
- MUI-specific code belongs only in the MUI package or integrated app;
- product behavior must not bypass `@scriberig/client`, `@scriberig/model`, and the public editor abstractions.

---

## Files to Create

Create:

```text
web/packages/components/package.json
web/packages/components/src/index.ts
web/packages/components-mui/package.json
web/packages/components-mui/src/index.ts
web/packages/agent-ui/package.json
web/packages/agent-ui/src/index.ts

web/apps/editor/package.json
web/apps/editor/src/main.tsx
```

Do not create additional application framework files unless a later design explicitly chooses the framework/build system.

---

## Package Names and Roles

Use these names exactly:

```text
web/packages/components      -> @scriberig/components
web/packages/components-mui  -> @scriberig/components-mui
web/packages/agent-ui        -> @scriberig/agent-ui
web/apps/editor              -> @scriberig/editor-app
```

Use version `0.1.0` for the reusable packages.

Mark the integrated editor app private.

At this stage the reusable packages may also remain private to avoid accidental publication before release design exists.

---

Represent these workspace dependencies:

├── @scriberig/react

├── @scriberig/components-mui

Use pnpm workspace references for all internal packages.

No public package may depend on `@scriberig/editor-app`.

---

## MUI Boundary

This task reserves the MUI-specific package boundary but does not need to install or implement MUI yet.

If MUI dependencies are added while performing this task, they are allowed only in:

```text
web/packages/components-mui
web/apps/editor
```

They must not appear in:

```text
@scriberig/protocol
@scriberig/client
@scriberig/model
@scriberig/editor-core
@scriberig/react
@scriberig/components
@scriberig/agent-ui
```

Do not add MUI merely to make the package name appear justified. An empty documented scaffold is acceptable and preferred until component design exists.

---

## Reusable Package Source Files

Each reusable package `src/index.ts` should contain only documentation comments and an empty module export.

Document the intended roles accurately:

- `@scriberig/components`: reusable style-neutral or styleable Scriberig component boundary;
- `@scriberig/components-mui`: opinionated MUI implementation over public editor/React primitives;
- `@scriberig/agent-ui`: reusable UI primitives for sessions, branches, agent operations, and agent-scoped semantic selections.

Do not invent components such as `ObjectTree`, `AgentPanel`, or `SemanticDiff` until their API has a lower-level design.

---

## Integrated Editor `main.tsx`

Create a compileable placeholder module only.

It may contain a comment explaining that the integrated editor will compose public Scriberig packages and an empty export:

```ts
export {};
```

Do not create a private semantic model in the app.

Do not create a raw database API client in the app.

Do not add direct server fetches.

Do not add placeholder UI that would establish accidental product architecture before the editor design exists.

---

## Editor App Manifest

The editor app manifest must express dependencies on the public packages listed above using pnpm workspace references.

Do not add a production framework, router, state library, or build system unless a later design explicitly selects it.

This means the app may not yet have a runnable browser bundle. That is acceptable: this task establishes the dependency boundary, not the final web runtime.

---

## Required Checks

From `web/`, if pnpm is available, run:

```text
pnpm install
pnpm list -r --depth -1
```

Verify that the three new packages and editor app are discovered.

Inspect package manifests and verify:

- no package imports the editor app;
- only the MUI package/editor may contain MUI dependencies;
- the editor depends on reusable packages rather than private source paths;
- workspace dependencies resolve without cycles.

Do not introduce a framework just to create a build command for this scaffold.

---

## Do Not Do

- Do not implement actual UI components.
- Do not choose a router.
- Do not choose an application state library.
- Do not implement HTTP/WebSocket calls.
- Do not implement agent commands.
- Do not implement raw entity browsing.
- Do not implement semantic editing.
- Do not add private product-only model types.
- Do not bypass the public package boundaries.
- Do not edit Level 1 or Level 2 design documents.
