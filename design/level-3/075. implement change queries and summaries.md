# Agent Task: Implement Change Queries and Progressive Summaries

## Goal

Implement the backend-independent query and compact-inspection layer for change history.

The result must let database-only applications, CLI/API surfaces, and future agents ask useful questions without loading full migration bodies or domain-specific representations.

2. `design/level-2/002. change history and merge crate design.md`.
3. Existing migration, history, branch, diff, conflict, and merge types.

## Query service

Provide a backend-independent service or set of functions capable of answering at least:

```text
what changed between snapshots A and B?
what migration introduced revision R?
what is the history of entity E?
which migrations touched entity E?
what branches descend from snapshot S?
what is the common ancestor of A and B?
what conflicts prevent merging A and B?
which changes came from branch/workspace W?
```

Use existing store/history abstractions. Do not reach into backend tables.

## Query result types

Return structured data, not formatted prose.

Each result should contain stable identifiers/handles that callers can use for deeper queries.

For example, entity history results should carry:

```text
EntityId
RevisionId before/after
Migration reference
SnapshotId where visible
optional branch/workspace provenance
```

Do not return only filenames, line numbers, or free-form descriptions.

## Pagination and bounded results

For potentially large queries, design result types so pagination or cursors can be added or used without changing meaning.

If the existing store/query conventions already provide cursors, use them.

Do not force every call to materialize all descendants or all migrations in memory when a bounded form is possible.

## Structural summaries

Implement deterministic compact summaries for:

### Migration

At minimum:

```text
base snapshot
result snapshot
source category
introduced count
removed count
modified count
semantic operation count
validation reference count
```

### Diff

At minimum:

```text
left/right snapshots
introduced count
removed count
modified count
```

### Branch/workspace

At minimum:

```text
branch/workspace reference
base snapshot
current snapshot
status
short title/description if present
resulting migration if present
```

### Merge result

At minimum:

```text
base/left/right
resolved entity count
conflict count
conflict kinds by count
```

These are structural facts. Do not invoke an LLM or create generated prose in `sr-change`.

## Progressive disclosure

Support at least three conceptual levels through APIs/types:

```text
summary
structured detail
exact referenced revisions/operations
```

A caller should be able to list many migrations/branches using summaries and then inspect one item deeply.

Do not make full migration payload loading mandatory for branch lists if storage can provide summary metadata separately.

## Branch descriptions

Expose authored or already-derived title/purpose/description/outcome fields when available.

Preserve their provenance/reference rather than pretending structural summaries generated them.

The query layer should not synthesize semantic conclusions.

## Generic operation without domain adapter

Every query in this task must remain meaningful if no domain adapter is loaded.

Domain-aware callers may enrich returned identifiers later.

For example, generic history must still say:

```text
Entity E changed R1 -> R2
```

without knowing that `E` is a function or paragraph.

## Cross-domain migration

Add tests where one migration changes entities from different domain/type categories.

The generic query/summary layer must return all changes in one migration without assuming one file, one language, or one adapter.

## Determinism

When a query returns an ordered collection without semantic order, sort using stable canonical identifiers.

Do not rely on hash-map, database, or insertion order.

## Tests

Add tests for:

- changed-between query delegates to semantic diff and returns stable handles;
- migration that introduced a revision can be found;
- entity history returns correct ordered transitions;
- migrations touching an entity are returned deterministically;
- descendant branch query uses explicit ancestry;
- common ancestor query returns topology result, not timestamp result;
- workspace provenance query filters correctly;
- migration summary counts match exact deltas;
- merge summary reports conflict kinds correctly;
- branch list can use compact metadata;
- cross-domain migration is fully visible without adapters;
- queries remain valid when descriptions are absent.

## Constraints

- No prose-generation model calls.
- No concrete backend SQL.
- No domain-specific assumptions.
- No physical write-order semantics.
- No hidden full-object reads solely to render a one-line list when structured summary data is available.
