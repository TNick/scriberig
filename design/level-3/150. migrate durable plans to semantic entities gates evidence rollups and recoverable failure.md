Implementation update (2026-10-22): plans are encoded as independently
revisioned Plan, PlanNode, dependency, gate, evidence, summary, and relation
objects under a deterministic semantic root. Reads hydrate plan projections
from that root, and mutations use root compare-and-swap. Typed plan mutations
are wired through application, protocol, server, Rust client, TypeScript client,
and the Web plan panel. SQLite stores a snapshot/version-bound rollup index,
updates it through the in-memory ancestor-only propagation path after plan CAS,
and rebuilds it when the cache is missing/stale or node membership changes.
Retry and failed-plan recovery operations preserve attempt provenance in
immutable plan history. Focused tests cover retries, deep/reparented rollups,
incremental SQLite persistence, and migration of multiple legacy plan history
revisions across restart. A transcript-free plan-attempt history endpoint now
pages the reconstructed immutable history, defaults to 25 entries, and caps
each response at 100. Protocol, server, Rust-client, TypeScript-client, and Web
client wiring are covered by focused tests and typechecking.

## 1. Objective

Migrate durable planning from aggregate session-plan persistence to independently revisioned semantic plan objects while preserving the existing coordinator, scheduler, dependency-result, branch-isolation, and cross-surface behavior.

The finished implementation must provide:

```text
independent Plan semantic entity
independent PlanNode semantic entities
semantic structural relations
independent dependency state
first-class Summary links
first-class evidence associations
first-class typed gates
recoverable Failed nodes and plans
preserved retry/attempt provenance
derived incremental parent/subtree status rollups
legacy aggregate-plan migration/compatibility
shared app/protocol/client/web/TUI projections
```

Do not introduce `PlanNodeWorkState` or another parallel lifecycle enum.

Do not replace Scriberig plan semantics with an upstream task-list model.

Reject an implementation that does any of the following:

- [ ] Treats serialized `Plan` JSON as the new canonical storage after migration.
- [ ] Stores PlanNode only as a nested field of Plan.
- [ ] Introduces `PlanNodeWorkState` or a second lifecycle enum.

- [ ] Requires a full descendant scan every time top-level status is read.
- [ ] Defines rollup semantics only inside SQLite trigger SQL.
- [ ] Makes generic foundation store crates depend on `scriberig-session` plan types.
- [ ] Copies validation/result payloads into opaque evidence strings instead of referencing exact semantic objects.
- [ ] Treats gates and dependencies as the same relation.
- [ ] Treats failed node as permanently terminal.
- [ ] Deletes failed attempt provenance during retry.
- [ ] Allows ignored/abandoned work to satisfy dependencies implicitly.
- [ ] Requires replan merely to append ordinary newly discovered work to a running plan.
- [ ] Lets TUI/web mutate plan state directly.
- [ ] Implements new TUI plan widgets against the superseded local Ratatui shell instead of task 148/upstream components.

Every item above must remain unchecked because each describes forbidden behavior.
