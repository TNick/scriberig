Baseline inventory (2026-10-22): `scriberig-session/src/planning.rs` and its
`planning/` modules own aggregate `Plan`, `PlanNode`, dependency, claim, and
plan-history domain behavior. `scriberig-session::SessionStore` exposes a
whole-session save plus plan-local CAS. `scriberig-session-sqlite` currently
encodes complete plans inside the `session_records.payload` and performs plan
CAS by replacing that nested plan in a transaction. `scriberig-app` owns plan
operations and delegates CAS to the session repository. `scriberig-agent-runtime`
owns scheduling/coordinator orchestration. `scriberig-protocol`, server,
client, web, and TUI expose plan projections; none is an authority for canonical
plan mutation. Universal immutable revision/snapshot APIs live in
`scriberig-store` and its backends, but plan writes do not currently use them.

Implementation update (2026-10-22): `scriberig-session::PlanSemanticSnapshot`
now encodes Plan, PlanNode, membership, structural, dependency, and mutation
metadata as independent universal revisions. `SqliteSessionStore` stores each
plan under a deterministic session/plan root in `scriberig-store-sqlite`;
plan-local CAS promotes that root and reads hydrate the aggregate compatibility
projection from the root. Snapshot ancestry reconstructs historical plan
states, while separate revision metadata retains safe mutation reasons. Legacy
aggregate plans are imported as an ordered snapshot chain on first read. The
SQLite session JSON still carries a compatibility projection and branch/session
records; it no longer accepts plan mutations when a semantic root exists.

Implementation update (2026-10-30): exact plan snapshot reads now reject
snapshots outside the plan root's ancestry and preserve historical membership.
Plan-attempt outcomes are independently revisioned semantic objects. Plan
semantic promotion and compatibility session/branch projection updates now use
one SQLite connection and one transaction, so a failed root CAS rolls back the
projection write as well. The regression
`plan_cas_rolls_back_session_projection_on_semantic_conflict` proves rollback;
`plan_dependencies_and_assignments_survive_reopen` proves stale callers still
receive a structured revision conflict. Structural cycle validation now runs
before semantic promotion. Focused session and SQLite tests pass, including 20
consecutive runs of `execution_selection_compare_and_swap_is_atomic` after its
competing proposals were made to carry consistent history.

Implementation update (2026-10-30): the session store now exposes a compact
snapshot-bound PlanView read. SQLite selects plan, node, membership, and
structure revisions using revision type metadata and does not load detailed
evidence, gate, summary, attempt, or history payloads. A corruption regression
proves compact inspection remains available while the full read correctly
reports a damaged evidence object. The TypeScript protocol/client now preserve
the shared plan/node view fields and call the shared semantic-mutation and
retry operations. Focused Rust semantic/SQLite tests and the web client tests
pass; `pnpm --dir web typecheck` passes.

Implementation update (2026-10-30): root promotion now starts with an
immediate SQLite transaction so independent connections serialize before
reading and promoting the named root. The regression
`independent_handles_serialize_root_compare_and_swap` verifies exactly one
writer succeeds and the other receives a structured root conflict. The focused
store suite and the plan-related Rust suites pass across session, SQLite,
application, agent runtime, protocol, client, and server packages; web client
tests and full web typecheck pass.

Remaining implementation gaps: bounded per-node detail and separate attempt /
evidence history reads are incomplete; SQLite does not persist a normalized
rollup index; migration equivalence coverage for every historical plan and
coordinator field is incomplete; and web product surfaces do not yet present

still In Progress, so task 150's TUI integration remains deferred under the

the governing design before task 150 can be completed.

Implementation update (2026-10-30): scheduler settlement now sends successful
and failed branch results, execution activity, evidence, and terminal Plan
state through one plan CAS. SQLite derives newly settled worker branches from
the prior and proposed semantic Plan and applies their result projections in
the same transaction as root promotion. The application fallback performs the
equivalent projection under its session lock. The regression
`plan_cas_rolls_back_session_projection_on_semantic_conflict` injects a root
promotion failure after projection work and proves neither the branch result
nor terminal node state is visible; `plan_settlement_commits_existing_branch_result_with_semantic_state`
proves both views appear after one successful CAS. Durable retry coverage

Implementation update (2026-10-22): focused SQLite recovery coverage exposed

## 1. Objective

Migrate durable planning from aggregate session-plan persistence to independently revisioned semantic plan objects while preserving the existing coordinator, scheduler, dependency-result, branch-isolation, and cross-surface behavior.

The finished implementation must provide:

```text
independent Plan semantic entity
independent PlanNode semantic entities
semantic structural relations
independent dependency state
first-class Summary links
first-class evidence associations
first-class typed gates
recoverable Failed nodes and plans
preserved retry/attempt provenance
derived incremental parent/subtree status rollups
legacy aggregate-plan migration/compatibility
shared app/protocol/client/web/TUI projections
```

Do not introduce `PlanNodeWorkState` or another parallel lifecycle enum.

Do not replace Scriberig plan semantics with an upstream task-list model.

## Task 7.6 — Optional SQLite triggers

Use triggers only if they simplify and harden transactional ancestor counter maintenance.

- [ ] Trigger implementation, if used, has equivalence tests against reference rollup.
- [ ] Trigger SQL is not the only specification of status semantics.
- [ ] Memory/reference backend passes the same conformance without triggers.

If triggers are not used initially:

- [x] Document why application/session-layer transactional propagation is preferable for the first implementation.

Implementation decision: dispatch currently derives readiness from canonical
plan state, so it cannot act on a stale persisted rollup. The in-memory
`PlanNodeRollupIndex` is rebuildable and snapshot-bound, but is not persisted.
SQLite triggers would duplicate Rust gate/rollup semantics inside SQL and
still need snapshot/evaluator-version invalidation logic. Keep the reference
evaluator authoritative; add transactional application-layer propagation
before introducing any durable index, and only after measured read cost
justifies that cache lifecycle.

# 19. Architecture Drift Rejections

Reject an implementation that does any of the following:

- [ ] Treats serialized `Plan` JSON as the new canonical storage after migration.
- [ ] Stores PlanNode only as a nested field of Plan.
- [ ] Introduces `PlanNodeWorkState` or a second lifecycle enum.
- [ ] Makes parent rollup counters part of PlanNode revision identity.
- [ ] Requires a full descendant scan every time top-level status is read.
- [ ] Defines rollup semantics only inside SQLite trigger SQL.
- [ ] Makes generic foundation store crates depend on `scriberig-session` plan types.
- [ ] Copies validation/result payloads into opaque evidence strings instead of referencing exact semantic objects.
- [ ] Treats gates and dependencies as the same relation.
- [ ] Treats failed node as permanently terminal.
- [ ] Deletes failed attempt provenance during retry.
- [ ] Allows ignored/abandoned work to satisfy dependencies implicitly.
- [ ] Requires replan merely to append ordinary newly discovered work to a running plan.
- [ ] Lets TUI/web mutate plan state directly.
- [ ] Implements new TUI plan widgets against the superseded local Ratatui shell instead of task 148/upstream components.

Every item above must remain unchecked because each describes forbidden behavior.
