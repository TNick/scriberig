# Implement Headless Editor-Core Primitives

## Objective

Implement `@scriberig/editor-core` as the framework-independent interaction layer for semantic selection, knowledge-tree navigation, commands, history, diffs, branches, migration review, and projection coordination.

This package contains behavior and state transitions only. It must not render JSX and must not depend on React or MUI.

Read before editing:

1. `design/level-1/010. universal query and operation model.md`
2. `design/level-1/012. web platform and integrated editor.md`
3. `design/level-2/001. web workspace packages and integrated editor.md`
4. `design/level-3/004. implement client semantic model and incremental events.md`

Prerequisite: `@scriberig/model` compiles and exposes framework-independent subscriptions/state access.

## Universal Selection

Implement one semantic selection type/model capable of representing:

```text
entity
optional exact revision
snapshot
optional relation/path context
optional projection location
```

Requirements:

- support current-resolution selection and exact historical selection;
- preserve snapshot identity;
- allow projection views to attach location metadata without changing semantic identity;
- support equality/comparison helpers based on semantic meaning;
- avoid file-path/line-number assumptions in the core representation.

Selection is local interaction state, not canonical knowledge.

---

## Selection Controller

Implement a small controller/state object for active selection.

It must support:

- get current selection;
- set/clear selection;
- subscribe/unsubscribe;
- update projection/path context while retaining semantic entity where appropriate;
- preserve historical exact revisions when current snapshot advances.

Do not couple selection to browser URL routing in this package.

---

## Command Model

Implement a command descriptor model with at least:

```text
id
title
read-only or mutating classification
applicability predicate/capability requirements
execute descriptor or operation factory
optional keyboard/menu metadata
optional domain metadata
```

Commands must resolve to public application/client operations, not frontend-only database mutations.

Implement command discovery given:

- current semantic selection;
- server/client capability set;
- registered domain extensions.

The same command descriptor must be usable later from palettes, menus, buttons, and agent-oriented action surfaces.

Do not embed JSX or MUI icons in the core descriptor. Use semantic icon keys/metadata if necessary.

---

## Knowledge Tree

Implement a headless expandable semantic tree controller.

It must support:

- a root semantic reference;
- lazy child loading by relation/collection;
- expand/collapse;
- loading/error state per node;
- child counts or summary metadata where supplied;
- stable semantic node handles;
- selection integration;
- pagination/cursor continuation for large child sets;
- refreshing a loaded branch when current resolution changes.

It must not recursively load all descendants.

The controller should work for raw knowledge, domain trees, sessions, PDFs, and other relation-driven structures.

---

## Navigation

Implement reusable navigation state for semantic history such as:

```text
back
forward
open selection
reveal related entity
```

Navigation entries must preserve enough snapshot/revision context to revisit exact historical state.

Do not assume URL routing or one fixed panel layout.

---

## History and Diff Controllers

Provide headless coordination models for:

- loading entity/snapshot history;
- selecting two comparable revisions/snapshots;
- requesting semantic diff;
- tracking raw/projection diff availability when provided;
- navigating changed semantic entities.

Do not implement visual diff rendering here.

---

## Branch Navigation

Provide a controller/model for session/project branches that can:

- list child branches lazily;
- expose branch description/purpose/outcome;
- select/open a branch;
- resolve result references such as migrations or snapshots;
- preserve branch semantic identity independently of chat transcript rendering.

---

## Migration Review

Implement local review state around a protocol migration proposal/detail.

It should support:

- current proposal/base snapshot;
- list of affected semantic objects;
- selected change;
- validation status reference;
- stale/conflict state;
- accept/apply command creation through the public client operation;
- reject/close local review without mutating canonical state.

Do not directly apply database updates.

---

## Projection Session

Implement reusable state for coordinating a semantic object with a projection editor/view.

It should carry:

- semantic selection;
- projection identity;
- snapshot/base state;
- candidate/draft state when present;
- semantic location mapping when available;
- stale/conflict markers.

Do not implement Monaco, CodeMirror, PDF rendering, or Markdown editing in this task.

---

## Domain Extension Registry

Implement a minimal public extension registry supporting descriptors for:

- inspectors;
- projection handlers;
- diff handlers;
- relation views;
- command providers;
- labels/icons metadata;
- validation presentation metadata.

The registry stores descriptors/handlers, not React components in the core package. React/component packages may interpret view keys or adapters later.

Keep the API small and typed.

---

## Tests

Required tests:

1. one selection can retain entity identity while projection location changes;
2. historical exact selection does not silently resolve to a newer revision;
3. command discovery filters by capabilities and applicability;
4. knowledge tree loads only expanded children;
5. pagination adds children without losing stable node state;
6. navigation back/forward preserves snapshot context;
7. migration review exposes stale/conflict state without mutating canonical model;
8. extension registration cannot overwrite an existing extension silently unless explicitly allowed.

Use fake model/client objects.
