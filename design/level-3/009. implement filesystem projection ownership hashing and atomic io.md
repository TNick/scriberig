# Implement: Filesystem Projection Ownership, Hashing, and Atomic IO

## Objective

Implement the low-level filesystem primitives required by managed file projections without adding watcher integration or domain parsing yet.

This task establishes explicit ownership, normalized locations, exact-byte hashing, and safe writes in `sr-projection-fs`.

## `location.rs`

Define a filesystem projection location type around a path.

Requirements:

- path is not a semantic `EntityId`;
- preserve enough information to access the exact file;
- define normalization/comparison behavior explicitly and conservatively;
- avoid canonicalizing through filesystem IO as part of ordinary equality if it would make missing paths impossible to represent;
- expose path accessors without leaking platform-specific watcher types.

Add tests for relative/absolute handling according to the chosen project-root policy.

## `ownership.rs`

Implement:

```text
ManagedEditable
ManagedReadOnly
Unmanaged
ImportedExternal
```

Represent ownership separately from existence/dirty state.

Add helpers answering at least:

- Scriberig may render/write this file;
- external changes may be imported;
- Scriberig must never rewrite it automatically.

`Unmanaged` must always reject automatic write/import ownership operations.

## `hash.rs`

Implement exact-byte digesting for file content and rendered output.

Requirements:

- reuse project-standard digest/hash implementation if available;
- hash exact bytes for the initial design;
- expose a strongly typed file-content digest if appropriate;
- support hashing bytes already in memory and file contents read from disk;
- errors are returned, not panicked.

Add tests proving byte differences, including newline/spacing changes, change the file digest even though later domain reconciliation may find no semantic change.

## `io.rs`

Implement a small filesystem IO abstraction used by synchronization code.

It must support:

```text
read(path) -> exact bytes
metadata/existence(path)
write_atomic(path, bytes)
remove/rename inspection helpers only if needed by later sync code
```

Provide a concrete local-filesystem implementation and a trait/interface that tests can replace if useful.

### Atomic write behavior

For `write_atomic`:

1. create a temporary sibling file where practical;
2. write all bytes;
3. flush/close as required for correctness of the chosen guarantee;
4. replace target atomically where supported;
5. clean up failed temporary artifacts best-effort;
6. return the digest of exact bytes known to have been written or enough data for the caller to compute/verify it.

Do not claim stronger crash-durability guarantees than implemented. The requirement is to avoid exposing half-written projection content during a normal process write.

Preserve reasonable file permissions where the implementation can do so safely; document limitations in code comments/tests rather than inventing a complex permission system here.

## `state.rs`

Add the filesystem-facing runtime sync-state value needed by later tasks.

It should be able to carry:

- projection/spec reference;
- location;
- ownership;
- last synchronized snapshot/base reference;
- last rendered digest;
- optional last observed digest;
- projection lifecycle state from `sr-projection`;
- adapter/style/renderer exact references needed to interpret the base.

Do not implement persistence backend tables in this task. Make the state serializable only if the workspace already has a standard serialization dependency and doing so does not couple it to a concrete backend.

## Tests

Using a temporary directory, cover:

- atomic write creates expected exact bytes;
- returned/computed digest matches file bytes;
- subsequent replacement produces the new exact bytes;
- failed target path returns a structured error;
- unmanaged ownership denies automatic writes through any high-level helper added here;
- exact-byte formatting changes change digest;
- semantic IDs are not derived from path text.
