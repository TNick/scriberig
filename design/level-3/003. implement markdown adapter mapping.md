# Implement Markdown Adapter Mapping

## Objective

Implement the Markdown adapter boundary that maps between Markdown text and the canonical Markdown domain schema defined by the previous Level 3 task.

The adapter must produce and consume universal graph/domain objects. It must not create an alternate Markdown persistence model.

This task covers parsing/import mapping and deterministic semantic rendering at the domain boundary. It does not own filesystem watching, projection synchronization orchestration, or generic migration storage.

Read before editing:

1. `design/level-1/006. projections and bidirectional editing.md`
2. `design/level-1/007. domain modeling and adapters.md`
3. `design/level-3/002. implement markdown domain schema.md`
4. the current public APIs of `scriberig-projection`, `scriberig-migration`, `scriberig-graph`, and `scriberig-schema`


Add tests under:

```text
tests/parse_render.rs
```

If the repository already uses another module organization for adapters, follow that established organization while preserving the responsibilities in this task.

## Parser Dependency

Choose one mature Rust CommonMark/Markdown parser that can expose enough structural information to construct the canonical entities from Task 002.

Prefer an existing workspace dependency if one has already been selected elsewhere. Do not introduce two Markdown parser libraries.

Record the parser choice in the crate manifest and crate-level documentation. Parser-specific syntax nodes must remain inside the adapter implementation and must not leak into the universal graph API.

---

## Parse to Semantic Structure

Implement parsing that can construct at least the first-slice entities:

```text
MarkdownDocument
Section
Heading
Paragraph
List
ListItem
Table
TableRow
TableCell
CodeBlock
QuoteBlock
Link
ImageReference
InlineContent
```

The parser must preserve semantic document order.

Headings must establish section hierarchy rather than being exposed only as flat tokens.

Paragraphs, list items, table rows, and table cells must become semantic objects through the shared graph/domain APIs.

Do not store the parser's entire private AST as canonical state unless a field is needed for faithful semantic round-trip behavior.

---

## Source Coordinates

If the chosen parser exposes byte ranges or source spans, preserve them only as adapter/projection metadata for diagnostics and external-coordinate mapping.

Do not use byte offsets as entity identity.

A semantic object must remain meaningful even if unrelated text is inserted earlier in the file.

---

## Rendering

Implement deterministic rendering from canonical Markdown domain state to Markdown text.

Rendering must:

- preserve semantic ordering;
- emit valid Markdown for the supported first-slice entities;
- avoid reading private persistence tables directly;
- operate through graph/schema/domain APIs;
- keep presentation-only decisions localized to rendering rather than writing them back into semantic state.

Use a simple deterministic default style. Do not build a full style system in this task unless `scriberig-projection` already exposes the required style abstraction.

The same semantic input under the same renderer configuration must produce byte-identical output.

---

## Adapter API

Expose a small public adapter surface consistent with shared projection/domain abstractions.

The public API must make these operations possible without agent code:

```text
parse/import Markdown text -> semantic candidate/domain data
render semantic Markdown scope -> Markdown text
```

If `scriberig-projection` already defines adapter traits, implement them instead of defining Markdown-specific competing traits.

If prerequisite traits do not yet exist, expose narrow functions in the Markdown crate and document the future integration point. Do not redesign the projection framework in this task.

---

## Semantic Mapping Rules

At minimum:

- heading level determines section nesting;
- paragraphs remain independently addressable;
- list item order is canonical;
- table row and cell order is canonical;
- code block language/info string is preserved where available;
- link target and visible content are preserved;
- image target and descriptive text are preserved;
- formatting-only whitespace is not promoted to canonical semantic state.

Unsupported syntax must return an explicit adapter error or preserve a safe fallback representation if the shared schema already defines one. Do not silently drop content.

---

## Tests

Create fixtures covering:

```text
nested headings
multiple paragraphs
ordered and unordered lists
tables
code blocks
quotes
links
images
mixed document structure
```

Test:

1. parsing produces the expected semantic hierarchy;
2. semantic order is preserved;
3. paragraphs/rows/cells are separate objects;
4. parse -> render -> parse preserves equivalent semantic structure;
5. deterministic rendering returns identical bytes on repeated calls;
6. formatting-only differences do not require different semantic meaning where the schema classifies them as projection-only;
7. source coordinates, if present, are metadata rather than IDs.

Run:

```text
cargo fmt --all -- --check
cargo test -p scriberig-domain-markdown
cargo clippy -p scriberig-domain-markdown --all-targets -- -D warnings
```

---

## Do Not Do

- Do not implement filesystem watching.
- Do not implement the generic projection record store.
- Do not implement three-way merge orchestration.
- Do not call an LLM for parsing or mapping.
- Do not create Markdown-specific database tables.
- Do not expose parser-library AST types through public universal APIs.
- Do not silently discard unsupported source content.
- Do not implement agent tools or UI components.

---

## Completion Checklist

- [ ] Markdown source parses into the canonical domain schema.
- [ ] Section hierarchy is semantic, not only flat heading tokens.
- [ ] Paragraphs, rows, cells, and list items remain separately addressable.
- [ ] Rendering is deterministic.
- [ ] Supported parse/render round trips preserve semantic structure.
- [ ] Parser-specific details stay inside the adapter.
- [ ] Source coordinates do not become semantic identity.
- [ ] No alternate persistence model exists.
- [ ] Tests, formatting, and clippy pass.
