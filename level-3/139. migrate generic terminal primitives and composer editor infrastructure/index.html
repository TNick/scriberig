    Migrate Generic Terminal Primitives and Composer/Editor Infrastructure¶

    Status: [x] Complete

    1. Objective¶

    Continue design/level-2/031. rpi tui adoption and shared presentation migration plan.md after task 138 is complete.

    Replace locally maintained commodity terminal behavior with the pinned rpi-tui-backed scriberig-tui-kit facade while preserving the existing Scriberig TUI state machine and semantic contracts.

    This task migrates generic primitives only:

    • normalized terminal input;
    • editor/composer behavior;
    • safe text/Markdown rendering primitives;
    • generic selection/search helpers;
    • theme/style primitives;
    • width/wrapping helpers;
    • terminal capability policy plumbing.

    It does not yet replace the recursive conversation renderer or all auxiliary screens. Those are tasks 140 and 141.

    Do not begin task 140 until this sheet is complete.

    2.3 Architectural prohibitions¶

    Do not:

    • move semantic effects into upstream components;
    • replace TuiState with an upstream application/session state;
    • replace Scriberig actions/effects with upstream agent commands;
    • make editor cursor/selection indexes become semantic continuation anchors;
    • add a second keymap with conflicting action meanings;
    • expose raw upstream text/control types directly to application/protocol crates;
    • invoke clipboard access during ordinary rendering;
    • change model-context construction because visual rendering changed;
    • rewrite task-134 product behavior in this primitive migration.

    4. Task A — Define the Translation Boundary¶

    scriberig-tui should consume Scriberig-owned facade types from scriberig-tui-kit, not scatter rpi_tui::* types through product code.

    Add only the adapters required for the migration.

    Conceptually:

    rpi-tui input            -> TuiKitInput -> current Scriberig input/action mapping
rpi-tui editor           -> TuiKitEditor -> composer state/action bridge
rpi-tui text/markdown    -> SafeUiLine/Segment -> current render adapter
rpi-tui selection helper -> TuiKitSelection -> stable caller-owned row identity
rpi-tui theme            -> TuiKitTheme -> Scriberig semantic style roles

    Exact type names should fit current code.

    Acceptance:

    • [x] Upstream types are contained at the kit/adapter boundary.
    • [x] Product code still maps user input to existing Scriberig action identifiers.
    • [x] Semantic/application crates do not gain terminal-kit dependencies.
    • [x] The adapter preserves enough information for key help and slash-command behavior.

    14. Implementation Notes¶

    The pinned upstream crate exposes editor and presentation components but no general terminal-event normalizer. Scriberig therefore retains its Crossterm-owned event decoder and action keymap, adding Home, End, and Delete translations for the shared composer editor. This keeps key help and slash command ownership in Scriberig while the kit owns editing, safe text and Markdown rendering, fuzzy selection mechanics, and semantic theme mapping.

    The persistent conversation composer now wraps the kit editor; cursor state remains presentation-only and the existing draft/action submission contract is preserved. Palette filtering uses the upstream fuzzy selector and returns stable action IDs after filtering. The old case-insensitive substring helper was removed after its production path was replaced.

    Focused verification passed: 15 tests in scriberig-tui-kit, 211 tests in scriberig-tui, cargo check -p scriberig-tui, and Clippy for both crates with warnings denied. Formatting passed with cargo fmt --all.
