    Pin, Vendor, and Wrap RPI TUI with Provenance and Dependency Isolation¶

    Status: [x] Complete

    1. Objective¶

    Implement the first slice of design/level-2/031. rpi tui adoption and shared presentation migration plan.md.

    This task does not replace the active Scriberig TUI yet. It establishes a reviewed, reproducible, isolated upstream intake and proves that generic rpi-tui primitives can be consumed without importing foreign agent/session semantics.

    The required outcome is:

    exact reviewed rpi-tui revision
        |
        v
provenance-preserving vendor boundary
        |
        v
scriberig-tui-kit generic facade
        |
        v
focused deterministic tests

    Do not begin task 139 until this sheet is complete and every checked item has verification evidence.

    2. Non-Negotiable Working Rules¶

    2.1 Read before editing¶

    Before changing code:

    • [x] Read root AGENTS.md completely.
    • [x] Read design/AGENTS.md completely.
    • [x] Read crates/scriberig-tui/AGENTS.md completely.
    • [x] Read the nearest AGENTS.md for every additional directory/crate modified.
    • [x] Read Level-1 documents 014, 015, and 022 completely.
    • [x] Read Level-2 documents 014, 021, 022, and 031 completely.
    • [x] Read Level-3 tasks 134 and 135 so the vendor intake does not redefine current session/TUI behavior.
    • [x] Inspect root workspace Cargo.toml, crates/scriberig-tui/Cargo.toml, current lockfile policy, LICENSES/, LICENSING.md, and THIRD_PARTY_NOTICES.md if present.
    • [x] Inspect the exact upstream bigfish1913/pi-rust revision before copying code.
    • [x] Search the repository for an existing third-party/vendor convention before creating a new one.

    2.2 Checklist discipline¶

    • [x] Keep this file open while implementing.
    • [x] Tick a checkbox only after that exact criterion is implemented and focused verification passes.
    • [x] Tick items immediately; never bulk-tick at the end.
    • [x] If later work invalidates a checked item, immediately return it to [ ].
    • [x] Add a short note below the affected task if current repository/upstream reality requires a materially different path than this sheet prescribes.
    • [x] Before setting this sheet to Complete, re-read every checked item against code, manifests, provenance files, and test output.

    2.3 Architectural prohibitions¶

    Do not:

    • add rpi-agent, rpi-harness, rpi-tools, rpi-extensions, or upstream provider/session crates;
    • map an upstream transcript/message/session identity onto Scriberig SessionId or BranchId;
    • add model/provider/tool execution to scriberig-tui-kit;
    • make the vendor tree depend on Scriberig semantic crates;
    • make Scriberig semantic/protocol types depend on rpi-tui types;
    • strip upstream license/copyright notices;
    • enable image terminal protocols as part of intake;
    • enable clipboard reads/writes without an explicit Scriberig-facing policy boundary;
    • ship two independently active Crossterm terminal runtimes;
    • silently copy only selected files without recording their exact upstream origin.

    Do not switch the active Scriberig runtime in this task.

    Acceptance:

The active Ratatui renderer remains unchanged in this task.
