    Implement Reference Integrated Editor¶

    Product-verification caveat (2026-10-12): The checked items in this document record completion of the historical reference-editor subsystem scope. They do not prove that the editor supports a useful end-to-end project workflow. Current product completion is governed by design/level-1/013. vertical product completion and end to end usability.md, design/level-2/025. first useful project workflow vertical slice.md, and Level-3 tasks 116-122. Do not cite this checklist as evidence that imported-project activation, named semantic navigation, editable source projection, validated migration review, filesystem write-back, or golden-path E2E are complete.

    Objective¶

    Implement the full Scriberig reference web application under web/apps/scriberig using only public web packages.

    The application must demonstrate that the public web platform is sufficient to build the complete editor described by Level 1. It combines low-level knowledge browsing, semantic/domain views, projections, history/diffs, sessions/agents, migrations, validation, and long-running operations around one shared semantic selection.

    Read before editing:

    1. design/level-1/012. web platform and integrated editor.md
    2. design/level-2/001. web workspace packages and integrated editor.md
    3. design/level-3/005. implement headless editor core primitives.md
    4. design/level-3/006. implement react bindings.md
    5. design/level-3/007. implement neutral reusable components.md
    6. design/level-3/008. implement material ui component package.md

    Prerequisites:

    • all public web packages compile;
    • the runtime/server exposes enough of the public protocol to connect the app;
    • if some server capability is not yet available, the app must show an explicit unsupported state rather than use a private workaround.

    The controlling rule is:

    If this application needs a private server call, direct database access, or private package import, fix the public abstraction instead of bypassing it.

    Do not create semantic logic in apps/scriberig that belongs in reusable packages.

    Runtime Composition¶

    runtime.ts creates the application runtime from public packages.

    It should construct/configure equivalents of:

    public transport
Scriberig client
WorkspaceModel
SelectionController
extension/command registry

    Configuration such as API base URL and authentication provider must enter through application configuration/environment, not hard-coded source constants.

    The runtime should be injectable or replaceable enough for application tests.

    Application Provider Composition¶

    App.tsx should compose:

    • MUI theme/provider;
    • @scriberig/react provider;
    • application routing/shell;
    • one shared selection controller/runtime;
    • connection/snapshot status.

    Do not create a separate model/client instance per view.

    App Shell¶

    Create a simple, maintainable workbench layout.

    The first implementation does not need docking or persistent layouts.

    It should expose navigation to these main surfaces:

    Raw Knowledge
Semantic
Projection
History / Diff
Session / Agent
Operations
Migration Review when active

    A practical initial layout may use:

    • top application bar with current snapshot/connection state;
    • left navigation or semantic tree area;
    • central active view;
    • optional right inspector/agent area.

    The exact arrangement is less important than shared selection and public-package use.

    Universal Selection Integration¶

    All major views must consume the same SelectionController through @scriberig/react.

    Required behavior:

    • selecting an entity in Raw Knowledge updates Semantic and History views;
    • selecting an object in Semantic view updates inspector/agent scope;
    • selecting a mapped semantic region in Projection view updates global selection;
    • agent commands receive the active semantic selection;
    • migration review can highlight affected selected entities;
    • historical exact selection remains historical and is visibly marked.

    Do not translate selection into file path + line number as the primary internal representation.

    RawKnowledgeView¶

    Provide the low-level supported database/knowledge browser using public APIs.

    It must support progressively inspecting:

    • entities;
    • exact/current revisions;
    • typed properties/summary data;
    • relations/collections;
    • descriptions/provenance;
    • reverse references if public capability exists;
    • snapshot resolution;
    • migration lineage where available.

    Use reusable tree/inspector/relation components.

    Do not connect directly to SQLite or server-internal database endpoints.

    SemanticView¶

    Show the selected entity through domain-aware extensions where available.

    Fallback to the generic semantic inspector when no domain-specific view is registered.

    The view should support progressive disclosure rather than loading an entire project/domain graph.

    Examples that may later be supported through extensions:

    code module/function/code group
Markdown document/section/paragraph/table
PDF document/page/table/figure
session/branch/decision/task

    Do not hard-code each domain into the app shell if extension registration can supply it.

    ProjectionView¶

    Host the public projection component/handler for the active semantic selection.

    Display clearly:

    • projection identity;
    • snapshot/base identity;
    • read-only/editable capability;
    • stale/candidate/conflict state;
    • semantic mapping availability.

    When edits are supported, they must produce public semantic operations/migration proposals.

    Do not treat the browser text buffer as canonical state.

    HistoryView¶

    Provide entity and snapshot history around the current selection.

    Allow choosing two comparable states and render semantic diff through public components.

    Expose migration provenance and common-ancestor information when public capabilities provide it.

    Raw projection/text diff may be offered as an additional view but must not replace semantic diff where available.

    SessionAgentView¶

    Provide structured session and agent workbench functionality.

    It should expose:

    • current session/branch;
    • nested branches progressively;
    • branch description/purpose/outcome;
    • goals/decisions/tasks where available;
    • agent command input;
    • active semantic selection as structured scope;
    • durable agent operation state;
    • resulting branch/migration/validation/snapshot links;
    • optional chat/transcript projection.

    Sending a command must use the public agent operation and semantic scope.

    Do not manufacture source-line prompts when entity selection exists.

    OperationsView¶

    List and inspect known long-running operations independently of the initiating panels.

    Support at least:

    • operation type/status;
    • queued/running/completed/failed/cancelled states;
    • progress;
    • result references;
    • structured errors;
    • cancellation when capability permits.

    Closing another panel must not hide or cancel an active operation.

    MigrationReviewView¶

    Display an active migration proposal using the reusable MUI migration component.

    Support:

    • base snapshot;
    • affected objects;
    • semantic diff;
    • validation result;
    • stale/conflict state;
    • accept/apply when permitted;
    • close/reject local review.

    After successful application, update from public events/new snapshot rather than mutating the local canonical model manually.

    Snapshot and Connection Status¶

    SnapshotStatus.tsx must make visible whether the active view is:

    current
historical
branch/candidate
stale relative to current server state
offline/disconnected

    Do not hide stale/disconnected conditions behind generic toast messages only.

    Unsupported Capabilities¶

    The reference editor must remain usable against servers that expose only part of the eventual feature set.

    If a capability is unavailable:

    • disable/hide invalid commands through capability discovery;
    • display an explicit unsupported state when a user navigates to a required view;
    • do not use undocumented endpoints as fallback.

    Routing¶

    Use routes only for application-level navigation/bookmarking.

    Do not make route strings the semantic identity model.

    Where useful, routes may serialize stable semantic references, but SelectionController remains the application interaction source of truth.

    Public-Boundary Test¶

    Add a test/static check that scans application imports and fails if web/apps/scriberig/src imports:

    • private src/... paths of another workspace package;
    • Rust/server source paths;
    • database implementation paths;
    • undeclared deep package internals.

    The app may import only documented package exports and normal third-party libraries.

    Required Functional Tests¶

    At minimum use fakes/mocks through public package interfaces to verify:

    1. selecting an entity in RawKnowledgeView updates shared selection observed by SemanticView;
    2. historical selection produces historical snapshot status;
    3. agent command sends semantic selection/snapshot/session context;
    4. migration apply goes through public operation and waits for resulting state/event;
    5. an operation remains inspectable after the initiating view is unmounted;
    6. an unavailable capability produces an explicit unsupported state;
    7. no app view accesses a database/server-private API.

    Do not require a full live backend for these application composition tests.

    Required Checks¶

    Run:

    pnpm --filter @scriberig/app typecheck
pnpm --filter @scriberig/app test
pnpm --filter @scriberig/app build
pnpm typecheck
pnpm test
pnpm build

    The production Vite build must succeed.

    Do Not Do¶

    • Do not import database code.
    • Do not import server-internal Rust or TypeScript modules.
    • Do not deep-import another package's private source.
    • Do not reimplement semantic caches in the app.
    • Do not create a second selection system per panel.
    • Do not hard-code command lists that editor-core can discover.
    • Do not implement private mutation endpoints.
    • Do not make agent interaction only a chat transcript.
    • Do not implement sophisticated docking/layout persistence in the first version.
    • Do not add desktop-shell functionality in this task.

    Completion Checklist¶

    • [x] The reference app uses only public web packages for Scriberig behavior.
    • [x] The raw knowledge surface bootstraps a shared tree through public client APIs.
    • [x] Snapshot and connection state is visible for connecting, current, and disconnected states.
    • [x] The raw tree loads its first child page lazily and updates shared semantic selection.
    • [x] Unsupported or unimplemented product surfaces remain available without private fallbacks.
    • [x] Raw, semantic, projection, history, session/agent, operations, and migration-review surfaces are fully implemented.
    • [x] One semantic selection coordinates every integrated view.
    • [x] Agent commands use structured semantic scope.
    • [x] Web edits/migration acceptance use public operations.
    • [x] Long-running operations are independently inspectable.
    • [x] Public-boundary and cross-surface conformance tests pass.
    • [x] App and workspace checks pass from a clean repository state.

    The current implementation is the first connected browser vertical slice. The remaining unchecked items require later protocol/application capabilities and must not be represented as complete merely because placeholder views exist.
