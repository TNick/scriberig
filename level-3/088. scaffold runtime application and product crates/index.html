    Scaffold Runtime Application and Product Crates¶

    Objective¶

    Create the runtime-facing Rust crates prescribed by:

    1. design/level-1/011. runtime libraries protocol and product surfaces.md
    2. design/level-2/001. workspace and package layout.md
    3. design/level-2/011. application operations protocol and runtime boundaries.md

    This task is scaffolding only.

    Do not implement semantic operations, protocol payloads, HTTP routes, model-provider integration, or terminal UI behavior.

    The goal is to establish compileable package boundaries and enforce dependency direction before behavior is added.

    Prerequisite¶

    The foundational Rust workspace from design/level-3/001. initialize rust foundation workspace.md must already exist.

    If the repository does not yet contain a root Cargo.toml and the foundational crates, perform that prerequisite task first rather than inventing a competing workspace layout.

    Files to Create¶

    Create:

    crates/scriberig-app/Cargo.toml
crates/scriberig-app/src/lib.rs

crates/scriberig-protocol/Cargo.toml
crates/scriberig-protocol/src/lib.rs

crates/scriberig-client/Cargo.toml
crates/scriberig-client/src/lib.rs

crates/scriberig-agent-core/Cargo.toml
crates/scriberig-agent-core/src/lib.rs

crates/scriberig-agent-runtime/Cargo.toml
crates/scriberig-agent-runtime/src/lib.rs

crates/scriberig-server/Cargo.toml
crates/scriberig-server/src/lib.rs

crates/scriberig-tui/Cargo.toml
crates/scriberig-tui/src/lib.rs

crates/scriberig-cli/Cargo.toml
crates/scriberig-cli/src/lib.rs

apps/scriberig/Cargo.toml
apps/scriberig/src/main.rs

    Update the root Cargo.toml workspace member list to include all of the above packages.

    Do not create scriberig-conformance in this task.

    Package Names¶

    Use these Cargo package names exactly:

    scriberig-app
scriberig-protocol
scriberig-client
scriberig-agent-core
scriberig-agent-runtime
scriberig-server
scriberig-tui
scriberig-cli
scriberig

    The final package under apps/scriberig produces the scriberig executable.

    Use workspace version and edition values already defined by the repository.

    Dependency Edges¶

    Add only architecture-level dependencies needed to establish the intended direction.

    Use workspace-local path dependencies.

    Required directions:

    scriberig-app
├── scriberig-core
├── scriberig-graph
├── scriberig-query
├── scriberig-migration
├── scriberig-projection
└── scriberig-session

scriberig-protocol
└── scriberig-core

scriberig-client
└── scriberig-protocol

scriberig-agent-core
├── scriberig-app
└── scriberig-session

scriberig-agent-runtime
└── scriberig-agent-core

scriberig-server
├── scriberig-app
└── scriberig-protocol

scriberig-tui
└── scriberig-app

scriberig-cli
├── scriberig-app
├── scriberig-server
├── scriberig-tui
└── scriberig-agent-runtime

scriberig executable
└── scriberig-cli

    Do not add reverse dependencies from any foundational crate.

    Do not add a dependency from scriberig-protocol to scriberig-app.

    Do not add a dependency from scriberig-client to scriberig-server.

    Initial Source Content¶

    Each lib.rs should contain crate-level documentation describing its responsibility and architectural restrictions.

    Do not create placeholder public APIs simply to populate the crate.

    The descriptions must state:

    • scriberig-app: shared user-visible application operations;
    • scriberig-protocol: public transport-neutral wire contract;
    • scriberig-client: reusable remote client over the protocol;
    • scriberig-agent-core: reusable agent-facing adapters over application/session operations;
    • scriberig-agent-runtime: integrated model/tool-loop orchestration;
    • scriberig-server: transport host adapting protocol requests to application operations;
    • scriberig-tui: terminal presentation over public operations;
    • scriberig-cli: command parsing and mode dispatch only.

    apps/scriberig/src/main.rs should compile and contain the smallest possible entry point. Do not invent commands in this task.

    No Product Logic Yet¶

    Do not add:

    • HTTP frameworks;
    • async runtimes unless already required by the workspace;
    • serde solely for future protocol work;
    • model SDKs;
    • TUI frameworks;
    • CLI parser frameworks;
    • database drivers;
    • domain parsers;
    • fake operation enums;
    • placeholder server routes.

    Those belong to focused tasks.

    Required Checks¶

    Run:

    cargo fmt --all -- --check
cargo check --workspace
cargo clippy --workspace --all-targets -- -D warnings

    All must pass.

    Also inspect the manifests manually to verify there is no dependency cycle and no foundational crate imports a runtime/product crate.

    Completion Checklist¶

    • [ ] All eight runtime library crates exist.
    • [ ] apps/scriberig exists and builds an executable.
    • [ ] Root workspace includes the new members.
    • [ ] Package names match this task exactly.
    • [ ] Dependency direction matches the prescribed graph.
    • [ ] scriberig-protocol does not depend on scriberig-app.
    • [ ] scriberig-client does not depend on scriberig-server.
    • [ ] Foundation/domain crates do not depend on product crates.
    • [ ] Source files contain documentation only, not speculative APIs.
    • [ ] Formatting, check, and Clippy all pass.
