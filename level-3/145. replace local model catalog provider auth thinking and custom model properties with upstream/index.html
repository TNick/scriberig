    4. Preserve ScribeRig Assignment, Remove ScribeRig Catalog Authority¶

    ScribeRig still owns the fact that one semantic execution location has one configured execution selection.

    Examples:

    branch -> execution selection
plan node -> execution selection
session default -> execution selection
agent profile preference -> execution selection
historical invocation -> resolved execution provenance

    But ScribeRig must no longer decide what models exist or what capabilities/properties they expose.

    Acceptance:

    • [x] Branch/plan assignment identity remains stable and ScribeRig-owned.
    • [x] Assignment resolution reads upstream catalog/runtime state.
    • [x] No branch/plan/session code depends on a ScribeRig-owned list of model capabilities.
    • [x] Historical assignment remains inspectable if the live upstream catalog later changes.

    provider public ID
model public ID

    That record is provenance, not a live catalog.

    6. Delegate Thinking-Level Semantics Completely¶

    Upstream owns thinking-level support, ordering, mapping, clamping, and provider serialization.

    ScribeRig must not maintain a separate support table or validation list.

    Required behavior:

    selected model changes
  -> supported levels come from upstream model
  -> currently requested level is accepted/clamped/rejected according to upstream
  -> provider request receives upstream-mapped value

    ScribeRig may persist the user-selected or resolved public level as execution configuration/provenance, but does not interpret its provider meaning.

    Acceptance:

    • [x] Supported thinking values come from upstream API.
    • [x] Thinking-level mapping to provider effort comes from upstream.
    • [x] Unsupported-level fallback/clamping comes from upstream.
    • [x] TUI/web protocol projection does not invent an independent thinking enum/catalog.
    • [ ] Trusted app model rows carry upstream rpi_ai::ThinkingLevel values directly, and protocol/web rows expose only ordered scalar level IDs; focused Rust and TypeScript projection tests pass.
    • [ ] A model switch test proves levels update from the new model's upstream metadata.

    The native path carries the exact upstream Model and typed effective ThinkingLevel from selection through UpstreamBranchInvocation to AgentBuilder::thinking_level and SimpleStreamOptions.reasoning. Provider crates own model-specific effort mapping and serialization. Durable request provenance converts the enum to its canonical scalar ID only at the projection boundary. Protocol projection and model-switch coverage remain unchecked.

    7. Delegate Custom Model Properties¶

    Use upstream model/provider metadata for custom and model-specific properties.

    This includes current/future upstream equivalents of:

    sampling parameters
reasoning maps
compatibility flags
strict-tool support
model input modalities
context window
max output
cost metadata
provider endpoint/public metadata
provider-specific request-shaping values
custom property maps

    Do not introduce a ScribeRig enum/schema for these fields.

    The provider credential boundary is separate from model properties. The host selects one ScribeRig SecretRef, authorizes it for the exact upstream model endpoint, and supplies it through RequestSecret using upstream's HostSelected resolver. The ScribeRig path does not invoke upstream's provider-keyed CLI/auth-store/environment precedence. Catalog credential and header fields are rejected by the native loader, and the host readiness adapter projects only upstream's source category while dropping material. Upstream does not need a ScribeRig-specific per-model credential-reference schema: that reference selection and destination authorization are ScribeRig host policy. Auth-success status and refresh after credential/provider changes are still not available, so §8 auth-status/readiness acceptance remains unchecked. The fork's ModelCatalogEvent and ModelCatalog::subscribe notify consumers only after model-row or provider-order changes; refresh_from_configuration is an explicit caller operation and does not watch configuration sources. The CLI's separate ModelRegistryEvent::AuthStatusChanged and AuthStatus are CLI-owned compatibility metadata, and the status setter has no production callsites. ScribeRig readiness is recomputed on each query from the latest shared catalog snapshot and its authorized credential provider. That provider re-reads live user/system policy and the selected secret source, but ScribeRig currently has no in-process provider-auth mutation or catalog-file reload path that could request a new projection after an external change. A generic upstream auth event cannot identify or observe ScribeRig SecretRef or destination policy; adding an event without a host change source and subscriber would not close this lifecycle gap. Keep auth-status and hot-refresh criteria unchecked until ScribeRig defines an authorized live change operation and wires it to refresh the shared catalog/readiness projection.
