    Rebuild ScribeRig Semantic Session, Plan, and Review Surfaces as Upstream TUI Components¶

    Status: [ ] In Progress

    Current dependency note (2026-10-21, late revalidation): ScribeRig pins controlled fork commit ebcf8d5e75d20fa3a6cc7cc76cbcdcec4cc36eb8, based on official upstream 0.7.1 main 281dfddfa39ac063d86de57b75370974c4d75e6c. The merged upstream changes do not alter the rpi-tui component APIs used by these semantic surfaces. The pin adds public key-type reexports, tree row caching, TreeList::{items,replace_items}, host tick callbacks, and theme metadata. Earlier checks passed at an older pin; visible and behavior acceptance remains open.

    1. Objective¶

    After task 147 makes upstream rpi-tui the active terminal product framework, port the Scriberig-specific terminal surfaces onto upstream component/layout/focus/overlay/scroll/theme contracts.

    These views remain Scriberig-specific because their data and interaction semantics depend on Scriberig architecture. Their terminal implementation must nevertheless be entirely on top of upstream UI primitives.

    Do not begin task 149 until this sheet is complete.

    TreeList and SelectList integration (2026-10-21): this audit was initially performed at fork commit 3f3a0b2db91eb87f5c5b68485b1c4c3394a240a9 and rechecked against the previous active pin 6e65635a2ac2336a86847d85e2c3bb771a945c87. The active pin descends from 15a68ef2d69a312122c09c1eccfa0fbd454c48b5, which adds application-registered keybindings with shared help/footer enumeration, and merges official upstream pi-rust 0.7.1. The rpi-tui component APIs used by these semantic views remain available at the active pin: semantic_views.rs composes the adapter from semantic_views/tree.rs, semantic_views/selection.rs, and semantic_views/details.rs. The tree module builds rpi_tui::TreeList items from the already-filtered ScribeRig ConversationModel.rows and SessionModel.rows. Namespaced stable source IDs map selection back to ScribeRig conversation identity or the existing session cursor. Session selection is retained as SessionRowIdentity (row kind plus semantic reference) in TuiState.session_cursor; an authoritative session refresh resolves that identity into the new row order before updating the numeric reducer cursor. Pending branch focus takes precedence, and missing rows fall back to the first available session row rather than activating whichever row inherited the old index. Up/Down movement is applied by TreeList, then forwarded through the ScribeRig cursor reducer, which updates both the numeric cursor and stable row identity. The ScribeRig projection and reducer remain the sole owners of expanded_branches; TreeList expands only rows present in the projection. The selection module builds upstream SelectList items for ready Explorer, History, Find, Diff, and Operations projections. Their source IDs derive from semantic row references, and Up/Down is forwarded as the existing cursor action; Enter remains the existing Activated action. TuiState.semantic_row_cursor retains typed identities for these views. Authoritative refreshes resolve the identity into the new row order before updating the numeric reducer cursor; missing rows fall back to the nearest valid position. The details module supplies bounded selected-row/context content to upstream Markdown. Overview and Projection remain Markdown because each presents one selected entity/document rather than a selectable row set. Changes remains Markdown because its cursor spans validation detail rows while activation confirms the current candidate as a whole. These adapters compiled, but no tests were run and Task 148 acceptance items remain unchecked pending behavioral verification.

    Reusable TreeList updates (2026-10-21, uncommitted upstream worktree): the controlled fork branch codex/scriberig-upstream-ownership now carries TreeList::items() and TreeList::replace_items(Vec<TreeItem>) in crates/rpi-tui/src/tree_list.rs. replace_items validates the complete item set first (unique non-empty IDs, resolved parents, acyclic depth); keeps selection when the selected ID survives and falls back to the first new item when it is removed (clearing selection for an empty set); keeps expansion only for surviving parents with children and expands newly added parents; and rebuilds item/child/depth indexes plus cached visible rows and viewport bounds. Invalid replacement leaves the previous items and selection unchanged. ScribeRig retains one Mutex<Option<TreeList>> in crates/scriberig-tui/src/runtime/upstream/semantic_views.rs and only calls replace_items when projected TreeItem values change. semantic_views/projection.rs owns TreeProjection, initial expansion, reuse, and selection synchronization; semantic_views/tree.rs::projection and semantic_views/plan.rs::projection produce items/selection/details without constructing a component. handle_tree_movement moves the retained tree and derives the semantic direction from projected item order instead of building a temporary tree per keypress. Plan rows still take parent_id only from PlanNodeParent; PlanDependency edges remain Markdown detail rows, so the dependency DAG is not folded into tree parentage.

    Remaining gaps: the update API exists only in the upstream working tree, not a committed/pinned fork revision; the Cargo pin remains bad1c5b4aa6f26cc231168d75a09165e990de39a and was not changed. No compile/test/PTY verification was run, so the upstream contribution and the ScribeRig reuse path remain unverified. The §6 acceptance items for stable row identity, independent dependency edges, reply-anchor behavior, and upstream tree navigation remain unchecked pending that verification.

    Acceptance:

    • [ ] Any plugin-supplied terminal panel support is upstream-owned or explicitly blocked pending upstream work.

    Use upstream viewport/scroll/virtualization primitives. If missing, contribute a generic upstream primitive.

    • [ ] Clipboard/image behavior follows upstream product policy and Scriberig capability policy.

    21. Implementation Notes¶

    Record which upstream components each Scriberig semantic surface uses and any upstream generic UI contributions required during the port.

    The active PrimaryView renders its ScribeRig-owned semantic read models through upstream components in crates/scriberig-tui/src/runtime/upstream/semantic_views.rs and its focused modules. Conversation and Session use rpi_tui::TreeList; ready Explorer, History, Find, Diff, and Operations rows use rpi_tui::SelectList; supplementary details and single-document/single-entity views use rpi_tui::Markdown. Values are terminal-sanitized, Markdown-escaped, bounded per value, and row-bounded. The conversation view keeps the recursive session projection and separately renders durable plan status, structural parents, execution assignments, BranchResult identities, coordinator state, and explicit dependency edges from the canonical session snapshot. Prompt detail and safe activity summaries follow the existing presentation visibility settings. Candidate confirmation now displays and validates the exact result snapshot against the current review alongside its base snapshot before it issues the shared commit intent. The upstream command palette reaches conversation, overview, semantic explorer, find, history, diff, projection, candidate review, session, and operation views. Choosing the semantic explorer sets the ScribeRig presentation focus and resets its cursor; the upstream composer routes F7 browse mode's Up/Down/Enter actions through the ScribeRig reducer, and Escape returns to editing. In the recursive conversation view, F7 also enters ScribeRig conversation-browse mode, Enter pins the selected reply cursor through ConversationPinCursor, and Left/Right toggles the selected branch's presentation expansion through ConversationToggleExpansion. These actions retain stable semantic identity and remain independent of the plan coordinator cursor. The ScribeRig cursor reducer remains the identity and activation owner: upstream row movement is translated to its existing cursor action, and Enter is still reduced as ScribeRig Activated. List selection uses typed stable semantic identities across authoritative refreshes; session selection uses SessionRowIdentity to survive authoritative row reorder. Overview and Projection are single-document/single-entity views, and Changes activation confirms the candidate as a whole, so these remain Markdown. This remains incomplete: stable identity activation for every row, all view-specific actions, richer focus/layout behavior, PTY scenarios, and behavioral verification remain outstanding. Task 147's visible PTY gate also remains unchecked; no tests were run.

    Plan projection (2026-10-21): the dedicated Plans view uses upstream rpi_tui::TreeList for plan and structural plan-node rows, plus upstream Markdown for the selected plan/node details. PlanSelection retains the stable (plan, optional node) identity separately from the conversation cursor and coordinator_cursor. Tree parent IDs come only from PlanNodeParent; dependency edges remain explicit PlanDependency values rendered as edge rows in the details section, including their fulfilled_by result. Node detail shows lifecycle status, branch, BranchResult, safe model assignment, worker claim, and expected result. The existing /plan lifecycle and /assign commands still issue shared application effects; from the Plans view they resolve their target from PlanSelection instead of changing the conversation or coordinator cursor. The available upstream TreeList and Markdown APIs cover this read-only view; no ScribeRig generic graph or widget framework was added. Upstream TreeList models structural hierarchy but does not provide a reusable dependency-DAG graph component. The current view exposes canonical edges through upstream Markdown; any graphical DAG component should be contributed to rpi-tui before ScribeRig adopts it. Focused projection tests were added and compiled with cargo check --offline -p scriberig-tui --tests; the tests were not executed. The task remains incomplete pending behavioral execution and interactive verification.

    Adapter audit (2026-10-21): ScribeRig semantic views use upstream TreeList, SelectList, and Markdown; status uses upstream FooterComponent; property editing uses upstream PropertyEditor and Editor; confirmations use upstream Dialog; and overlays/lifecycle use TuiAltScreen. SemanticViewPanel is retained because it projects canonical session/plan/semantic identities into upstream rows and maps navigation back to ScribeRig reducer actions.
