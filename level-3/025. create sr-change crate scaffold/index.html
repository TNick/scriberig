    Agent Task: Create the sr-change Crate Scaffold¶

    Goal¶

    Create the backend-independent Rust crate prescribed by design/level-2/002. change history and merge crate design.md and wire it into the workspace without implementing domain behavior yet.

    This task is complete only when the workspace compiles with the new crate and every prescribed module exists.

    Read before editing¶

    Read these files in order:

    1. design/level-1/003. identity revisions and snapshots.md
    2. design/level-1/004. persistence and storage model.md
    3. design/level-1/005. changes migrations branches and merge.md
    4. design/level-2/001. persistence crate boundaries.md
    5. design/level-2/002. change history and merge crate design.md

    Do not reinterpret the identity model. EntityId, RevisionId, and SnapshotId come from sr-core.

    Prerequisite check¶

    Before changing files, verify that the workspace and these crates exist:

    Cargo.toml
crates/sr-core/
crates/sr-store/

    If they do not exist, do not create replacement versions from this task. Stop and report that the persistence foundation must be implemented first from its own Level 3 tasks.

    Files to create¶

    Create exactly these initial files if they do not exist:

    crates/sr-change/Cargo.toml
crates/sr-change/src/lib.rs
crates/sr-change/src/migration.rs
crates/sr-change/src/operation.rs
crates/sr-change/src/provenance.rs
crates/sr-change/src/history.rs
crates/sr-change/src/branch.rs
crates/sr-change/src/workspace.rs
crates/sr-change/src/promotion.rs
crates/sr-change/src/diff.rs
crates/sr-change/src/conflict.rs
crates/sr-change/src/merge.rs
crates/sr-change/src/rebase.rs
crates/sr-change/src/query.rs
crates/sr-change/src/summary.rs
crates/sr-change/tests/change_conformance.rs

    Also update the root Cargo.toml workspace members to include crates/sr-change.

    Cargo.toml¶

    Use the repository's existing workspace package metadata and dependency style.

    The crate must depend only on libraries needed for the backend-independent change model.

    Required internal dependencies:

    sr-core
sr-store

    Do not add dependencies on:

    • sr-store-memory;
    • sr-store-sqlite;
    • agent crates;
    • CLI/server crates;
    • domain adapters.

    Dev-dependencies may use sr-store-memory for conformance tests when that crate is available.

    lib.rs¶

    Declare all prescribed modules.

    Expose the main public types from their owning modules only when doing so follows the repository's existing public-API style. Avoid creating a large prelude in this task.

    The crate-level documentation should state three rules:

    1. snapshots and revisions are immutable;
    2. change is represented as transitions between snapshots;
    3. the crate is backend- and domain-independent.

    Module responsibility comments¶

    Each module should contain a short module-level documentation comment stating its responsibility:

    • migration: exact snapshot transitions and entity deltas;
    • operation: generic and domain-extensible semantic operations;
    • provenance: source and provenance metadata;
    • history: explicit change-history topology;
    • branch: branch metadata and branch references;
    • workspace: isolated speculative work;
    • promotion: optimistic named-root advancement;
    • diff: comparison of exact snapshots;
    • conflict: structured semantic conflicts;
    • merge: three-way merge orchestration;
    • rebase: replay against a new base;
    • query: history/change queries;
    • summary: compact structural summaries.

    Do not implement algorithms in this scaffold task.

    Conformance test placeholder¶

    tests/change_conformance.rs should compile and contain a module-level comment listing the cases prescribed by Level 2.

    Do not add ignored failing tests merely to reserve names. Add real tests only when the relevant implementation task is completed.

    Constraints¶

    • Do not define duplicate EntityId, RevisionId, or SnapshotId types.
    • Do not issue SQL.
    • Do not depend on a concrete store backend from library code.
    • Do not add Markdown-, Rust-, PDF-, or session-specific change variants.
    • Do not create agent APIs.
    • Do not modify Level 1 or Level 2 documents.
    • Do not add speculative abstractions not needed by the prescribed module boundaries.

    Verification¶

    Run the repository's normal formatter and checks. At minimum:

    cargo fmt --check
cargo check --workspace
cargo test --workspace

    If the repository uses additional standard checks, run them too.

    Completion checklist¶

    • [x] crates/sr-change exists.
    • [x] Root workspace includes the crate.
    • [x] sr-change depends on scriberig-core and scriberig-store, not concrete backends.
    • [x] All 14 source modules exist.
    • [x] change_conformance.rs exists.
    • [x] Module responsibilities are documented.
    • [x] No domain-specific behavior was introduced.
    • [x] Workspace formatting, build, and tests pass.

    Final response from implementing agent¶

    Report:

    • files created or modified;
    • dependency changes;
    • commands run and whether they passed;
    • any prerequisite mismatch discovered.

    Do not claim later change-model tasks are implemented merely because the module files exist.
