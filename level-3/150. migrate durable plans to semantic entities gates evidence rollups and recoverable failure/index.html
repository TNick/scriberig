    Implementation update (2026-10-22): scriberig-session::PlanSemanticSnapshot now encodes Plan, PlanNode, membership, structural, dependency, and mutation metadata as independent universal revisions.     19. Architecture Drift Rejections¶

    Reject an implementation that does any of the following:

    • [ ] Treats serialized Plan JSON as the new canonical storage after migration.
    • [ ] Stores PlanNode only as a nested field of Plan.
    • [ ] Introduces PlanNodeWorkState or a second lifecycle enum.
    • [ ] Makes parent rollup counters part of PlanNode revision identity.
    • [ ] Requires a full descendant scan every time top-level status is read.
    • [ ] Defines rollup semantics only inside SQLite trigger SQL.
    • [ ] Makes generic foundation store crates depend on scriberig-session plan types.
    • [ ] Copies validation/result payloads into opaque evidence strings instead of referencing exact semantic objects.
    • [ ] Treats gates and dependencies as the same relation.
    • [ ] Treats failed node as permanently terminal.
    • [ ] Deletes failed attempt provenance during retry.
    • [ ] Allows ignored/abandoned work to satisfy dependencies implicitly.
    • [ ] Requires replan merely to append ordinary newly discovered work to a running plan.
    • [ ] Lets TUI/web mutate plan state directly.
    • [ ] Implements new TUI plan widgets against the superseded local Ratatui shell instead of task 148/upstream components.

    22. Final Implementation Report¶

    Plans, nodes, dependencies, gates, evidence, summaries, and attempts are persisted as independent semantic objects and relations. SQLite imports legacy aggregates into semantic roots, exposes plan aggregates as read-only compatibility projections, and maintains rebuildable node/rollup indexes. Shared application operations own plan writes; server, Rust and web clients, and the upstream-first TUI consume the shared plan semantics. TUI next-step, required decomposition, retry, and gate waiver commands preserve exact selected identities and observed plan revisions.

    Migration preserves stable plan/node identities, historical revisions, assignments, branch/result references, coordinator metadata, and attempt identity. Legacy active claims are recovered deterministically, with a durable pending marker so interrupted migration resumes safely. Owner-indexed gate and evidence selection is a separate performance follow-up; page limits and authorization are enforced.
