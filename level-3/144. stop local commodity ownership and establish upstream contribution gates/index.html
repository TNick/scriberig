    12. Implementation Notes¶

    12.1 Authority and classification key¶

    Level 2 032 is the current target and supersedes the ownership target in 023, 025, 031, and older task notes where they assign generic provider, model, loop, or terminal framework ownership to ScribeRig. Level 1 semantic invariants remain controlling. No production subsystem is rewritten by task 144.

    The classifications below expand the task sheet's U/S/A shorthand:

    • KEEP — ScribeRig semantic ownership (S): semantic contracts and durable ScribeRig state remain canonical.
    • ADAPTER — thin bridge from ScribeRig semantics to upstream (A): translate ScribeRig operation/context/capability values to upstream calls and results.
    • DELETE — duplicate commodity implementation (U): remove after the listed upstream consumer/API is available.
    • UPSTREAM GAP: generic capability is absent or trapped in a product binary; upstream work gates the consumer task.
    • TEMPORARY: bounded compatibility code with a named removal condition. No temporary exception is authorized by this audit.

    Freeze: do not add a local model/provider/thinking catalog, provider auth registry, model property schema, generic provider transport, ordinary agent loop, plugin/package host, terminal lifecycle, generic widget/editor/Markdown/ selector/theme framework, or Ratatui shell. An upstream gap is not permission to implement a permanent ScribeRig substitute.

    • Child/plan-worker invocations pass no summary callback, so a child summary cannot be misattributed to the root branch. The CLI one-shot path also leaves it unset.

    This does not claim full observable-reasoning support: there is no separate ReasoningSummaryStart/End, no provider-visible/full reasoning distinction, no per-part identity, and no durable reasoning-segment representation. Those remain task 136/145 acceptance gaps.

    12.8.3 Plugin worker guarantees and remaining gaps¶

    Now present in the pinned dependency and ScribeRig:

    • Versioned worker protocol (rpi-plugin-worker-v1), worker process ownership, request correlation/deadlines, cancellation frames, shutdown, host-call RPC, and process-tree termination on host timeout.
    • WorkerLauncher injection, environment clearing by default, HostProcessLauncher failing closed for sandboxed requests, and LinuxBubblewrapLauncher reporting filesystem/network/secret guarantees.
    • ScribeRig AuthorizedPluginWorker requires WorkerSandboxPolicy::is_sandboxed, applies an upstream AllowlistedHostHandler over PluginHostPolicy, retains only host-authorized tool names, and rechecks tool authorization on call.
    • ApplicationDomainDispatcher permits only domain_operation, binds the exact host snapshot and branch context, performs capability/scope checks, rejects oversized arguments, and returns only a change handle; validation/apply/ promotion are not exposed through it.

    Still absent or unvalidated:

    • validate_isolated_plugin_configuration rejects every configured worker or package root, so the worker is never started in production and worker tools never enter ToolCatalog/build_tools.
    • No atomic package/extension-session/catalog replacement and no package install/update/link path in ScribeRig.
    • Sandbox guarantees are launcher self-reports; the client does not verify them. macOS/Windows have no built-in launcher, and no seccomp or CPU/memory limits exist.
    • Cancellation is cooperative inside native FFI; a plugin that ignores its cancellation hook survives until the worker exits. Host capability calls are not cancellation-aware, and registration-time loading is not cancellable.
    • The bubblewrap launcher and sandbox policy have not been runtime-validated.

    Therefore plugin activation remains deny-by-default and no OS containment is claimed.

    12.8.4 Authentication note¶

    The fork now exposes typed AiError::Auth, but the provider stream still flattens provider failures into the assistant message error string at the pinned API. ScribeRig's UpstreamBranchError::Authentication therefore still depends on known upstream authentication display prefixes; HTTP 401/403 that the fork classifies internally are improved, but the ScribeRig boundary is not fully typed end-to-end. Replacing prefix detection would require a structured error event from the fork and is not part of this turn's change.
